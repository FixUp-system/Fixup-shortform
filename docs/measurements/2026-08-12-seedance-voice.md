## 관측한 것 — 앱으로 한 편 (프로젝트 `c2abe051`)

사용자가 앱에서 직접 만들었다. **구현이 실제로 도는 것은 확인됐다** — ③목소리를 건너뛰고
④이미지·⑤영상이 열렸고, 캐스팅이 목소리를 정했으며, 클립이 나왔다.

| 무엇 | 값 |
|---|---|
| 설정 | 15초 · 9:16 · anime · `i2v_model: seedance-2.0` |
| 원고 | **84자** (목표 82.5 = 15 × 5.5) |
| 컷 | **2개** (7초 + 4초) |
| 캐스팅 | `who: "20대 동양인 남성 농구 선수"` · `voice: "중저음, 차분하고 단단한 톤"` |
| 말하는 판정 | `true` — 두 컷 모두 인물이 있고 대사가 있다 |

★ **캐스팅이 `voice` 를 실제로 채웠다.** 이번 작업의 핵심 장치가 라이브에서 동작한다.

## ★ 결함 1 — 시선을 강제해 액션 장면이 깨진다 (이번 작업이 만든 것)

`lib/cuts.js` 의 말하는 분기가 이렇게 쓴다:

```
${who} speaks to the camera with natural lip sync.
```

`to the camera` 가 **모든 컷에서 인물이 정면을 보게** 만든다. 그래서 점프슛 중인 선수가
카메라를 보며 클로즈업되는 부적합한 연출이 나왔다(사용자 관측).

광고 내레이션은 대개 **화면 밖 목소리**다. 인물이 말한다는 것과 인물이 카메라를 본다는 것은
다른 요구인데, 이번 구현이 둘을 묶었다.

**후보 해법 둘** (아직 정하지 않음):
- (a) `speaks to the camera` → `speaks the line` — 한 줄. 시선을 장면에 맡긴다.
  ⚠️ 대신 모델이 입을 덜 움직여 립싱크 품질이 떨어질 수 있다 — 다시 재야 한다
- (b) 컷마다 갈라 준다 — 인물이 정면을 보는 컷에서만 `to the camera`.
  더 정확하지만 **그 판정을 무엇이 하느냐**(화면 설계가 답하게 할지)를 설계해야 한다

## ★ 결함 2 — 화면 설계가 모순된 장면을 한 컷에 합친다 (이번 작업 밖)

```
컷1 문장: 미드솔은 착지 시 압력을 흡수해 무릎 충격을 완화합니다.
컷1 화면: 점프슛 정점에서 공중에 뜬 선수의 역광 실루엣,
          아웃솔이 바닥을 잡으며 마찰 먼지가 일어난다
```

**공중에 떠 있는데 동시에 바닥을 잡는다.** 자료의 서로 다른 두 장면(체공·마찰)이 한 문장으로
합쳐졌고, 문장은 "착지"인데 화면은 "체공"이라 문장과도 어긋난다.

i2v 는 이미지 한 장에서 움직임을 만들므로, 모순된 화면 지시는 그림 단계부터 무너진다.

## ★ 결함 3 — 대본에 구조가 없다 (이번 작업 밖)

사용자 요구: **제품 정보 → 제품 특성 → 다시 제품 정보**(수미상관).

지금 대본 프롬프트는 "자료의 사실 중에서 골라 쓴다"까지만 시키고 **배치 순서를 정하지
않는다.** 그래서 사실이 나열되고 끝난다.

★ 지난번(2026-08-12 이전) 30초 영상에서는 더 나쁜 형태로 드러났다 — 마지막 문장이
*"신발에서 시작해 신발로 끝나는 구조가 이를 가능하게 합니다"* 였다. 연출 지시를 **구조로
만들지 못하고 낭독으로 읽어버린 것**이다.

## 길이에 대한 오해를 막는 기록

이번 편의 "구성이 빈약하다"는 관측 중 **분량 부분은 결함이 아니다.** 15초를 골랐고
목표가 82.5자라 84자가 나왔다 — 코드가 지시대로 움직였다. 30초를 고르면 165자에 컷 4~6개다.

구조(수미상관)는 길이와 별개이며 결함 3 이다.
