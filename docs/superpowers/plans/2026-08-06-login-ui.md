# 로그인 화면 시각 개선 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로그인 화면을 네이버·구글 실측에서 뽑은 규칙 넷(큰 입력칸·넓은 간격·좁은 상자·폭을 채운 큰 버튼)에 맞춘다 — 색은 지금 다크 토큰 그대로.

**Architecture:** `app/globals.css` 에 **로그인 전용 클래스**를 더하고 `app/login/page.js` 가 그것을 쓴다. 기존 `.sent-input`·`.cta`·`.panel` 의 **기본형은 건드리지 않는다**(다른 화면이 쓴다) — 변형 클래스를 얹는 방식이다.

**Tech Stack:** Next.js 15 (App Router, JS), 순수 CSS(`app/globals.css` 단일 파일), Vitest 4.

## Global Constraints

- 스펙: `docs/superpowers/specs/2026-08-06-login-ui-design.md`
- **실측값 그대로**: 입력칸 높이 **52px** · 칸 사이 **16px** · 마지막 칸→버튼 **28px** · 상자 폭 **420px** · 주버튼 높이 **48px**·폭 **100%**
- **색 토큰만 쓴다** — `:root` 밖에 hex 리터럴을 두지 않는다(`--surface`·`--line`·`--deep`·`--ink`·`--ink-soft`·`--btn`·`--btn-ink`)
- **반경은 토큰 3종**(`--r-card` 16px · `--r-ctl` 8px · `--r-pill` 999px)과 50%만
- **font-size 는 12·14·16·18·28px**, **font-weight 는 400·600·700** 만
- 그라디언트 금지. `style={{ }}` 인라인은 저장소 전체 10곳 이하 — 새로 늘리지 마라
- **`.sent-input`·`.cta`·`.panel` 기본형 무수정** — 브리핑·StylePicker·앱 전역이 쓴다
- 인증 로직·라우트 계약·실패 문구는 **무수정**(서버 문구 그대로 출력이 인증 스펙의 계약)
- 런타임 의존성 추가 금지, 한국어
- `npx vitest run` 전체 그린 유지. 커밋은 태스크마다. 커밋 전 `git branch --show-current` 로 `feature/video-compose` 확인, `git add` 는 명시 경로만
- ⚠️ 3000·3001 포트에 사용자 서버가 떠 있다 — 죽이지 마라. 검증 서버는 **3007**, `next.config.mjs` 의 기존 `SHOTFORM_DIST_DIR` 스위치를 쓰고 그 파일은 **커밋하지 마라**

## Self-Review 결과 (계획 작성 시 수행)

- **스펙 커버리지**: 규칙 넷(입력 52·간격 16/28·상자 420·버튼 48/100%)은 T1 CSS + T2 사용 + T3 실측으로 3중. 탭 표현(T1 `.login-tab.on` + T2 마크업), 보조 안내(T2), 손대지 않을 것들(전역 제약 + T1 의 `.sent-input` 기본형 무수정 테스트), design-system 통과(T1·T2 Step 4), 검증 절차(T3). **누락 없음.**
- **타입 일치**: 클래스 5종 이름을 T1 정의 → T2 사용 → 테스트가 양쪽을 대조. `.login-help` 는 T1 CSS·T2 마크업 양쪽에 있다.
- **주의로 남긴 것**: `.panel` 과 `.login-card` 를 함께 쓰므로 padding 을 T1 에서 재정의하지 말 것(T1 Step 3 말미), 실측이 스펙과 어긋날 때 임의 변경 금지(T3 Step 3).
