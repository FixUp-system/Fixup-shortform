# 대본 임팩트 개편 — 기획 point를 살리고, 초안이 전사 말고 실현하게

날짜: 2026-07-26 / 브랜치: `feature/script-impact`
관련: `lib/script.js`, `lib/validate.js`, `app/api/projects/[id]/script/route.js`
선행: `2026-07-24-script-planning-stage-design.md`(기획 단계 신설), `2026-07-24-script-quality-design.md`(담담 2단 생성)

## 배경 — 라이브 검증이 드러낸 것

기획(분석) 단계를 넣은 뒤 실제 gpt-4o로 4개 자료(빵집·딸기라떼·라떼아트·필라테스)를 태워보니, 앙상함(길이)은 해소됐지만 **세 가지 실제 문제**가 나왔다. 셋은 한 뿌리다.

**1. 기획의 메타 언어가 나레이션으로 전사된다 (핵심).**
`point`가 "그 사실을 어떤 인과·상황·의미로 *풀지* 한 문장"이라, 모델이 **기법 라벨**을 쓴다: "희소성을 강조한다", "방문을 유도한다", "차별화된다". 초안은 그걸 그대로 옮긴다:
- ❌ "한정된 수량으로 **희소성을 강조합니다**"
- ❌ "매일 다른 맛을 **경험할 수 있는 기회를 제공합니다**"

이건 나열보다 나쁘다 — 사실을 말하는 게 아니라 "우리가 지금 마케팅을 하고 있다"를 서술한다. 초안이 `point`를 **realize(사실로 실현)** 하지 않고 **transcribe(전사)** 한 것이다.

**2. 금지어가 최종 대본에 샌다.** 빵집에서 기획 `point`가 "특별한 맛으로 손님을 끌어들인다"라 쓰고(PLAN_SYSTEM이 "금지어는 신경 쓰지 마라"고 명시했으므로), 초안이 "이 특별한 맛이…"로 전사했다. 이전 담담 마일스톤의 핵심 보증(금지어 0)이 이 경로로 깨졌다.

**3. `editKeptContent`의 coverage-개수 가드가 정상 교정을 폐기한다.** 4건 중 3건에서 교정본이 버려지고 초안이 채택됐다(글자비 0.91~1.00로 바닥 0.8은 통과했는데도). 원인은 coverage 개수 검사: 교정이 대본을 다시 쓰며 coverage를 조금 다르게(짧게) 내면 "사실 유실"로 오판해 교정을 통째로 버린다. 그 바람에 빵집에선 "특별한"이 살아남았다.

## 방향 결정 (2026-07-26)

- **`point`를 조이지 않고 더 살린다.** 숏폼은 임팩트가 생명이고, `point`의 야심(각·훅·왜 꽂히는가)이 기획 단계를 둔 이유다. 사실로만 눌러버리면 기획이 밋밋한 목차가 된다. → 문제는 `point`의 야심이 아니라, 그것이 **기법 라벨로 착지**한 것. 임팩트 의도는 살리되 착지를 바꾼다.
- **어조를 좀 더 살려도 된다.** 순수 담담보다, 훅·리듬·짧고 세게 치는 숏폼 특유의 에너지를 허용한다. **단 거짓·과장은 여전히 금지.** 광고 필러어도 계속 금지 — 어조를 살린다는 건 리듬·구체성이지 상투어 부활이 아니다.
- 임팩트 개편은 기획 단계 신설과 별개 결정이라 **새 문서**로 둔다(이 문서).

## 목표 결과 (같은 딸기라떼 자료)

개편 전(전사):
```
(희소성) 생딸기라떼는 오전 11시부터 하루 40잔만 한정 판매합니다. 한정된 수량으로 희소성을 강조합니다.
```
개편 후(실현·임팩트):
```
(희소성) 오전 11시부터, 하루 40잔. 지나면 없습니다.
```
사실 개수는 같지만, 기법 서술이 사라지고 짧고 세게 착지한다.

## 설계 A — `point`의 성격 전환: 기법 라벨 → 임팩트 의도

`PLAN_SYSTEM`에서 `point`의 정의를 바꾼다.

**바뀐 정의:** `point` = 이 비트가 시청자에게 줄 **임팩트를 구체적으로**.
- 여는말 → 스크롤을 멈추게 할 한 방(무엇을 대뜸 던질지).
- 중간 → 긴장 또는 구체적 장면(무엇이 걸려 있는지, 어떤 그림인지).
- 마무리 → 무엇을 남길지.

**못박는 규칙(PLAN_SYSTEM에 추가):**
- `point`는 연출 의도다. **'강조한다·유도한다·차별화·소개한다' 같은 기법 서술이나 광고 형용사('특별한'·'완벽한'…)로 쓰지 않는다.** 실제로 칠 사실·훅·장면으로 적는다.
  - ❌ "희소성을 강조한다" / "방문을 유도한다"
  - ✅ "오전 11시 지나면 그날 치는 끝 — 마감을 건다" / "성수역 3번 출구 2분, 지금 갈 수 있다"
- `angle`은 그대로(가장 구체적이고 센 사실). 여는말 beat의 `point`는 **스크롤을 멈추게 할 가장 센 한 방**으로 잡는다.
- "새 사실 금지"는 유지: `point`의 임팩트도 자료가 함의하는 데까지만.

스키마(`{angle, beats:[{role, facts, point}]}`)는 그대로 둔다 — 필드명·구조 변경 없음. 바뀌는 것은 `point`에 무엇을 담으라 지시하느냐다. `validatePlan`은 변경 없음(형태만 검사).

## 설계 B — 초안: "전사 말고 실현" + 숏폼 어조

`SYSTEM`(초안)에 두 축을 넣는다.

**B-1. 전사 금지(가장 무거운 규칙):**
- "기획의 `point`는 너에게 주는 **연출 지시**다. 그 표현을 문장에 옮기지 마라. **'강조·유도·차별화·소개·훅·긴장' 같은 연출·기법 단어는 나레이션에 절대 넣지 않는다.** 그 의도를 실제 대사로 실현하라."
- 대조 예시 한 쌍(라이브 실패 기반):
  - ✗ "한정된 수량으로 희소성을 강조합니다"
  - ✓ "오전 11시부터, 하루 40잔. 지나면 없습니다."

**B-2. 어조 완화(담담 → 숏폼 에너지):**
- 기존 "목소리는 담담하게 / 평서문 위주 / 권유 남발 금지"를 **"군더더기 없이, 짧고 힘있게. 훅과 리듬을 살려라. 첫 문단은 스크롤을 멈추게 할 한 방으로 연다."**로 바꾼다.
- 거짓·과장 금지, 자료에 없는 사실 금지는 유지.
- 광고 필러어 금지 목록은 유지(특별한·만나보세요·경험해보세요·자랑합니다·다양한·완벽한·놓치지 마세요·최고의·진정한·잊지 못할·지금 바로·함께하세요). 어조를 살린다는 건 리듬·구체성이지 이 상투어들이 아니다.
- 담담 예시(딸기라떼 ✓)는 **짧고 세게 치는 예시**로 교체해 어조를 톤 참고로 보인다.

**B-3. 폴백 유지:** `plan`이 null이면 오늘 동작 그대로(브리핑+자료로 직접 초안). 기획은 강화 레이어.

## 설계 C — 교정: "평평하게 말고 날카롭게" + 가드 수정

**C-1. `EDIT_SYSTEM` 재정의:** 교정의 일을 "담담한 평서문으로 되쓴다"에서 **"숏폼답게 날카롭게 다듬는다"**로 바꾼다.
- 필러·군더더기·기법 서술(설계 B-1의 금지 단어)을 걷는다. 여는말이 무디면 punch-up 한다.
- **사실·임팩트·전개·리듬을 보존한다. 평탄하게 되쓰지 않는다(임팩트를 깎지 마라).**
- 사실을 하나도 빠뜨리지 않는다, 새 사실 금지, 광고 필러어 제거는 유지.

**C-2. `editKeptContent` 가드 완화:** coverage-개수 검사가 정상 교정을 3/4 폐기한 문제를 고친다.
- **coverage 개수 비교를 제거한다.** 교정은 대본을 다시 쓰며 coverage를 정당하게 재도출하므로, 개수 감소를 사실 유실로 볼 수 없다(라이브 반증).
- 유지: `edited`가 null → false, 문단 수 감소 → false, 글자 수(공백 제외) < 초안의 80% → false.
- 이 셋으로도 "교정이 사실을 통째로 흘리는" 진짜 사고(문단이 사라지거나 분량이 급감)는 여전히 잡는다.

## route

`app/api/projects/[id]/script/route.js`의 흐름(기획→초안→교정→폴백)은 그대로다. 프롬프트 내용만 바뀌므로 route 로직 변경 없음. 기획 실패=plan=null 흡수, 초안 실패=502는 유지.

## 테스트

프롬프트 문구 변경이 커서 단위 테스트는 "지시가 프롬프트에 들어갔는가"를 검증하고, 실제 품질은 라이브로 본다.

- `buildPlanMessages`: PLAN_SYSTEM이 "point는 연출 의도" + 기법 서술 금지("강조한다" 등을 쓰지 말라)를 지시하는지.
- `buildScriptMessages`: SYSTEM이 (a) "point를 전사하지 말고 실현하라", (b) 기법 단어 나레이션 금지, (c) 숏폼 어조(짧고 힘있게·훅)를 지시하는지. 금지 필러어 목록은 여전히 존재하는지. plan 있음/없음 분기는 기존 테스트 유지.
- `buildScriptEditMessages`: EDIT_SYSTEM이 "날카롭게 다듬되 임팩트·전개 보존, 평탄화 금지"를 지시하는지. 필러어 제거 지시 유지.
- `editKeptContent`: coverage가 줄어도(문단·글자바닥 통과 시) 이제 **채택**되는지(회귀 반전 — 기존 "coverage 줄면 거부" 테스트는 삭제/수정). 문단 감소·글자 80% 미만은 여전히 거부.
- route: 변경 없음 → 기존 route 테스트 회귀 그린(기획→초안→교정 순서·폴백).

⚠️ **회귀 주의:** `editKeptContent`의 coverage 검사 제거는 기존 `tests/script.test.js`의 "coverage가 줄면 거부한다" 테스트를 **깨뜨린다**. 이 테스트는 이번 설계로 의도적으로 뒤집히므로 삭제하고, 대신 "coverage가 줄어도 문단·글자바닥을 지키면 채택한다"로 교체한다. `tests/routes.test.js`의 "교정본이 문단을 흘리면 초안 폴백" 테스트는 교정본 문단이 2→1로 줄어 **문단 수 감소로 걸리므로**(coverage 아님) 그대로 유효하다 — 손대지 않는다.

## 라이브 재검증 (구현 후)

`node .superpowers/sdd/live-verify.mjs`(기존 하네스 재사용)로 같은 4개 자료를 다시 태워:
- (a) 기법 서술("강조합니다/유도합니다/차별화됩니다")이 나레이션에서 사라졌는가.
- (b) 금지 필러어 0 유지(특히 빵집 "특별한" 재발 없음).
- (c) 교정본이 대부분 채택되는가(coverage 폐기 해소).
- (d) 어조가 짧고 세게 착지하는가(임팩트), 그러면서 거짓·과장 없는가.
- (e) 전개용 질문·앙상함 해소는 유지되는가(회귀 없음).

## 영향 없는 것

- `project.script` 저장 스키마 불변. 기획은 여전히 transient.
- 기획 JSON 스키마(`{angle, beats:[{role, facts, point}]}`) 불변 — `point`의 내용 지시만 바뀜.
- route 로직·화면·게이트 불변.
- 컷 분해 등 대본 이후 단계 무영향.

## 열린 값

- 어조 완화의 정도 — 라이브로 보고, 광고 티가 재발하면 다시 조인다.
- 글자 바닥 0.8 유지(이번엔 안 건드림).
- 숏폼 CTA(마무리)를 어디까지 허용할지 — 우선 필러어 금지 목록으로 억제, 라이브에서 판단.
