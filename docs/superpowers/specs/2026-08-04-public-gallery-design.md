# 공개 갤러리 — 설계

> 2026-08-04 · 브랜치 `feature/video-compose`
>
> 홈에 **다른 이용자가 만든 영상**을 깐다. 지금은 내 것만 보인다.

## 참조한 것

사장님이 지목한 두 곳을 실제로 열어 읽었다.

| | dropshot AI | dola |
|---|---|---|
| 입력창 | 하단 고정 | 상단 중앙 |
| 갤러리 | masonry, 비율 제각각 | masonry, 비율 제각각 |
| 작성자 | `@핸들` 우하단 워터마크 | **없음** |
| 로그인 | 없어도 갤러리는 보임 | 없어도 갤러리는 보임 |

**공통**: 입력과 갤러리가 한 화면 · masonry · 갤러리 내용은 이용자 생성물.

## ★ 먼저 정한 것 — 왜 그대로 못 옮기는가

**shotform 이용자가 만드는 것은 자기 가게 광고다.** 자료에 상호·주소·신메뉴·가격이 들어간다.
dropshot·dola의 취미 창작물과 성격이 다르다. 그래서 세 가지를 다르게 간다.

### ① 기본은 비공개다. 공개는 사장님이 고른다

동의 없이 남에게 보여주지 않는다. `is_public`의 기본값은 `false`이고, ⑥완성 화면에서
**무엇이 공개되는지 눈으로 본 뒤** 켤 수 있다. 만들기 전에 묻지 않는다 — 결과를 모르고
하는 동의는 동의가 아니다.

### ② 카드에 제목을 쓰지 않는다

지금 `title`은 `material.text.slice(0, 40)`이다. 실제 값이 **"성수동에서 6년째 하는 작은 수제
요…"** 같은 것이다 — 상호와 위치가 그대로 들어 있다. 공개 갤러리 카드는 **영상만** 싣는다.

작성자도 싣지 않는다. 지금 이용자에게 표시용 이름이 없고 이메일을 노출할 수는 없다.
dola가 정확히 이 방식이다(작성자 표기 없음).

### ③ 공개 목록은 RLS 로 열지 않는다

`projects` 에 "공개된 행은 anon 이 select 가능" 정책을 얹으면 **`doc` 통짜가 열린다.**
그 안에는 자료 원문·대본·비용이 다 있다. 정책은 지금대로 두고(소유자만), 앱이
`service_role` 로 **필요한 컬럼만 골라** 내보낸다. 노출면을 코드 한 곳(`listPublicProjects`)에
가둔다.

> 이 판단은 기존 주석과 같은 결이다 — `db/schema.sql:121` 이 "RLS 는 방어선이지 우리 앱의
> 방어선이 아니다. 진짜 방어는 lib/projects.js 의 소유자 필수 인자다"라고 적고 있다.

## 무엇을 만드는가

### A. 저장 — 공개 플래그

```sql
alter table projects add column if not exists is_public boolean not null default false;

-- 갤러리는 공개된 것만, 최신순으로 읽는다. 부분 인덱스라 비공개 행은 색인에 들지 않는다.
create index if not exists projects_public_idx
  on projects (created_at desc) where is_public;
```

`db/schema.sql` 은 통째로 다시 올려도 안전해야 한다(`if not exists`).

### B. store — `listPublicProjects`

**소유자 필터가 없는 유일한 읽기 함수다.** 그래서 조건을 코드로 좁힌다:

- `is_public = true` 인 행만
- **완성본만** — `doc->render->>url` 이 있어야 한다. 미완성 그림만 뜨면 "이 서비스로 무엇을
  만들 수 있나"를 못 보여준다
- 돌려주는 필드는 `id`·`video_url`·`aspect` **셋뿐**. 제목·상태·소유자·doc 은 싣지 않는다
- 상한 60개

memory·supabase 두 구현 모두에 같은 계약으로 넣는다.

### C. API — `GET /api/gallery`

로그인한 사용자에게만 연다. 두 참조 사이트는 비로그인에게도 보여주지만, shotform 은 승인제라
공개 경로(`PUBLIC_PATHS`)를 넓히는 것은 인증 경계를 바꾸는 별건이다. **이번 범위 밖.**

### D. 공개 토글 — ⑥완성 화면

합성이 끝난 뒤에만 보인다. 켜고 끄는 것은 `PATCH /api/projects/<id>` 가 받는다.

문구는 무엇이 일어나는지 그대로 말한다:

> **갤러리에 공개하기**
> 다른 사장님들이 만든 영상 옆에 이 영상이 걸립니다. 자료·대본·가게 이름은 공개되지 않고
> **영상만** 걸려요. 언제든 다시 끌 수 있어요.

### E. 홈 — masonry 갤러리

```
새 영상 만들기                          [+ 시작하기]
자료를 넣으면 …

┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐    ← 공개 갤러리(남의 것)
│      │ │      │ │      │ │      │       비율 그대로, masonry
│      │ └──────┘ │      │ └──────┘
└──────┘ ┌──────┐ └──────┘ ┌──────┐
─────────────────────────────────────
빠른 생성 (실험)                          ← 그대로
```

- **내 영상은 홈에서 뺀다.** 홈은 남의 작품을 보는 자리, 내 것은 보관함이 맡는다
- masonry 는 CSS `columns` 로 만든다 — 카드 높이가 제각각이라 grid 로는 빈틈이 생긴다
- 카드는 **누르지 않는다**. 남의 프로젝트 상세로 갈 수 없고, 갈 이유도 없다
- 마우스를 올리면 재생(홈 카드와 같은 규칙)

### F. 빈 상태

지금 공개된 영상은 **0개**다(DB 에 프로젝트가 2개뿐이고 둘 다 사장님 것, 둘 다 비공개).
그래서 만들자마자 빈 화면이 뜬다 — 그것을 숨기지 않는다:

> 아직 공개된 영상이 없어요. 완성한 영상을 갤러리에 공개하면 여기 걸립니다.

## 건드리지 않는 것

- **RLS 정책** — 위 ③ 참조
- 보관함(`/archive`) — 내 영상 목록 그대로
- 빠른 생성 — 지금 자리 그대로
- `/create/**` 단계 화면 — ⑥완성에 토글 하나만 는다
- `PUBLIC_PATHS` — 갤러리는 로그인 사용자만 본다

## 검증

1. `npx vitest run` — 930 그린 위에서 새 테스트가 는다
2. **소유자 필터 없는 읽기가 정확히 하나뿐임을 테스트로 못 박는다.** `listPublicProjects` 가
   비공개 행·미완성 행을 절대 돌려주지 않는지, 그리고 제목·doc 을 싣지 않는지
3. 변이 확인 — `is_public` 조건을 지우면 그 테스트가 빨개져야 한다
4. 라이브: 사장님 프로젝트 하나를 공개로 켜고 홈에 뜨는지, 끄면 사라지는지
5. 눈으로: masonry 가 비율을 지키는지, 카드가 눌리지 않는지

> ⚠️ **스키마를 올려야 한다.** `is_public` 컬럼이 없으면 갤러리 API 가 500 을 낸다.
> `db/schema.sql` 을 통째로 다시 실행하면 된다(멱등).

## 범위 밖

- 비로그인 갤러리 관람 — `PUBLIC_PATHS` 확장이 필요하다
- 작성자 표시·좋아요·정렬 — 표시용 이름이 없다
- 신고·숨김 — 공개물이 쌓인 뒤의 문제다
- 큐레이션(우리가 고른 샘플) — 이번엔 이용자 공개물만 싣는다
