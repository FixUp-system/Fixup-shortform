# 제품이 컷마다 같은 물건으로 나온다 — 사물 레퍼런스를 코드가 꽂는다

**한 줄:** 홍보 영상인데 **제품이 컷마다 다른 물건으로 나온다.** 화면 설계가 사진 id 적기를
빠뜨려도 아무도 판정하지 않고, 그 컷은 레퍼런스 없이 모델 상상으로 그려진다.

워크트리 `C:\Users\fixup\shotform-video`, 브랜치 `feature/video-compose`.

## 실측 — 같은 실행 안의 대조군

화장품(VT PDRN 시카 엑소좀 앰플) 홍보 편, 초점 `{mode:"물건", subject:"VT PDRN 시카 엑소좀 앰플"}`,
업로드 사진 1장(`vision: {person:false, what:"화장품 병"}`).

| 컷 | `ref_ids` | 화면 설명 | 결과 |
|---|---|---|---|
| 1 | `["c1"]` | 붉어진 볼 클로즈업 | 제품 없음(정상) |
| 2 | `["32bcd365…"]` ← **제품 사진** | 앰플 병 극단적 클로즈업 | **청록 띠·검정 스포이드·라벨 글자까지 원본 그대로** |
| 3 | `["c1"]` | 밤 침실에서 **앰플을 얼굴에 바르는** 손 미디엄 샷 | **민무늬 투명병에 희미한 `VT`만 — 딴 물건** |
| 4 | `["c1"]` | 20대 후반 여성의 미소 짓는 얼굴 클로즈업 | 제품 없음(가격을 말하는 컷인데) |

같은 프로젝트·같은 모델·같은 실행에서 **레퍼런스가 붙은 컷만 제품이 맞았다.**

VLM 검수는 **4컷 전부 통과**시켰다(컷3: "장면 설명과 일치하고 신체 오류 없음"). 당연하다 —
"레퍼런스 외형 일치"는 레퍼런스가 있을 때만 보는 기준이고, 컷3에 간 것은 아바타 한 장뿐이었다.
→ wiki `sources/shotform-character-consistency-2026-07-29.md` §4의 "VLM 검수를 의심해야 한다"가 또 맞았다.

## 근본 원인 둘

**① 사진 고르기가 아직 "프롬프트 약속"이다.**
화면 설계(2패스)가 컷마다 `ref_ids`를 적는다. 규칙은 "이 컷 화면에 실제로 보이는 물건·공간이
[올린 사진]에 있을 때만 그 id를 적는다"인데, **컷3에서 그냥 빠뜨렸다.**

이 저장소는 **인물에서 이미 같은 문제를 풀었다**(`ae2dc26`):

> 인물이 자기 컷 번호를 함께 답하게 해서, '같은 사람에게 같은 id'를 프롬프트 약속이 아니라
> **코드가 보장**하게 한다.

인물은 코드 보장인데 **사물은 아직 약속이다.** 그래서 인물은 컷마다 유지되고 제품은 사라졌다.

**② 초점이 물건인데 화면 설계가 물건을 잘 안 비춘다.** 4컷 중 2컷뿐이고, 가격을 말하는
마지막 컷에도 제품이 없다. ①을 다 고쳐도 컷4는 그대로다 — `shows`에 제품이 없으면 붙일
자리가 없다.

## 결정 (사장님 확인)

1. **사진 고르는 책임을 화면 설계에서 떼어내 캐스팅이 다 맡는다.** 인물에 쓴 방식 그대로라
   규칙이 하나로 준다.
2. **빠짐 방지는 "0개일 때만 재시도".** 컷마다 다시 묻지 않는다(호출이 늘고, 컷마다 독립
   판단은 흔들린다).
3. **② 마지막 컷 문제도 이번에 함께 넣는다.** 둘 다 "초점이 물건인데 제품이 화면에 없다"는
   한 뿌리다. 따로 고치면 캐스팅이 비추지도 않는 제품을 찾게 된다.

### 컷마다 묻는 방식을 왜 안 쓰나 — 이력을 정확히

인물에서 **실측으로 기각된 것은 "원고에서 뽑기"**다(`ae2dc26`: 손님 3/3 누락, 조이니 cast가
1명으로 수렴). "컷마다 묻기"는 인물에서 시험한 적이 **없다** — `lib/cast.js` 첫 주석의 설계
논증으로 채택하지 않았을 뿐이다:

> 화면 설명은 같은 사람을 여러 이름으로 부른다("초등학생"·"꼬마"·"아드님"). 컷마다 고정
> 목록에 맞추게 하면 표현이 조금 달라져도 못 고르거나 잘못 고른다.

**다만 사물에 대해서는 실측이 있다: 지금 방식이 곧 컷마다 묻기이고, 이번에 샜다.**

## 구조

```
전)  화면 설계 → shows · motion · ref_ids(사진)      ← 여기서 샌다
     캐스팅   → 인물 + 그 인물이 보이는 컷 번호

후)  화면 설계 → shows · motion                       (사진 목록은 참고로 계속 본다)
     캐스팅   → 인물 + 사물, 각각 자기가 보이는 컷 번호   ← 코드가 꽂는다
```

화면 설계는 `[올린 사진]` 목록을 **계속 본다** — 무엇을 찍을 수 있는지 알아야 그것을 화면에
넣는다. **id를 적는 책임만** 옮긴다.

### 캐스팅 응답

```json
{
  "cast":  [{"who":"20대 후반 여성", "avatar_id":"av-woman-20s", "cuts":[0,2,3]}],
  "props": [{"photo_id":"32bcd365…", "cuts":[1,2]}]
}
```

주는 사진은 **사물만**이다(`vision.person`이 참인 사진은 `resolveCastRefs`가 인물에 쓰므로
겹치지 않는다). 사물 사진이 없으면 **블록째 주지 않는다** — "칸이 있으면 모델은 채운다"를
07-29에 실측했다.

```
[올린 사진 — 사물]
- id:32bcd365… 화장품 병
```

규칙은 인물 규칙과 같은 모양으로 쓴다:

> `props`의 `cuts`는 이 사진에 찍힌 것이 화면에 보이는 컷 번호를 **전부** 적는다. 화면 설명이
> 그것을 다른 이름으로 불러도(앰플·병·제품) 같은 것으로 묶는다. 어느 컷에도 안 보이면 빈
> 배열로 둔다.

### 코드가 꽂는다

`mergeCastIntoCuts` 옆에 같은 모양의 함수를 하나 더 둔다. **사물이 인물보다 앞에** 들어간다 —
`resolveCutRefs`가 "사물 하나 + 인물 하나"로 자리를 나누므로, 앞에 있어야 제품이 밀리지 않는다.

**`resolveCutRefs`는 손대지 않는다.** 사진 id가 컷에 들어오면 이미 `kind:"thing"`으로 잡아
"모양·색 그대로" 문구를 붙인다. 구조는 준비돼 있었고 빠진 것은 꽂는 것 하나였다.

## 화면 설계 — 사람이 나오는 컷에서 제품이 사라지는 것

규칙을 세게 쓰지 않는다. 저장소 교훈이 **"프롬프트로 규칙을 조인 것은 네 번 다 다른 형태로
샜고, 없던 정보를 준 고침은 통했다"**이다. 화면 설계가 모르는 것은 "사람이 나오는 컷에서
물건을 어떻게 함께 담는가"이므로, 그 본보기를 준다:

> 초점이 물건인데 사람이 보이는 컷이면, 사람과 물건을 **한 화면에** 담는다. 시선·손이 그
> 물건을 향하게 쓴다.
> ✗ `20대 후반 여성의 미소 짓는 얼굴 클로즈업` — 초점이 물건인데 물건이 없다
> ✓ `앰플 병을 손에 들고 바라보며 미소 짓는 20대 후반 여성 미디엄 샷`

## 재는 법 — 문자열 매칭 없이

"제품이 몇 컷에 보이나"를 세려면 보통 `shows`에서 제품 이름을 찾아야 하는데, 그것은
`lib/refs.js`가 하지 말라고 못박은 방식이다("코드가 문자열 매칭을 하지 않는다").

**이제 셀 수 있다** — 캐스팅이 `props`로 컷 번호를 답하므로 그 합집합의 크기가 곧 답이다.

- **0개면** → 한 번 더 묻는다(초점이 물건이고 사물 사진이 있을 때만). 기존 재시도 루프와 같은
  결이고, 정상일 때 호출은 늘지 않는다
- **0개는 아닌데 적으면** → **로그로 남긴다. 막지 않는다**

임계를 지금 박지 않는 이유는 표본이 **한 편**이기 때문이다. "임계값은 감이 아니라 실측
분포에서 뽑는다"가 이 저장소 규칙이고, 컷 길이에서도 그렇게 했다
(→ wiki `sources/shotform-cut-length-2026-07-29.md`).

## 오류 처리

- **`props`가 실패해도 컷은 남는다.** 화면 설계·캐스팅과 같은 원칙 — 레퍼런스 없이 가면
  지금 동작이다
- 목록에 없는 `photo_id`, 범위 밖 컷 번호는 **버린다**(개수가 안 맞아도 `cast`는 살린다)
- 옛 프로젝트의 `cut.ref_ids`·`cut.ref_photo_id`는 그대로 쓰인다

## 건드리는 곳

**수정**

  `[올린 사진]` 블록은 유지

**건드리지 않음**
- `lib/cast.js`의 `resolveCutRefs` — 사물 자리는 이미 있다
- `lib/imagegen.js` · `lib/vlm.js` · `lib/refs.js`

## 테스트

1. `buildCastMessages` — 사물 블록이 들어간다 / 사물 사진이 없으면 안 들어간다 / 규칙 문구
2. `validateCast` — `props` 통과, 모르는 `photo_id` 버림, 범위 밖 컷 번호 버림,
   `props`가 깨져도 `cast`는 산다
3. `mergePropsIntoCuts` — 꽂기, **사물이 인물보다 앞**
4. `SHOWS_SYSTEM` — `ref_ids` 규칙이 없다 / 사진 목록은 여전히 준다 / 사람+물건 본보기가 있다
5. `runSplitPipeline` — 초점이 물건이고 사물 사진이 있는데 `props`가 비면 한 번 더 묻는다
6. 회귀 하한선 **459 그린**
7. **가짜 모드 측정**(fal 0원, OpenAI 몇 센트) — 화장품 자료로 돌려 제품이 보이는 컷 비율을 본다

## 하지 않는 것 (YAGNI)

- **사진을 이미지로 보여주는 매칭** — 이번 실패는 매칭이 아니라 **누락**이다. 근거: 같은 라벨
  ("화장품 병")로 컷2는 정확히 매칭됐고 컷3만 빠졌다. 사진이 여러 장이라 라벨로 못 가릴 때
  재고 정한다
- 컷별 레퍼런스를 사장님이 직접 붙이는 UI
- 제품이 보이는 컷 수의 임계 강제(로그만)
