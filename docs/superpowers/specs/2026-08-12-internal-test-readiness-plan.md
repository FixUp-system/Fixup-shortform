### 1순위 · 완성본을 Supabase Storage 로 〔1~2일〕

**왜**: 지금 mp4 가 `data/renders/` **로컬 파일**이다(37개). 서버를 다시 만들거나 여러 대로
늘리면 **테스터가 만든 영상이 사라진다.** 업로드 사진은 이미 비공개 버킷으로 갔는데 렌더만 남았다.

**규모**: 참조 자리가 **6곳**뿐이고 선례가 있다 — `putObject`/`getObject` 가 이미 있고
`/api/uploads/[name]` 라우트가 소유자 검사로 흘려주는 방식을 그대로 베낀다.

```
lib/compose.js:22   rendersDir()          → Storage 업로드로
lib/compose.js:165  파일 쓰기
lib/compose.js:187  url 반환               → 형태는 /api/renders/<id>.mp4 유지
app/api/renders/[name]/route.js:18  파일 읽기 → getObject 로
```

★ **URL 형태를 바꾸지 않는다.** `render.of` 각인이 URL 로 낡음을 판정하므로, 형태가 바뀌면
기존 완성본이 전부 "낡음"이 된다.

⚠️ ffmpeg 는 여전히 로컬 파일에 써야 한다(자식 프로세스라 스트림을 못 받는다) — **만들고 나서
올리는** 순서다. 임시 파일은 지운다.

### 2순위 · 새 가입 알림 〔반나절〕

**왜**: 지금 테스터가 가입하면 `pending` 에 갇히고, **운영자는 그 사실을 모른다**(코드에 알림
0건). `/admin` 을 주기적으로 열어보는 사람이 없으면 첫인상이 "안 되는 서비스"가 된다.

**가장 싼 해법부터**:
1. `/admin` 에 **승인 대기 수를 배지로** — 운영자가 열면 바로 보인다 (반나절)
2. 그 위에 알림 수단(메일·슬랙)은 나중에. 테스터 5명 규모면 1번으로 충분하다

⚠️ `app/admin/page.js` 는 병렬 세션의 파일 목록에 없다 — 충돌하지 않는다.

---

### 3순위 · 오류를 우리가 보는 수단 〔1일〕

**왜**: `console.error` 가 28곳 있지만 **전부 서버 콘솔에만** 남는다. 테스터가 말해주기 전에는
무엇이 깨졌는지 모른다.

**범위를 좁힌다** — 외부 서비스(Sentry) 도입은 계정·비용·설정이 붙는다. 그 전에:
- **실패한 유료 호출을 원장에 남긴다** — `cost_records.status` 가 이미 있다. 실패도 행으로
  남으면 `/costs` 화면에서 우리가 본다
- 화면에서 사장님이 본 오류 문구를 그대로 기록

## 권하는 순서

```
1순위 렌더 Storage      ← 테스터 결과물이 사라지지 않게   (가장 크다)
2순위 가입 알림 배지    ← 테스터를 방치하지 않게
3순위 실패 기록         ← 무엇이 깨졌는지 우리가 알게
```

셋은 서로 **독립**이다 — 파일이 겹치지 않아 순서를 바꾸거나 나눠서 해도 된다.
크기 순으로 놓았을 뿐이다.

병렬 세션의 `billing-gaps` 와도 파일이 겹치지 않는다(위 목록 대조).
