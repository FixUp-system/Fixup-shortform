# 대본 생성 개정안 검토 — 무엇을 받고, 무엇을 미루고, 무엇을 되돌리지 않을 것인가

검토 2026-07-28 · 대상 브랜치 `feature/video-compose`

외부에서 제안된 「대본 생성 모듈 스펙 — 전체 시나리오 방식 + 할루시네이션 통제」를 현재 구현과
대조한 결과다. **결정 기록이지 구현 계획이 아니다.** 나중에 같은 제안이 다시 올라올 때 왜 이렇게
정했는지 알 수 있도록 근거를 파일·줄로 남긴다.

## 한 줄 결론

문제의식은 옳다. 큰 방향("시나리오가 원본, 컷은 파생물")은 **이미 더 강하게 구현돼 있다.**
지금 취할 것은 **숫자·실적의 코드 대조 하나**이고, 그것도 반려기 이전에 **측정기**로 시작한다.
나머지는 조건부 보류다 — 트리거를 아래에 적어 둔다.

---

## 1. 이미 있는 것 (새로 만들지 않는다)

| 제안 항목 | 현재 구현 |
|---|---|
| 시나리오가 원본, 컷은 파생 | `lib/cuts.js:9-35` LLM은 경계 번호만 고르고 코드가 자른다. `lib/validate.js:18-36` 빈틈·겹침·누락을 거절한다. **"컷을 이어붙이면 원고와 글자 그대로 같다"는 구조적 보장** — 제안서의 "파생물" 서술보다 강하다 |
| 컷 경계 = 문장 경계 | `lib/cuts.js:9-15` `splitSentences`, `SPLIT_SYSTEM`("문장을 쪼개지 않는다") |
| 클립 제약 변경 시 분할만 재계산 | `runSplitPipeline`(`lib/pipeline.js:112`)은 `script.text` 만 읽는다 — 재분할해도 원고는 불변 |
| 반려 시 재생성, 상한 | `app/api/projects/[id]/script/route.js:49-70` 상한 3회 + **`scriptScore` 채택 판정**(나아질 때만 받는다). 제안서에는 이 채택 기준이 없다 |
| 로깅(반려 사유·재생성 횟수) | 같은 라우트. 라운드별 글자 수·결함·점수·채택이 남는다 |
| **분량 부족 시 출구 (제안서 ③-④ 전체)** | **구현 완료.** `underTarget`(`lib/script.js:266`)은 "짧은가"가 아니라 **"채울 재료가 남았는가"**를 묻고, `buildDevelopMessages`(`lib/briefing.js:61`)가 이야기 소재를 되묻고, `capacitySeconds`(`lib/script.js:87`)가 "이 자료로는 N초"를 숫자로 제시한다 |

## 2. 되돌리지 않을 것 — 실측으로 이미 기각된 방향

### (a) "시나리오 생성 LLM에는 원문이 아니라 fact_sheet만 입력"

`lib/synopsis.js:52-56`에 A/B 결과가 있다:

> 요약을 함께 주면 모델이 원문 대신 요약을 문장화해 **두 번 증류됐다** — 사장님이 실제로 한 말과
> 구체 수치가 밋밋한 요약체로 바뀌었고, 두 줄짜리 얕은 자료에서는 **금지어와 자료에 없는 우위
> 주장까지 나왔다.** 요약이 없는 쪽이 창업 계기·대립·수치를 살렸다(자료 3종 모두 같은 방향).

요약을 주는 쪽이 **환각이 늘었다.** fact_sheet 는 요약의 다른 이름이라 같은 결과가 재현될 공산이
크다. 브리핑의 `key_points` 도 같은 이유로 대본 지문에 넣지 않는다.

**절충은 열려 있다:** 원문은 그대로 주고 fact_sheet 는 **검증용으로만** 쓴다. 생성 입력을
바꾸지 않는 한 위 결과와 충돌하지 않는다.

### (b) "TTS를 시나리오 전체 한 덩어리로 생성하고 타임스탬프로 배분"

지금은 반대이고 이유가 `lib/tts.js:1-5` 에 있다: **"컷별로 나눠 읽는 이유는 하나다: 길이를 알아야
한다."** 그 실측값(`cut.seconds`)이 클립 길이(`lib/i2v.js:13`)·자막 큐(`lib/subtitles.js:9`)·
합성 보정(`lib/compose.js:33`)을 전부 쥔다.

바꾸면 잃는 것:
- 문장별 타임스탬프를 얻을 수단 — 현 엔드포인트가 주는지 **미확인**. 안 주면 forced alignment 가
  새로 필요하다
- **컷 단위 실패 격리와 부분 재생성**(`regenVoice`) — 한 컷 발음이 틀리면 전체를 다시 사야 한다
- 합성이 컷별 오디오를 받으므로(`lib/compose.js:156`) 통짜를 다시 자르는 단계가 붙는다

얻는 것은 톤 일관성인데, **그 문제가 존재하는지조차 모른다 — 실제 TTS 호출이 0회다.**
"측정 없이 품질을 주장하지 않는다"는 이 저장소의 원칙에 정면으로 어긋난다.

### (c) 현재 규칙과 충돌하는 둘

- **"마지막 문장은 한 줄 카피로 닫는다"** — 현재는 명사형 카피 투를 **금지**한다
  (`lib/script.js:34-36`). 07-24 개편이 카피 투를 걷어내는 데 여러 라운드를 썼다
- **"모든 문장이 시각화 가능해야 한다"** — 현재는 원고에서 화면 묘사를 **금지**하고
  (`lib/script.js:32`), 시각화는 2패스 `shows`(`lib/cuts.js:38-56`)가 맡는다.
  "말이 하지 않는 것을 화면이 맡는다" — 원고는 귀로 듣는 물건이라는 설계다

## 3. 구조적 약점 — FACT/FRAME/BRIDGE 태깅

**분류 자체가 LLM 재량인데 검증 강도가 그 분류에 붙어 있다.** 모델이 FACT 를 FRAME 으로 태깅하면
검증이 통째로 무력화된다. "지켜져야 하는 것은 코드가 판정한다"는 원칙에서 보면, **판정의 전제를
코드가 검증할 수 없는 구조**다. 회피 연쇄(같은 동기가 옆에서 새 형태로 나타나는 것)의 교과서적
사례가 된다.

숫자는 유형 태그 없이도 코드가 전 문장에서 잡을 수 있다. 태깅의 실익은 "숫자 없는 구체 주장"에만
남는데 — 그것이 바로 다음 문제다.

## 4. 숫자 대조의 한계 (그래도 만들 가치는 있다)

**이 저장소가 실제로 겪은 환각 두 건은 숫자가 없다.** `lib/script.js:244-247`:

> 두 줄짜리 자료에서 하한을 요구했더니 모델이 자료에 없는 말("직접 삶아 세탁",
> "고객 만족도가 높습니다")을 지어내 채웠다.

오탐 쪽도 만만치 않다:
- 한국어 수사 — "한 잔", "스무 해", "두 배"
- 표기 변형 — `6,500원` / `6500원` / `육천오백원`
- 파생 계산 — 자료 "하루 40잔" → 원고 "주 240잔"은 **참인데 반려된다**
- 부분 일치 — "오전 11시부터"의 11

그럼에도 만들 값어치는 있다. "판매 1위·후기 1,000건" 류를 막는 안전망이 지금은 **프롬프트 두
곳뿐**이고, 이 저장소는 "프롬프트에 두 번 적고 두 번 다 어겼다"를 이미 겪었다(약한 오프닝).

**그래서 반려기가 아니라 측정기로 시작한다.**

## 5. 결정

### 지금 한다
1. **관통 검증**(로컬 30초 mp4 1회)이 무엇보다 앞선다. fal 호출 0회 상태에서는 제안서의 절반
   (TTS 방식·컷 연결·상한 처리)이 **판단 근거 자체가 없다**
2. **숫자·실적 대조를 측정기로** — `scripts/measure/run-pipeline.mjs` 로 20~30개 출력을 모아
   원고의 숫자 vs 자료 원문의 불일치 분포(오탐/미탐)를 잰다. fact_sheet·태깅 없이, 자료 원문과
   답변된 `asked`(= `sourceBlock` 이 이미 모으는 재료)를 대조 대상으로 한다
3. 분포를 보고 **`scriptFaults` 결함으로 승격** — 기존 되돌리기 루프·점수·로그에 편입된다
   (별도 루프를 얹지 않는다. 얹으면 호출이 배가 되고 채택 판정이 없는 쪽이 개선을 버린다)

### 조건부 보류 — 트리거를 적어 둔다

무기한 기각이 아니다. 제안서의 문제의식(할루시네이션의 경계를 시스템이 쥔다)은 옳다.

| 항목 | 다시 여는 조건 |
|---|---|
| TTS 통짜 생성 + 타임스탬프 배분 | 컷별 TTS 의 톤·속도 불일치가 **라이브에서 실측될 때** |
| `prev_frame_ref` 컷 연결 | 단일 클립 i2v 가 검증된 뒤 (지금은 기본 호출조차 0회) |
| FACT/FRAME/BRIDGE 태깅 | 숫자 대조 안전망으로 **못 잡는 환각이 실측될 때**. 그때도 분류를 코드가 검증할 방법을 함께 설계한다 |
| fact_sheet | 생성 입력이 아니라 **검증 입력**으로 한정할 때 |
| 장문 결함(i2v 상한 초과 문장) | 관통에서 10초 초과 컷의 빈도를 보고. 임계는 제안서의 6초(≈33자, 한국어 평서문이 흔히 넘는다)가 아니라 **실측 분포**에서 뽑는다. 잔여과제 2(문장 지목 반려가 통짜 재작성에 묻힘)의 부분 교체 메커니즘과 함께 |

### 하지 않는다
- 카테고리 few-shot — 예시 오염(소재·동사가 겹치면 통째로 베끼거나 지어낸다)을 이미 두 번 겪었다
- 제품 소개형 서사 뼈대 고정("제품은 3번째 문장 이후") — 현 파이프라인은 업종 불문·이야기 지향이다
- 문장 3~6초 강제 — 임계 근거가 없다
