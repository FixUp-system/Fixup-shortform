# 단계별 만들기를 도구형 화면으로 — 설정 레일 + 누적 작업대

2026-09-14 · 사장님이 다른 제품의 화면(왼쪽 설정 레일 + 오른쪽 결과)을 보여 주며
"우리도 이렇게" 라고 한 데서 시작했다. 시안: <https://claude.ai/code/artifact/d747128c-232e-437f-aaa3-b4d9df9113b0>

## 무엇을 바꾸나

**단계별 영상(`/reel/[id]/*`)의 화면 구조**만 바꾼다. 지금은 단계마다 화면이 통째로 갈리고
설정은 첫 화면에서 한 번 받고 사라진다. 바꾼 뒤에는:

- **왼쪽에 설정 레일**이 늘 서 있다 — 이 영상이 무엇으로 만들어지는지 항상 보인다
- **오른쪽은 작업대**다 — 끝난 단계는 한 줄로 접혀 위에 쌓이고, 지금 단계만 펼쳐진다

## 대화에서 정해진 것 (뒤집지 마라)

1. **모드 토글은 두지 않는다.** 원클릭·단계별은 사이드바에서 이미 갈린다. 화면 안에 토글을
   두면 "지금 무슨 모드지"가 생기고, 두 흐름이 **다른 주소·다른 저장 구조**라 값 이월이
   지저분해진다.
2. **사이드바는 그대로 둔다.** 다만 두 항목에 한 줄씩 붙인다 —
   `원클릭 영상 / 한 번만 확인하면 끝` · `단계별 영상 / 보면서 고쳐요`.
   그리고 **단계 목록은 사이드바에서 뺀다** — 작업대가 그 말을 하므로 두 곳에 두면 갈린다.
   ⚠️ 사이드바에는 스테퍼가 **넷**이다(옛 단계별 `STEPS` · 광고 · film · reel).
   이번에 빼는 것은 **reel 하나**다. 나머지 셋은 각자의 흐름이 그대로 쓴다.
3. **작업대는 누적이다.** 끝난 단계를 접어서 남긴다(칸 교체가 아니다). 지난 단계를 보려고
   주소를 옮길 필요가 없다.
4. **설정은 돈 안 치른 축만 열린다.** 아래 「잠금 규칙」.
5. **레일은 부품 하나다.** 나중에 원클릭 화면도 같은 부품을 쓴다(이번 범위 아님).

## 화면 구조

```
┌ 사이드바 ┐┌ 설정 레일 ┐┌──────── 작업대 ─────────┐
│ 원클릭   ││ 모델      ││ ▸ 1 입력            ✓   │
│ 단계별 ● ││ 사진      ││ ▸ 2 시나리오        ✓   │
│ 보관함   ││ 프롬프트   ││ ▾ 3 이미지 생성  ← 지금 │
│ 내 계정  ││ 비율 🔒   ││     [컷][컷][컷][컷]    │
│         ││ 길이 🔒   ││     고치고 싶은 것…      │
│         ││ 화질      ││ · 4 영상 프롬프트        │
│         ││ 화풍 🔒   ││ · 5 영상                │
│         ││ ─────── ││ · 6 완성                │
│         ││ 245 크레딧││ [나머지는 알아서 끝내기]  │
└─────────┘└──────────┘└─────────────────────────┘
```

**파일**

| 자리 | 무엇 |
|---|---|
| `app/reel/[id]/layout.js` | 레일과 작업대 틀을 여기서 그린다. 지금도 이 layout 이 단계 페이지를 감싸고 라우팅을 지킨다 — 그 자리에 껍데기만 더한다 |
| `components/reel/SettingsRail.jsx`(신설) | 설정 레일 **부품 하나**. 값은 프로젝트 문서에서 읽고, 잠금은 아래 순수 함수가 판정한다 |
| `components/reel/StepStack.jsx`(신설) | 누적 카드 틀. 끝난 단계는 접힌 머리줄, 지금 단계는 `children`(각 단계 페이지)을 펼쳐 꽂는다 |
| `app/reel/[id]/<seg>/page.js` 여섯 | **내용은 그대로 둔다.** 작업대 카드 안에 들어갈 뿐이다 |
| `components/Sidebar.jsx` | 단계 목록 제거 · 두 항목에 한 줄 설명 |
| `lib/reel/locks.js`(신설) | `lockedAxes(project)` — 순수 함수. import 0 |

## 잠금 규칙

**새 상태를 만들지 않는다.** `lib/reel/steps.js` 의 도달 판정이 이미 같은 신호를 쓴다.

| 축 | 열려 있는 동안 | 판정 신호 | 잠긴 뒤 문구 |
|---|---|---|---|
| 비율 · 길이 | 시나리오 확정 전 | `!project.scenario?.text` | "시나리오를 확정해서 잠겼어요" |
| 화풍 | 첫 그림 전 | `!cuts.some(c => c.image?.url)` | "첫 그림을 그려서 잠겼어요" |
| 모델 · 화질 | 첫 클립 전 | `!cuts.some(c => c.video?.url)` | "첫 컷을 만들어 잠겼어요" |
| 사진 · 프롬프트 | 끝까지 열림 | — | — |

- 잠긴 축은 **값이 계속 보인다**(회색). 무엇으로 만들었는지가 화면에서 사라지면 안 된다.
- 잠긴 칩을 누르면 **"이 값으로 새 영상 만들기"** 를 권한다 — 지금 것을 망가뜨리지 않고,
  적어 둔 프롬프트·사진은 들고 간다. (이 문은 새 프로젝트를 만드는 기존 경로를 쓴다.)
- ⚠️ 왜 잠그나: 그 값들이 컷마다 **각인**(`of`)돼 있어서, 바꾸면 이미 만든 산출물이 낡는다
  (`lib/steps.js` 하단). 열어 두면 사장님이 모르는 새 전 컷 재구매가 된다.

## 작업대 카드 계약

- 접힌 머리줄은 **한 줄 요약**을 보여 준다: 입력=무엇을 만드는지·사진 장수 / 시나리오=컷 요약 /
  이미지=컷 수. 요약 문자열은 **프로젝트 문서에서 파생**한다(새 저장 값을 만들지 않는다).
- 지금 단계만 펼쳐진다. 끝난 단계를 눌러 펼치면 **그 단계 주소로 이동**한다 —
  라우팅 가드가 지금 그대로 판정하므로 못 가는 곳은 못 간다.
- 아직 못 간 단계는 흐리게 두고 누를 수 없다(`isReelStepReachable`).

## [나머지는 알아서 끝내기]

작업대 바닥에 문 하나. 자동 관통(`lib/auto.js`)을 **그대로 부른다** — 새 파이프라인을 만들지
않는다. 첫 선택(원클릭이냐 단계별이냐)이 막다른 길이 아니게 하는 장치다.

- 값이 나가는 문이므로 **얼마가 나가는지 먼저 말한다**(정가는 `lib/pricing.js`).
- 진행 중에는 안 보인다 — 돌고 있는데 또 누르면 이중 청구다(이 저장소의 기존 함정).

## 안 건드리는 것

- 단계 표(`lib/reel/steps.js`) · 라우팅 가드 · 낡음 판정(각인) · 상태 라우트 다섯
- 각 단계 화면의 **내용**(시나리오·이미지·프롬프트·영상·완성)
- 가격표(`lib/pricing.js`) · 청구 장치 — 화면은 **읽기만** 한다
- 원클릭(`/ads/*`) 화면 — 같은 레일을 쓰는 것은 다음 회차
- **시작 화면(`/create`)** — 프로젝트가 생기기 전 자리다. 그대로 두고, 레일은 프로젝트가
  생긴 뒤(`/reel/[id]/*`)부터 선다. 나중에 이 화면도 레일로 바꾸면 값을 두 번 묻지 않게 된다

## 테스트

이 저장소의 방식대로 **소스 문자열 판 + 순수 함수 단위 판**으로 짠다(렌더 테스트 인프라 없음).

1. `lib/reel/locks.js` — 축별 잠금이 신호대로 갈리는지(단위). 각 축 × 열림/잠김.
2. 레일이 **부품 하나**인지 — 화면이 칩을 손으로 다시 그리지 않는지(문자열 판).
3. 작업대가 `isReelStepReachable` 을 쓰는지 — 못 가는 단계를 화면이 열지 않는지.
4. 사이드바에 **단계 목록이 없다** — 같은 말이 두 곳에 있지 않게.
5. 자동 관통 문이 **진행 중에는 없다** — 이중 청구 방지.
6. 값·색·치수는 기존 판(design-system)이 이미 잰다.
7. 사이드바에서 **reel 스테퍼만** 빠졌는지 — 광고·film 스테퍼를 같이 지우면 그 흐름이 길을 잃는다.

## 미결 — 사장님이 정할 것

1. **벌** — 레퍼런스는 어두운 벌이다. 이 설계는 **밝은 벌**(지금 앱)로 그렸다. 도구 화면만
   어둡게 하려면 랜딩의 두 갈래 절처럼 경계를 하나 더 만들어야 한다.
2. **모바일** — 좁은 화면에서 레일을 서랍으로 숨길지, 접힌 요약 줄로 둘지. 만들면서 보는 편이 낫다.
3. **원클릭 문구** — 지금 랜딩·사이드바가 "중간에 멈추는 곳이 없습니다"라고 말하는데
   실제로는 시나리오에서 한 번 멈춘다(`app/ads/[id]/page.js`). 이 설계는 **ⓐ 문구를 사실로**
   ("한 번만 확인하면 끝")를 전제로 그렸다.

## 되돌리기

레일·작업대는 **껍데기**다. 단계 페이지의 내용과 라우팅은 그대로이므로, 되돌릴 때는
`layout.js` 를 옛 판으로 두고 새 부품 셋을 지우면 끝난다. 저장 구조·주소·가격은 바뀌는 것이 없다.
