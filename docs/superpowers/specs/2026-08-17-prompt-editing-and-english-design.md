# 프롬프트를 사장님에게 보이고, 고치게 하고, 영어로 쓴다 — 설계

> 브랜치 `feat/scenario-pipeline` · 2026-08-17
> 앞선 결정: LLM 은 `claude-opus-5`(병합 `28a8a0e`). 이미지 `nano-banana-2`, 영상 `Seedance 2.0`/`Kling v3`.

## 무엇을 만드는가

셋이다. 하나의 일로 묶는 이유는 **전부 같은 두 함수를 고치기 때문**이다
(`lib/cuts.js` 의 `buildImagePrompt`·`buildClipPrompt`). 따로 하면 그 파일을 세 번 연다.

1. **컷마다 프롬프트를 보여 주고 고치게 한다** — 이미지·영상 둘 다
2. **①자료에서 프로젝트 공통 지시를 받는다** — 밖에서 쓴 프롬프트를 그대로 싣는 자리
3. **모델이 읽는 값을 영어로 쓴다** — 대사는 한국어

## 지금 무슨 일이 벌어지고 있나

fal 에 실제로 나가는 요청 본문을 잡아서 봤다(`data/show-prompts.mjs`, $0).

```
POST https://fal.run/fal-ai/nano-banana-2
{ "prompt": "High-quality photographic still for a short-form video, vertical 9:16
   composition. Scene: <한국어>. Setting (same in every scene of this video): <한국어>.
   The video's subject is: <한국어>. Keep this exact product/subject consistent in every
   scene. Its appearance, identical in every scene: <한국어>. Cinematic lighting,
   realistic, no text or letters in the image. Overall look and color treatment, keep
   identical across all cuts: <한국어>.",
  "aspect_ratio": "9:16", "num_images": 1, "resolution": "1K" }
```

**틀은 영어인데 내용물이 전부 한국어다.** 사장님은 이 문장을 어디서도 볼 수 없고, 고칠
수 있는 것은 `edit_instruction`(컷별 "수정 지시") 한 줄뿐이다 — 그 한 줄은 프롬프트
**맨 뒤에** 붙는 추가 지시라, 앞의 서술이 틀렸을 때 그것을 지우지 못한다.

## 설계

### A. 본문과 꼬리를 가른다 (사장님이 고른 방식)

프롬프트를 두 조각으로 본다.

- **본문(창작부)** — 이 컷이 무엇을 보여 주고 어떻게 움직이는가. 사장님이 통째로 갈아
  끼울 수 있다.
- **꼬리(계약부)** — 코드가 **언제나 본문 뒤에** 붙인다. 사장님이 무엇을 쓰든 지워지지
  않는다.

이 배치는 새 발명이 아니다. `lib/cuts.js:694` 에 이미 같은 문장이 적혀 있다 —
*"위치가 방어다 — 마감과 글자 금지는 항상 코드가 이 뒤에 붙으므로 사장님이 무엇을 쓰든
우리 지시가 지워지지 않는다."* `Style note` 와 `edit_instruction` 이 이미 그렇게 산다.

**이미지 꼬리 — 코드가 지키는 것**

| 꼬리 | 왜 사장님에게 안 넘기는가 |
|---|---|
| `${orient} composition` (9:16) | 판형이 틀리면 합성이 깨진다 |
| `no text or letters in the image` | 모델이 글자를 "글자처럼 생긴 무늬"로 그린다. 자막은 ffmpeg 가 태운다 |
| 레퍼런스 번호↔배역 결속 + `do not swap them` | 첨부 순서와 문구가 갈리면 배역이 뒤바뀐다(2026-07-29 실측) |

**영상 꼬리 — 코드가 지키는 것**

| 꼬리 | 왜 |
|---|---|
| `The attached image is the first frame — continue naturally from it.` | 이게 없으면 i2v 가 아니다 |
| `Keep the subject and style unchanged.` | 컷 사이 일관성 |
| `No text or letters.` | 위와 같다 |
| `No talking faces or lip sync.` (말 없는 컷) | 없으면 모델이 없는 사람의 입을 움직인다 |
| **`Says exactly, in Korean: "<대사>"`** | ★ 아래 참고 |

★ **대사 절은 반드시 꼬리다.** 같은 문자열을 ffmpeg 가 자막으로 태운다
(`lib/subtitles.js`). 사장님이 영상 프롬프트에서 대사를 고칠 수 있으면 **들리는 말과
화면의 자막이 갈린다** — 고쳐야 할 자리는 ②시나리오의 대사 칸이지 프롬프트가 아니다.
화면에도 그렇게 적는다.

**저장 자리**

| 값 | 자리 | 형식 |
|---|---|---|
| 컷별 이미지 본문 덮어쓰기 | `cut.image_prompt` | 문자열, **있을 때만** |
| 컷별 영상 본문 덮어쓰기 | `cut.clip_prompt` | 문자열, **있을 때만** |

`edit_instruction`·`silent`·`narration` 과 같은 모양이다 — **참일 때만 붙는 필드**.
그래야 옛 컷의 모양이 글자 그대로 그대로 남는다.

### B. ①자료의 프로젝트 공통 지시 — 상자 둘

**비슷한 것이 이미 있다 — 하지만 그것이 아니다.** `settings.style.note` 가
`Style note: …` 로 실리고 각인(`styleKey`)에도 들어가 있으며, ①자료에 입력칸까지 있다
(`StylePicker`). 처음에는 그것을 재사용하려 했는데, **상한이 120자다**
(`STYLE_NOTE_MAX`). 근거가 코드에 적혀 있다 — *"보정 한 줄의 상한. 프롬프트는 한 문장
열거라, 여기가 길어지면 우리 지시를 밀어낸다."*

밖에서 써 온 프롬프트는 보통 300~800자다. 재사용하면 **사장님이 붙여넣기부터 거절당한다.**

> **판단(Ruling)** — `style.note` 는 **그대로 둔다**(화풍 보정 한 줄, 120자). 프로젝트 공통
> 지시는 **새 필드 둘**로 만든다: `settings.image_note` · `settings.clip_note`, 상한
> `PROMPT_NOTE_MAX = 600`.
>
> *같은 값을 두 군데 두지 않는다* 를 어기는 것이 아니다 — **다른 값**이다. 하나는 화풍에
> 딸린 보정 한 줄이고, 하나는 밖에서 써 온 프롬프트 통짜다. 상한도 자리도 성격도 다르다.
> 120자 상한을 올려서 재사용하는 쪽은 택하지 않는다: 그 숫자에는 근거가 적혀 있고,
> 화풍 보정을 800자로 열어 주는 것은 이 작업이 요청받은 일이 아니다.

싣는 자리: `image_note` 는 `Style note` 절 옆(이미지 본문 끝), `clip_note` 는
`buildClipPrompt` 의 맥락 절과 꼬리 **사이**. 둘 다 꼬리보다 앞이다.

> **판단(Ruling)** — 상자를 **둘로** 나눈다. 하나로 합치면 영상 지시(움직임·립싱크·시간)가
> 이미지 프롬프트에 붙는다. 그것이 해로운 것은 추측이 아니라 이 저장소가 이미 코드로
> 막고 있는 일이다 — `stillOnly()` 가 `shows` 에서 움직임 서술을 일부러 걸러낸다
> (`lib/cuts.js`). 같은 이유가 여기에도 그대로 적용된다.

### C. 각인 — 고친 프롬프트가 낡음을 만들어야 한다

이 저장소의 규칙은 한 줄이다: **프롬프트에 실리는 것만 각인에 담는다. 있을 때만 담는다.**

| 각인 | 더할 것 | 조건 |
|---|---|---|
| `imageContextKey` | `\|prompt:<cut.image_prompt>` | 있을 때만 |
| `imageContextKey` | `\|imgnote:<settings.image_note>` | 있을 때만 |
| `clipKey` | `\|prompt:<cut.clip_prompt>` | 있을 때만 |
| `clipKey` | `\|clipnote:<settings.clip_note>` | 있을 때만 |
| `styleKey` | (손대지 않는다 — `style.note` 가 이미 들어 있다) | — |

"있을 때만"이 아니면 **지금 저장된 모든 산출물의 각인이 불일치가 되어 통째로 재구매가
제시된다.** 이 저장소는 같은 함정을 `style_of`·해상도·`tone_of`·자막 위치에서 네 번
겪었고, 그 주석들이 `lib/steps.js` 에 그대로 남아 있다.

프롬프트를 고치면 **낡음이 뜬다 → 화면이 "다시 만들어야 해요 (유료)" 라고 말한다.**
사장님이 고쳤는데 아무 일도 안 일어나는 것보다, 값이 든다고 미리 말하는 쪽이 맞다.

### D. 언어 — 누가 읽느냐가 정한다

> **규칙: 이미지·영상 모델이 읽는 말은 영어. 기획 LLM 과 사장님이 읽는 말은 한국어.
> 대사는 한국어.**

번역 LLM 을 새로 두지 않는다. 각 단계의 SYSTEM 프롬프트에 **그 칸은 영어로 쓰라**고
적는다(사장님 지적 — 굳이 번역 단계가 필요한 부분이 아니다).

| 값 | 누가 읽나 | 언어 |
|---|---|---|
| `shows` (화면 설계) | 이미지 모델 | **영어** |
| 움직임 3축 (`motion_axes`) | 영상 모델 | **영어** |
| `environment` / 무대 | 두 모델 | **영어** |
| `tone` | 두 모델 | **영어** |
| `transition` | 이미지 모델 | **영어** |
| 캐스팅 `look` | 이미지 모델 | **영어** |
| 캐스팅 `who` | 영상 모델 (`${who} speaks to the camera`) | **영어** |
| `focus.subject` · `focus.look` | 두 모델 | **영어** |
| `narrator_voice` | 영상 모델 (`Voice: …`) | **영어** |
| `beat` (장면이 하는 일) | 기획 LLM + 사장님 | 한국어 |
| `angle` (전달 방식) | 기획 LLM + 사장님 | 한국어 |
| `speaker` (화자) | 캐스팅 LLM + 사장님 | 한국어 |
| `topic` | 사장님 + (드물게) 이미지 폴백 | 한국어 |
| **`line` (대사)** | 영상 모델 + **자막** + 사장님 | **한국어** |

`topic` 은 갈등이 있다 — 사장님이 읽는 값이면서 초점이 없을 때 이미지 앵커 폴백으로
쓰인다(`subjectOf`). **한국어로 둔다**: 사장님이 읽는 쪽이 먼저고, 폴백은 `focus.subject`
(영어)가 있으면 애초에 안 탄다.

**★ 이 전환은 이미 산 산출물을 낡게 만들지 않는다.** 낡음은 "저장된 각인 vs 지금 값"인데,
`shows`·`tone`·무대는 전부 **컷에 저장된 값**이다. 언어 정책은 *앞으로 생성될 값*만
바꾼다. 옛 프로젝트의 한국어 `shows` 는 그대로 읽히고 각인도 안 움직인다.

**★ 근거의 한계를 적어 둔다.** "영어가 성능이 더 좋다"는 **사장님의 판단이고, 이
저장소에 한국어 대 영어 비교 실측은 없다.** 지금 나가는 프롬프트는 내용물이 한국어인데
결과물이 쓸 만하다. 그래서 이 항목은 *가정 위에서* 진행하고, `scripts/measure/` 로
전후를 재는 것을 후속으로 남긴다 — 이 저장소의 규율이 *측정 없이 품질을 주장하지 않는다*
이기 때문이다.

### E. Opus 5 를 향한 프롬프트 정리 (같은 손에서)

지금의 SYSTEM 프롬프트들은 **gpt-4o 를 상대로 쓰인 글**이다. `**반드시**`·`절대` 같은
강조가 여러 줄 있는데, Opus 5 는 지시를 훨씬 문자 그대로 따라서 그 강조가 과하게 작동한다.

범위를 좁게 잡는다: **강조 표시만 걷고 구조·요구사항은 한 줄도 바꾸지 않는다.**
프롬프트를 다시 쓰는 일이 아니다. 어차피 D 때문에 같은 파일을 열기 때문에 함께 한다.

## 안 하는 것 (YAGNI)

- **②시나리오에서 프롬프트 편집** — `shows` 가 아직 없다. 시나리오 확정 **후에** 화면
  설계가 돈다. 편집 자리는 ④이미지·⑤영상이 맞다.
- **번역 LLM** — 위 D.
- **프롬프트 되돌리기(버전 히스토리)** — 원본은 언제나 다시 만들 수 있다(덮어쓰기를 비우면
  코드가 생성한 본문으로 돌아간다). "원래대로" 버튼 하나면 된다.
- **꼬리를 사장님이 끄는 스위치** — 꼬리가 계약인 이유가 그것이다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `lib/cuts.js` | `buildImagePrompt`·`buildClipPrompt` 를 본문/꼬리로 가르고 덮어쓰기를 받는다. SYSTEM 프롬프트 영문 지시 |
| `lib/scenario.js` | SYSTEM — `focus`·`narrator_voice` 를 영어로 적으라고 지시 |
| `lib/steps.js` | `imageContextKey`·`clipKey` 에 덮어쓰기를 담는다(있을 때만) |
| `lib/styles.js` | `normalizeStyle` — `clip_note` 게이트(화이트리스트 없는 얕은 머지를 막는 자리) |
| `app/create/[id]/images/page.js` | 컷마다 프롬프트를 보여 주고 고치는 자리 |
| `app/create/[id]/video/page.js` | 같은 것, 영상 쪽 |
| `app/create/[id]/briefing/page.js` | 프로젝트 공통 지시 상자 둘 |

## 지켜야 할 불변 (테스트가 판정한다)

1. **덮어쓰기가 없으면 프롬프트가 글자 그대로 지금과 같다.** 본문/꼬리로 가르는 리팩터가
   기존 프롬프트를 한 글자도 안 바꿨다는 것을 못 박는다 — 이게 이 작업에서 가장 위험한 자리다.
2. **덮어쓰기가 있어도 꼬리는 남는다.** 사장님이 "글자를 크게 넣어라"라고 써도
   `no text or letters` 가 그 뒤에 붙는다.
3. **덮어쓰기가 없는 컷의 각인이 안 바뀐다.** 지금 저장된 산출물이 낡지 않는다.
4. **덮어쓰기를 넣으면 각인이 바뀐다.** 고쳤는데 조용히 지나가지 않는다.
5. **대사는 영상 프롬프트 편집으로 바뀌지 않는다.** 자막과 갈리지 않는다.
6. `settings.clip_note` 는 화이트리스트를 지난 값만 저장된다.

## 열린 질문

- **한국어 대 영어 실측** — 위 D. 유료라 사장님 승인 후.
- **덮어쓰기와 `edit_instruction` 의 관계** — 둘 다 살려 둔다(하나는 본문 교체, 하나는
  뒤에 붙는 지시). 실제로 써 보고 하나가 죽으면 그때 걷는다.
