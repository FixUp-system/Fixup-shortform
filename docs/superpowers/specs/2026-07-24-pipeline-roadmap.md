## 2. 현재 코드 실측 (2026-07-24, `feature/staged-workflow-m1`)

| 원문 단계 | 상태 | 실제 |
|---|---|---|
| ① 씬 분해 | 부분 | `lib/script.js` 대본 → `lib/cuts.js` 컷. `visual_description`·`camera`·`mood`·`role` 없음 |
| ② 대본 게이트 | 있음 | 문단 편집 + 수정 지시 + coverage |
| ③ TTS → 타이밍 | **없음** | `seconds`는 LLM 추정 |
| ④ 레퍼런스 | 부분 | 업로드 사진 주입 경로 동작(nano-banana `/edit`). 스타일 시트·공통 스타일 토큰 없음 |
| ⑤ 이미지 + QC | 있음 | 후보 2장 → VLM 선별 → 지적사항 반영 1회 재시도 → `needs_attention` 격리 |
| ⑥ 영상화 + QC | 없음 | `/api/video`의 Kling/Veo 어댑터 재활용 가능 |
| ⑦ 씬 단위 재생성 | 부분 | 이미지 재생성 3회. 영상화 단독 재시도·대본 연동 재생성 없음 |
| ⑧ ffmpeg 병합 | 없음 | 자막·덕킹·-14 LUFS·세이프존·인코딩 전무 |
| 잡 큐/상태머신 | 부분 | 컷 상태·실패 격리는 있으나 큐 없음. 서버 재시작 시 `generating` 영구 잔류, 재개 경로 없음 |
| 모델 어댑터 | 부분 | 영상 O / 이미지 △(fal 단일) / TTS X |
| 산출물 저장 | 부분 | `data/*.json` + 업로드 사진. **생성 이미지는 fal 원격 URL만 보관** |
| 비용 추적 | 부분 | 호출당 기록. 프로젝트·컷 귀속 없음 |

## 3. 확정 순서

```
① 자료 (텍스트 + 사진) → 브리핑 추출·부족분 질문 → [게이트 1: 브리핑 확정]
② 대본 생성 → [게이트 2: 대본 확정]        무료
③ 컷 분할 (씬 스키마)
④ TTS → 컷별 실측 길이 확정               ← 클립 길이의 유일한 기준
⑤ 레퍼런스 확보 → [게이트 3: 사진 없을 때만 스타일 승인]
⑥ 컷별 이미지 생성 + VLM QC
⑦ 이미지 → 영상화 + QC → [게이트 4: 최종 검수·컷 단위 재생성]
⑧ 자막 + 병합/믹싱/인코딩 (전부 코드)
```

게이트가 4곳이지만 화면(사이드바 단계)은 6개 그대로다 — 브리핑 확정은 ①자료 안에서 일어난다. 설계는 `2026-07-24-briefing-intake-design.md` 참조.

원문의 핵심 순서 결정을 그대로 따른다: **클립 길이는 오디오가 정한다.** ④가 ⑥⑦ 앞에 있는 이유다.

현행 게이트 2(컷별 이미지 확인)는 게이트 3으로 흡수한다. 이미지만 따로 검수시키면 사장님이 같은 컷을 두 번 본다.

## 4. 우선순위

## 3.5 저장소 — Supabase 확정 (2026-07-24)

DB는 Supabase(Postgres + Storage)를 쓴다. 이건 품질 개선이 아니라 **배포의 전제**다: 현재 코드는 `data/*.json`과 `data/uploads`에 직접 쓰는데 Vercel 함수의 파일시스템은 읽기 전용이라 지금 구조로는 로컬 밖에서 한 번도 못 돈다.

| 지금 | 옮길 곳 |
|---|---|
| `data/projects/*.json` | `projects` 테이블 (+ `cuts`를 별도 행으로 분리 — 컷 단위 갱신이 잦다) |
| `data/costs.json` | `cost_records` 테이블. 이 참에 `project_id`·`cut_idx` 귀속 |
| `data/uploads/*` (사용자 사진) | Storage 버킷 `uploads` |
| fal 원격 URL만 들고 있는 생성 이미지 | Storage 버킷 `renders` — 생성 즉시 내려받아 저장 (만료 부채 해소) |
| 앞으로 생길 TTS 오디오·클립·최종 렌더 | 같은 `renders` 버킷 |

부수 효과 둘:
- `lib/projects.js`의 프로젝트별 promise-chain 락이 필요 없어진다. 컷 단위 UPDATE는 행 단위로 직렬화된다.
- 컷 상태를 DB에 두면 고아 `generating` 회수를 조회 한 방으로 처리할 수 있다.

**P0 — 자료를 제대로 받고, 순서 바로잡기**
- 자료 수집·브리핑 확정 (`2026-07-24-briefing-intake-design.md`) — 07-23 실험 결론("정보량이 본질")에 직접 답하는 유일한 항목이라 P0 맨 앞
- 컷 스키마 보강: `role`(opening/body/closing — 훅·CTA는 그 안의 한 방식일 뿐, 홍보를 전제하지 않는다), `visual_description`, `mood` 추가. 이미지 프롬프트의 원천을 문장이 아니라 `visual_description`으로
- TTS 어댑터 + 컷별 오디오·character 타임스탬프 저장, `actual_audio_duration`을 컷에 기록
- 컷 분할과 이미지 생성 분리(현재 `runCutsPipeline`이 한 덩어리) — 사이에 ④가 들어가야 한다
- **Supabase 이행** (3.5절): 파일 저장 → Postgres + Storage. 배포의 전제이고, 생성물 보관(fal URL 만료 부채)이 여기서 함께 해소된다
- **고아 `generating` 복구**: 서버 재시작 시 잔류 상태를 `needs_attention`으로 회수

**P1 — 영상까지**
- 영상 어댑터를 컷 파이프라인에 연결(이미지 → 클립, `actual_audio_duration` 기준)
- 클립 QC(첫/끝 프레임 VLM), 게이트 3 UI(컷 단위 재생성 3종: 이미지만 / 영상만 / 대본 수정 후)
- ffmpeg 병합: 컷 이어붙이기 + 내레이션 믹싱 + 자막 번인(세이프존) + -14 LUFS + 9:16 인코딩

**P2 — 품질·운영**
- 스타일 토큰 공통 suffix, 사진 없는 프로젝트용 스타일 시트 + 게이트 2
- BGM 무드 선택·덕킹
- 렌더 워커 인프라 (ffmpeg 실행처가 정해지면), 필요 시 pgmq/Supabase Queues
- 인증·RLS (Supabase Auth)

**P3 — 정책**
- 크레딧 차감 구현(영상형 3 / 슬라이드형 1, 재생성 상한)
- 폴백 모델, 지수 백오프

## 5. 열린 결정

- **TTS 모델** — character 타임스탬프를 주는 것으로. 한국어 품질이 선정 기준
- 렌더 워커 인프라 — ffmpeg가 Vercel 함수에서 도는지가 갈림길 (저장소는 Supabase로 확정, 3.5절)
- 슬라이드형(D8) 경로를 ⑥ 생략으로 처리할지, 별도 렌더 경로로 둘지

## 6. 진행 중 작업에 미치는 영향

`feature/deferred-settings`(설정 지연): 목적·길이 제거는 이 로드맵과 일치하므로 그대로 간다. **비율 선택은 폐지** — 9:16 고정이므로 대본 게이트에 비율 칩을 두지 않는다. 예상 초 표시는 P0에서 TTS 실측으로 교체될 임시 표시다.
