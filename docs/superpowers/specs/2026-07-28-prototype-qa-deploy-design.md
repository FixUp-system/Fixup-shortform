# 프로토타입 — 로컬 e2e 30초 영상 — 설계

작성 2026-07-28 · 대상 브랜치 `feature/video-compose`

## 목표

**자료를 넣으면 자막이 구워진 30초 mp4 가 나온다.** 로컬에서, 한 번도 막히지 않고.

## 왜 하는가

뒷단(목소리·영상·합성)은 구현됐지만 **실제 fal 호출이 아직 0회**다. 파라미터는 전부 문서를 보고
추정한 값이라 맞는지 모른다. 대본 품질 과제도 다섯 개 남아 있지만, 그걸 더 다듬어도 뒷단이
터지면 아무 소용이 없다.

**제일 안 해본 것을 제일 싸게 먼저 해본다.** 얇은 한 줄을 진짜로 관통시켜, 이 파이프라인이
실제로 영상을 만들어 내는지부터 확인한다.

## 전제와 제약

- **실행**: 로컬 `npm run dev` 만. **배포하지 않는다**
- **합성**: 로컬 ffmpeg(`lib/compose.js` 기본 경로). 자막이 구워진 mp4 가 나온다
- **목표 길이**: 30초

### 비용

단계별 워크플로가 실제로 쓰는 엔드포인트 기준이다. `FAL_VIDEO_ENDPOINT`(Veo 3.1)는 이 경로가
아니라 `app/api/video/route.js`(옛 단발 t2v)만 쓴다 — **혼동하면 단가를 10배로 잘못 잡는다.**

| 항목 | 엔드포인트 | 계산 | 비용 |
|---|---|---|---|
| 클립 | `ltx-2.3/image-to-video/fast` | $0.04/s × 30s | $1.20 |
| 이미지 | `nano-banana` | 10컷 × 후보 2장 × $0.04 | $0.80 |
| 목소리 | `elevenlabs/tts/turbo-v2.5` | ~165자 | $0.01 |
| 합성 | 로컬 ffmpeg | — | $0 |
| **한 편** | | | **약 $2**, VLM 재시도 시 최대 $3 |

예산은 $10~50 이므로 여러 편 돌릴 수 있다. 다만 **상한이 없으면 실수 한 번에 바닥나므로**
가드를 먼저 만든다(1절).

## 범위

### 하는 것

1. 비용 가드
2. 목소리를 이미지 앞으로
3. e2e 30초 관통

### 하지 않는 것 (나중에)

- **배포 일체** — Supabase 전환, Vercel 적응, 팀 QA. 로컬에서 영상이 나오는 것을 먼저 본다
- **자막 오버레이** — 로컬 ffmpeg 가 자막을 구워 주므로 지금은 필요 없다. 배포할 때 fal
  합성으로 가면 그때 만든다
- **긴 컷의 자동 재분할** — 2절에서 알려주기만 한다. 실제로 쪼갤지는 관통에서 얼마나 자주
  걸리는지 보고 정한다
- **대본 품질 잔여과제 1~5** — 관통이 되고 나서

## 1. 비용 가드

`lib/costs.js`는 지금 **기록만 하고 막지 않는다.** 한 편이 $2~3 이라 해도, 되돌리기·재생성이
얽히면 한 프로젝트에서 훨씬 더 나갈 수 있다.

### 설계

`lib/costs.js`에 추가한다:

```
spentTotal()            → 전체 누적 USD
spentForProject(id)     → 프로젝트 누적 USD
assertBudget({ projectId, endpoint, amount })
```

`assertBudget`은 **이번 호출의 예상 비용을 더한 값**이 상한을 넘으면 던진다. 호출한 뒤에 재는
것이 아니라 나가기 전에 막는다.

- `SHOTFORM_BUDGET_TOTAL_USD` (기본 20)
- `SHOTFORM_BUDGET_PROJECT_USD` (기본 5) — 한 편 $2~3 의 두 배쯤

호출 지점은 셋이다: `imagegen.js` · `tts.js` · `i2v.js`. **가짜 모드일 때는 부르지 않는다**(0원).

합성에는 걸지 않는다 — 로컬 ffmpeg 라 $0 이고, 거기서 막히면 이미 치른 클립 값이 결과물 없이
버려진다.

### 딸린 변경

비용 기록에 `project_id`가 없다. `addRecord` 호출부에 넣고, 그러려면 `generateImage`·
`generateSpeech`·`generateClip`이 `projectId`를 받아야 한다.

### 화면

가드에 걸리면 파이프라인이 실패하고 기존 에러 경로를 탄다. 메시지는
`"예산 상한($N)에 닿아 멈췄어요"` 로 구분되게 쓴다 — "고장"과 "예산"을 헷갈리면 안 된다.

### 테스트

단위 테스트: 누적 합계, 상한 미달 통과, 초과 시 throw, 가짜 모드 통과, 호출부가 실제로 막히는지.
`SHOTFORM_DATA_DIR`을 임시 폴더로 두어 실제 비용 기록을 오염시키지 않는다(기존 규칙).

## 2. 목소리를 이미지 앞으로

### 왜

**낭독 길이가 컷 구조를 판정하기 때문이다.** TTS 실측이 `cut.seconds`를 덮는데, 그 값이 i2v
상한(10초)을 넘으면 `truncated`로 잘린다 — 낭독은 12초인데 그림은 10초에서 끝나는 어긋남이다.
지금 순서에서는 **이미 이미지 값을 치른 뒤에** 그 사실을 안다.

비용도 같은 방향이다. 30초 한 편에서 TTS 는 $0.01, 이미지는 $0.80 이다. **80배 싼 것으로 먼저
재고 비싼 것을 나중에 한다.**

기존 순서는 필연이 아니었다. `lib/steps.js` 주석이 적어둔 제약은 "컷 분할 뒤 & 영상 앞"뿐이고,
목소리가 이미지 뒤로 간 것은 **컷 분할이 이미지 단계(`POST /cuts`)에 묶여 있었기 때문**이다.

### 어떻게

**컷 분할을 대본 승인 직후로 당긴다.** 분할은 OpenAI만 쓰고 fal 을 부르지 않아 비용이 미미하다
(문장 나누기 + 화면 설계 2패스). 대본을 승인하면 이어서 돌리고, 사장님은 목소리 화면에서 멈춘다.

그러면 단계 개수는 그대로고 순서만 바뀐다:

```
① 자료 → ② 대본 → ③ 목소리 → ④ 이미지 → ⑤ 영상 → ⑥ 완성
```

`runCutsPipeline`을 둘로 가른다:

- `runSplitPipeline(projectId)` — 분할 + 화면 설계. 대본 승인이 부른다
- `runImagesPipeline(projectId)` — 컷별 이미지 생성. 이미지 단계가 부른다(지금 `processCut` 그대로)

`regenCut`은 이미지 재생성이므로 뒤쪽에 남는다.

### 상태 판정

`status`는 **마지막으로 끝난 산출물**, `currentStepKey`는 **다음에 열릴 화면**이다. 이 구분을
흐리면 "완성본을 두고 이미지 화면으로 돌아가는" 결함이 재발한다(커밋 `be15c5b`가 겪은 것).

새 흐름: `cuts`(분할 완료) → `voice`(목소리 완료) → `images`(이미지 완료) → `video` → `done`.
`images`가 새 상태값이다. `currentStepKey`는 지금처럼 **뒤 단계부터** 확인한다.

### 긴 컷 알리기

목소리가 끝나 `cut.seconds`가 실측으로 덮인 뒤, **이미지 화면에 들어갈 때** 10초를 넘는 컷을
표시한다. 이미지 값을 치르기 전에 보이는 것이 요점이다.

문구는 무엇이 잘리는지 말한다: `"이 컷은 낭독이 12초라 영상은 10초까지만 나와요"`.
쪼개는 것은 이번 범위가 아니다.

### 테스트

- `lib/steps.js`: 새 순서의 `STEPS`·`currentStepKey`·`isReachable`. 특히 **각 status 값마다**
  어느 화면이 열리는지 전부
- `runSplitPipeline`/`runImagesPipeline`이 갈라져도 컷의 산출물이 같은지
- 10초 초과 컷 판정 단위 테스트 (경계값 10.0 포함)
- **회귀 하한선**: 화면·라우트에 박힌 단계 번호(③④⑤)와 안내 문구가 전부 새 순서를 따르는지.
  `be15c5b`가 같은 자리에서 옛 번호를 고쳤다

## 3. e2e 30초 관통

**실제 fal 호출이 처음 나가는 지점.** 여기까지의 모든 코드가 추정 위에 서 있다.

### 조건

```
SHOTFORM_FAKE=off
SHOTFORM_COMPOSER=            # 비운다 — 로컬 ffmpeg 로 자막을 굽는다
FAL_I2V_ENDPOINT=fal-ai/ltx-2.3/image-to-video/fast
목표 30초
```

`SHOTFORM_FAKE_IMAGES`가 남아 있으면 지운다 — `1`이면 fal 이 전부 가짜가 된다.

### 완료 기준

브리핑 → 대본(→ 컷 분할) → 목소리 → 이미지 → 영상 → 완성까지 한 번도 막히지 않고,
**자막이 구워진 30초 mp4 를 내려받을 수 있다.**

### 확인할 것

- fal 응답의 필드 이름이 코드의 가정과 맞는가 (`data.audio.url`·`data.audio.duration`·
  `data.video.url`·`data.images[0].url`)
- TTS 가 돌려준 실측 길이가 `cut.seconds`를 덮고, 그 값이 클립 길이로 넘어가는가
- 클립이 소리보다 짧을 때 마지막 프레임 정지로 길이가 맞춰지는가 (`buildFfmpegArgs`의 `tpad`)
- 자막이 세이프존(하단 18%)에 제대로 얹히는가 — 폰트가 없으면 글자가 깨진다(`assets/`)
- 컷을 이어붙인 전체 길이가 30초 근처인가
- **TTS 실측이 추정치(5.5자/초)와 얼마나 벌어지는가** — 10초 초과 컷이 흔한 문제인지 드문
  문제인지가 여기서 갈린다
- `data/costs.json`의 합계와 fal 대시보드의 실제 청구액을 대조 — `PRICE_TABLE`이 얼마나 틀렸는가

### 틀린 것을 고칠 때

파라미터가 틀렸으면 그 자리에서 고치고, **고칠 때마다 테스트를 하나 더한다**(같은 실수를 다시
하지 않게).

## 검증 환경

- **1·2**: 로컬 `npx vitest run` (기존 211개 그린 유지가 하한선. 단 2절은 단계 순서가 바뀌므로
  `steps.test.js`와 화면 테스트의 기대값이 **의도적으로** 바뀐다)
- **3**: 로컬 `npm run dev` + 실제 fal 키. 수동 관통

## 곁가지 (착수 전 정리)

- 메인 워크트리 `shotform-saas`에 **미커밋으로 남은 길이 임계 작업**(`lib/script.js`의
  `LENGTH_SLACK` 1.3→1.15, `AIM_BAND`)을 먼저 커밋한다. 테스트는 이미 그린이다
- `feature/video-compose`는 `feature/synopsis-redefinition` 위에 얹혀 있고 둘 다 main 미병합이다

## 미검증 가정

이 스펙이 기대는 것 중 아직 사실로 확인되지 않은 것:

- fal 응답 필드 이름 (→ 3절에서 판명)
- `PRICE_TABLE`의 추정 단가 (→ 3절 후 실제 청구와 대조)
- 로컬 ffmpeg 합성이 실제로 도는가 — `ffmpeg-static` 경로, 폰트(`assets/`), 자막 필터
  (→ 3절에서 판명. **가짜 모드에서는 합성을 아예 건너뛰므로 한 번도 돈 적이 없다**)
- TTS 실측 길이가 추정치와 얼마나 벌어지는지 (→ 3절에서 처음 관측)
- **TTS 가 같은 문장을 다시 읽었을 때의 편차.** 결정적이지 않은데 `stability`·`seed` 를
  보내지 않아 fal 기본값에 맡기고 있다. 편차가 크면 [다시 읽기]가 `cut.seconds` 를 흔들고,
  그것이 클립 길이·자막 타이밍까지 밀어낸다 (→ 3절에서 두세 번 읽혀 비교)

## 이 다음

관통이 되면 그때 정한다. 후보는 배포(Supabase·Vercel·자막 오버레이·팀 QA)와 대본 품질
잔여과제 1~5 인데, **관통에서 무엇이 부서지는지 보고 나서** 순서를 정하는 것이 맞다.
