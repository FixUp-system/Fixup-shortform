# 한 번에 굽는 영상을 단계별 화면으로 — 그리고 그림 한 장만 다시 그리기

2026-08-20 · 브랜치 `feat/theme-light` · 워크트리 `.claude/worktrees/step-gate`

## 왜 지금 하는가

`/film/[mode]` 한 화면이 입력·시나리오·그림·굽기를 전부 받는다(540줄). 사장님 지시:
**"1페이지에서 전부 진행되는데 단계별로 진행될 수 있도록. 기존에 있는 내용을 활용해서."**

⚠️ 지난 회차([[shotform-control-restraint-2026-08-19]] §7-6)에 이 전환을 **보류**했다 —
"두 방식 중 하나가 확정된 뒤에 한다, 지금 나누면 `?mode=` 같은 곧 버릴 구조를 만든다."
2026-08-20 에 사장님이 다시 지시했으므로 진행한다. 다만 **그 함정은 피한다** — 아래 §1 이
그 방법이고, 이 설계의 핵심이다.

곁들여 **그림 한 장만 다시 그리기**를 넣는다. 지금은 축 하나를 손봐도 넉 장을 통째로 다시
그린다($0.32). 오늘 하루에만 두 번 그렇게 썼다.

## 결정된 것 (사장님 확인 2026-08-20)

| 물음 | 답 |
|---|---|
| 지금 한 화면은 | **지우지 않고 `/film/one/[mode]` 로 옮긴다** |

## 1. 주소 — `mode` 는 뜻이 있는 자리에만 둔다

코드가 이미 답을 갖고 있었다. `app/api/film/[id]/scenario/route.js:10`:

> ★★ **이 라우트만 방식(mode)을 안 본다.** 시나리오는 두 방식이 **공유하는 하나**여야 한다.

즉 **입력·시나리오는 방식과 무관하고, 그림부터 갈린다.** 주소가 그 사실을 그대로 담는다.

```
/film/one/order?id=…          기존 한 화면 (파일만 이동, 내용 그대로)
/film/one/refs?id=…

/film/<id>/briefing           1 입력      ─┐ 두 방식 공유
/film/<id>/scenario           2 시나리오   ─┘
/film/<id>/order/images       3 그림      ─┐
/film/<id>/order/video        4 영상       │ 방식별
/film/<id>/order/done         5 완성      ─┘
```

**나중에 방식 하나가 확정되면 뒤쪽 세그먼트만 걷어낸다.** 앞 두 단계는 손대지 않는다 —
이것이 "곧 버릴 구조를 만들지 않는다"의 실제 내용이다.

### 왜 기존 화면을 옮기는가 (기술적 강제)

Next.js 는 같은 자리에 이름이 다른 동적 세그먼트를 못 둔다. `app/film/[mode]` 가 있는 한
`app/film/[id]` 를 만들면 **빌드가 죽는다.** 둘 중 하나가 비켜야 한다.

`/film/...` 로 들어오는 링크는 그 화면이 자기 자신을 가리키는 두 줄뿐이고
(`app/film/[mode]/page.js:271,528`) 미배포라 밖으로 나간 주소가 없다. 새 흐름이 앞으로
주로 쓸 길이므로 그쪽이 깔끔한 주소를 갖는다.

`app/film/one/` 은 정적 세그먼트라 `[id]` 와 공존한다(정적이 이긴다). 프로젝트 id 가
`"one"` 일 수 없으므로 충돌하지 않는다.

## 2. 기존 자산을 어떻게 쓰는가

새로 쓰는 로직은 `lib/film/steps.js` **하나뿐**이다. 나머지는 이동·재사용이다.

| 가져다 쓰는 것 | 어디서 | 어떻게 |
|---|---|---|
| 단계 표 + 라우팅 가드의 **모양** | `lib/steps.js` | `lib/film/steps.js` 를 같은 모양으로 신설 |
| 프로젝트 로드 · 스테퍼 · 못 연 단계 되돌리기 | `app/create/[id]/layout.js` | `app/film/[id]/layout.js` 로 이식 |
| 버튼 문 판정 | `lib/film/gates.js` | **그대로** — 한 벌을 유지한다 |
| 방식 표 · 문서 판독 | `lib/film/mode.js` · `doc.js` | **그대로** |
| 폴링 루프 | `lib/poll.js` | **그대로** |
| 각 단계 화면 | 지금 페이지의 `<section>` 넷 | 그대로 떼어 옮김 |

`lib/steps.js` 를 확장하지 않고 **film 전용 표를 따로 두는 이유**: 저쪽 표는 컷 파이프라인의
낡음 판정·`projectSpeaks` 분기까지 얽혀 있다. 한 표에 두 흐름을 담으면 한쪽을 고칠 때마다
다른 쪽을 확인해야 한다. 대신 **모양은 같게** 해서 읽는 사람이 배운 것을 그대로 쓴다.

### `lib/film/steps.js` 가 답하는 것

```js
FILM_STEPS                      // 표 하나 — 스테퍼와 가드가 같은 것을 본다
filmStepHref(step, id, mode)    // 방식별 단계에만 mode 가 들어간다
filmStepFromPathname(pathname)
currentFilmStepKey(project, mode)
isFilmStepReachable(key, project, mode)
```

문을 여는 조건 — **새로 만들지 않고 이미 있는 판정을 부른다**:

| 단계 | 열리는 조건 | 판정을 가진 자리 |
|---|---|---|
| 1 입력 | 언제나 | — |
| 2 시나리오 | 프로젝트가 있다 | — |
| 3 그림 | `scenario.text` 가 있다 | `app/api/film/[id]/images/route.js` 와 같은 조건 |
| 4 영상 | `film.images` 가 있다 | `filmOf(project, mode)` |
| 5 완성 | `film.video?.url` 이 있다 | `filmOf(project, mode)` |

⚠️ **"열려 있다"와 "지금 있어야 한다"는 다르다.** 2026-07-29 에 단계별에서 이것을 섞어
완성 단계에 아무도 못 들어가는 잠금 고리를 만들었다(`shotform-character-consistency-2026-07-29`).
완성은 굽기가 끝나면 **열리지만**, 현재 단계는 여전히 영상이다.

## 3. 화면

`app/film/[id]/layout.js` 가 프로젝트를 한 번 읽고 스테퍼를 그리고 가드를 건다. 각 단계
페이지는 화면만 그린다 — `app/create/[id]/layout.js` 와 같은 구조다.

**두 방식이 같은 단계 컴포넌트를 쓴다.** 지금 페이지 머리말의 경고를 그대로 지킨다:

> 화면을 둘로 두면 한쪽에만 붙은 버튼·한쪽에만 뜬 안내가 그대로 실험 조건의 차이가 된다 —
> 그러면 결과의 차이가 방식 때문인지 화면 때문인지 알 수 없다.

3단계 그림 화면:
- 방식 칩 둘 — 고르면 같은 `<id>` 를 들고 옆 방식으로 건너간다(한 시나리오, 두 방식)
- 그림 카드마다 `다시 만들기`
- 아래에 `전부 다시 만들기`
- 다음 → 영상

## 4. 그림 한 장만 다시 그리기

`runFilmImages` 가 "어느 축만"을 받는다. 계획(`imagePlanFor`)을 기준으로 목록을 다시 짜되,
**안 고른 축은 기존 그림을 그 자리에** 둔다(덧붙이기가 아니라 자리 맞춤).

```js
runFilmImages(projectId, ownerId, mode, { only: ["subject"], ...deps })
```

`only` 가 없으면 오늘 그대로 전부 그린다 — 옛 호출부 회귀 0.

### 함정 셋과 처방

**① 앵커** — 장면 순서 방식은 앵커를 먼저 만들고 장면 그림 **전부**가 그것을 참조한다
(직전 그림이 아니다: 오차가 누적된다). 장면 하나만 다시 그릴 때 앵커를 새로 만들면 나머지
셋과 갈린다.
→ 앵커가 `only` 에 없으면 **기존 앵커 URL 을 참조로 재사용**한다.

**② 시나리오 판 섞임** — 지금은 `films[방식].scenarioTries` 에 "어느 판으로 그렸는지"를
적어 보증한다. 부분 재생성이 판을 넘나들면 그 보증이 깨지고, **"차이는 방식 때문"이라는
이 기능의 대전제를 나중에 아무도 확인할 수 없다.**
→ `film.scenarioTries !== project.scenario.tries` 면 **선택 재생성을 안 연다**(전부 다시
그리기만 열린다). 화면도 같은 판정으로 버튼을 잠근다.

**③ 계획에서 사라진 축** — 시나리오가 바뀌면 축 구성이 달라진다(`focus` 가 바뀌면 키가
통째로 바뀐다). 옛 그림이 되살아나면 안 된다.
→ 항상 **계획을 기준으로** 목록을 재구성하고, 계획에 없는 키의 그림은 버린다. 계획에
있는데 그림이 없는 키는 `only` 와 무관하게 그린다(빈 자리를 남기지 않는다).

### 값과 잠금

- `imageTries` 는 **한 장만 그려도 오른다** — 값이 실제로 나갔고, 상한은 지출을 막는 그물이다
- 재진입 잠금(`isDrawLocked`)·굽는 중 금지는 **그대로**다. 새 문을 만들지 않는다
- 라우트는 `only` 의 각 값이 **그 방식의 계획에 있는 키인지** 검사한다. 모르는 키는 400

## 5. 시험

**`lib/film/steps.js`** — 순수 함수라 값으로 잰다(`tests/film-ui.test.js` 의 gates 시험과
같은 방식). 재는 것은 "글자가 있는가"가 아니라 **막다른 길이 안 생기는가**다:
- 못 연 단계로 직접 들어가면 지금 있어야 할 단계로 돌려보낸다
- 굽기가 끝난 프로젝트가 완성 단계에 들어갈 수 있다(2026-07-29 의 잠금 고리 회귀 방지)
- 방식별 단계의 주소에는 `mode` 가 들어가고, 공유 단계에는 안 들어간다

**선택 재생성** — 가짜 이미지 생성기로:
- 안 고른 축의 URL 이 그대로다
- 앵커를 다시 만들지 않고 기존 것을 참조로 쓴다
- 시나리오 판이 다르면 열리지 않는다
- 계획에서 빠진 축의 그림이 안 되살아난다
- 계획에 있는데 없는 그림은 `only` 밖이라도 그린다

**라우트** — 모르는 축 이름은 400 · 그리는 중 409 · 굽는 중 409(기존 문 회귀 0)

**화면** — 소스 문자열 검사. ⚠️ `setInterval` 금지 그물이 세 파일에 흩어져 있어 **새 화면은
어디에도 안 걸린다**(CLAUDE.md). `tests/poll-migration-ui.test.js` 의 화면 목록에 새 단계
화면들을 손으로 넣는다.

⚠️ **화면 파일을 손댔으면 한 번 굽는다** — 소스 문자열 검사는 문법이 깨진 파일을 못 잡는다.
dev 서버를 끄고 `npx next build && rm -rf .next`.

## 6. 안 하는 것

- **광고 흐름(`/ads`)은 안 건드린다.** 지시 범위 밖이고, 저쪽은 자기 폴링 루프를 따로 든다
- **`lib/steps.js` 통합 안 한다.** 두 흐름의 표를 한 벌로 만드는 것은 방식이 확정된 뒤 일이다
- **그림 낡음 판정(각인)은 안 만든다.** 지금 film 에는 `scenarioTries` 하나뿐이고, 그것으로
  §4-② 를 막는다. 축별 각인은 필요해지면 그때 넣는다
- **상자에 인쇄된 글자 문제는 별건이다** — 사장님이 "밀키트 만드는 것까지는 괜찮다"고
  확인했다(2026-08-20). 남는 것은 한국어 광고에 영어 패키지가 나오는 것 하나
