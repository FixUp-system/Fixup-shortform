# 화면 정밀도 개편 — 설계

> 2026-08-03 · 브랜치 `feature/video-compose` · 시작 HEAD `53da117`
>
> 범위는 **시각 정밀도**다. 화면 로직·라우팅·단계 구조는 건드리지 않는다.

## 왜 하는가

사장님 판정: **"보기가 안 예쁘다."** 흐름이나 단계 수가 아니라 시각적 완성도가 문제다.

`localhost:3737` 홈 화면을 1440×900으로 실제로 띄워 본 결과, 촌스러움의 원인은
취향 문제가 아니라 **셋으로 특정된다.**

### ① 아이콘·번호가 폰트 글리프다 — 가장 큰 원인

사이드바가 쓰는 `⌂ ✦ ▤ ◫ ◷ ⚙︎ ⏻ ▶`와 단계의 `①②③④⑤⑥`은 전부 유니코드 글리프다.
폰트마다 굵기·크기·베이스라인이 달라 **세로줄이 눈에 띄게 어긋난다.**

`globals.css`의 `.side-item .ic { width: 18px; text-align: center }`는 **폭만** 맞춘다.
글리프 자체의 크기 차이는 그대로 남는다 — 스크린샷에서 `⌂`와 `✦`의 시각 크기가 확연히 다르다.

원문자는 더 나쁘다. 잠긴 단계는 `opacity: 0.5`가 걸리는데, 원문자는 획이 가늘어
그 상태에서 거의 보이지 않는다.

### ② 화면에서 가장 강한 색이 가장 안 중요한 것을 가리킨다

`globals.css`에 이렇게 적혀 있다:

```css
/* 크레딧 상자 — 화면에서 액센트가 허용된 유일한 곳 */
.credit-box { background: var(--accent-soft); border: 1px solid var(--accent); ... }
.credit-box b { font-size: 24px; font-weight: 800; }
```

그 "유일한 자리"의 내용은 **"실험 모드 / 무제한 / 테스트 기간에는 크레딧을 차감하지 않아요"** 다.
핑크 테두리 + 24px/800이라 화면에서 제일 먼저 눈에 들어온다.

정작 사장님이 매 순간 알아야 하는 것 — **"내가 지금 몇 단계인가"** — 는 회색 12px이다.
강조가 뒤집혔다. 게다가 저 안내문은 테스트 기간에만 유효한 임시 문구다.

### ③ 빈 공간이 설계되지 않았다

- `.chat { min-height: 340px }` — 인사말 한 줄뿐인 첫 화면에 340px 공백이 생긴다
- `main.work`는 `max-width: 1160px`인데 `.chat-wrap`은 `760px`이라 오른쪽 400px가 죽는다
- 세로로도 아래 300px가 빈다

1440×900에서 콘텐츠가 좌상단에만 몰려 있고 나머지가 비어 있다.

### 부수 원인 둘

**테두리 남용.** `surface` 배경과 `line` 테두리를 **동시에** 가진 요소가 많다
(`.panel`·`.chat-card`·`.cost-tile`·`.ask`·`.cost-table-wrap`). 배경만으로 이미 면이
갈리는데 테두리를 또 그어 화면이 상자로 잘게 쪼개진다. 홈 챗은 카드 → 입력칸 → 버튼이
각각 경계를 가져 **3겹**이다.

**실질 위계가 2단.** 굵기 400/500/800에서 400과 500의 차이는 화면에서 거의 안 보이고,
800은 24px에만 쓰인다. 크기 12/14/15/16에서 15와 16도 구분되지 않는다.

## 무엇을 바꾸는가 — A~F

### A. 아이콘을 SVG로 (`components/Icon.jsx` 신설)

유니코드 글리프를 전부 걷어내고 인라인 SVG 한 세트로 바꾼다. **라이브러리 의존성은 추가하지 않는다.**

- `viewBox="0 0 24 24"` · `stroke="currentColor"` · `stroke-width="1.5"` · `fill="none"` ·
  `stroke-linecap="round"` · `stroke-linejoin="round"`
- 렌더 크기는 호출부가 정한다(기본 18)
- `aria-hidden="true"` — 아이콘 옆에 항상 글자 라벨이 있으므로 스크린리더에 두 번 읽히면 안 된다

| 이름 | 대체 대상 | 쓰이는 곳 |
|---|---|---|
| `home` | `⌂` | 홈 — 빠른 생성 |
| `sparkle` | `✦` | 영상 만들기 (단계별) |
| `archive` | `▤` | 보관함 |
| `template` | `◫` | 템플릿 |
| `clock` | `◷` | 비용 기록 |
| `gear` | `⚙︎` | 설정 |
| `power` | `⏻` | 로그아웃 |
| `play` | `▶` | 로고 |
| `check` | `✓` | 완료된 단계 |

`.side-item .ic`는 `width: 18px; text-align: center`에서 `display: inline-flex`로 바꾼다 —
SVG는 이미 크기가 고정이라 폭 보정이 필요 없다.

### B. 단계 번호를 숫자로

`lib/steps.js`의 `STEPS[].no`를 `①`~`⑥` → `"1"`~`"6"`으로 바꾼다. 단계 표는 이 하나뿐이라
사이드바 스테퍼와 라우팅 가드가 같은 값을 본다.

`.side-step i`를 숫자 배지로 만든다:

```
18×18 · border-radius 50% · font-size 12px · font-variant-numeric: tabular-nums
```

배지 글자는 **12px**다. 11px는 F가 정한 크기 목록(12/14/16/18/28)에 없어 규칙 테스트가 빨개진다.

- **완료**: 숫자 자리에 `check` 아이콘(`--good`), 오른쪽 `em.ok` 제거 — 같은 말을 두 번 하지 않는다
- **진행 중**: 아래 C 참조
- **잠김**: 배지를 유지하고 `.locked`의 기존 `opacity: 0.5`를 그대로 쓴다.
  **"잠김" 글자는 뺀다** — 흐린 것으로 이미 말했다

> `tests/steps.test.js:28`이 `["①","②",…]`를 못 박고 있다. 함께 갱신한다.

### C. 액센트를 크레딧 → 진행 단계로 옮긴다 ★ 규칙 변경

이 개편에서 **유일하게 기존 규칙을 뒤집는 항목**이다.

**크레딧 상자**는 무채색으로 내린다:

```css
.credit-box { background: var(--surface2); border: 0; }
.credit-box b { font-size: 18px; font-weight: 600; }
```

**진행 중인 단계**가 액센트를 받는다:

```css
.side-step.on {
  background: var(--accent-soft);
  color: var(--ink);
  font-weight: 600;
  box-shadow: inset 2px 0 0 var(--accent);   /* 왼쪽 액센트 바 */
}
.side-step.on i { background: var(--accent); color: var(--deep); }
```

`em.now`("진행 중" 텍스트 칩)는 **제거한다** — 액센트 바와 채워진 배지가 이미 말한다.

근거: 화면에서 가장 강한 색은 사용자가 가장 알아야 할 것을 가리켜야 한다. 이 제품에서 그것은
"지금 몇 단계이고 다음이 무엇인가"다. 임시 안내문이 아니다.

> `tests/design-system.test.js:117` "액센트를 배경으로 쓰는 규칙은 크레딧 상자뿐이다" →
> **"액센트는 진행 중 단계 표시에만 쓴다"** 로 갱신. 크레딧 상자가 액센트를 쓰면 빨개져야 한다.

### D. 죽은 여백 제거

- `.chat { min-height: 340px }` **삭제**. 내용 높이를 따른다
- 홈의 빈 상태(인사말만 있을 때)는 카드가 작업 영역 세로 중앙에 온다
- `.chat-wrap`을 가로 중앙 정렬한다 — 1160px 폭에 760px 카드를 왼쪽에 붙여 둘 이유가 없다
- `main.work`의 `padding-bottom: 64px`을 40px로 — 바닥 공백이 과하다

### E. 테두리는 1겹

**규칙: `--surface` 배경을 가진 면은 테두리를 갖지 않는다.** 배경만으로 이미 면이 갈린다.
`--deep` 배경(입력칸)은 테두리를 **유지한다** — 그 선이 "여기에 쓸 수 있다"를 말한다.

대상: `.panel` · `.chat-card` · `.cost-tile` · `.ask` · `.cost-table-wrap` · `.brief`

이러면 홈 챗의 3겹이 2겹이 된다(카드 면 → 입력칸 선).

### F. 위계를 굵기와 대비로

종류를 **늘리지 않는다.** 스케일을 다시 배분해 대비만 키운다.

| 축 | 지금 | 바꾼 뒤 |
|---|---|---|
| 굵기 | 400 / 500 / 800 | **400 / 600 / 700** |
| 크기 | 12 / 14 / 15 / 16 / 24 | **12 / 14 / 16 / 18 / 28** |

- `body` 15px → **16px**. 본문이 16이 되면서 기존 15와 16의 구분 없는 두 단이 하나로 합쳐진다
  - **15px를 쓰던 자리는 전부 16px로 흡수한다**(`.bub`·`.cta`·`textarea.ref`·`.sent-input`·
    `.preview-sentence` 등). 15와 16 둘 다 남기면 종류만 늘고 화면에서는 구분되지 않는다
  - 예외 없이 흡수한다 — 원고를 읽는 `.script-box`는 이미 16px이라 그대로다
- `h1.pgtitle` 24/800 → **28/700**
- `.eyebrow` 14/500 → 14/600 (소제목이 소제목으로 보이게)
- `.cost-tile b` 24/800 → **28/700** (숫자는 커도 된다)
- `.credit-box b` 24/800 → **18/600** (C에서 내림)

> `tests/design-system.test.js:128`(굵기)·`:138`(크기)이 현재 값을 못 박고 있다. 함께 갱신한다.

## 건드리지 않는 것

- **다크 톤과 색 토큰 값** — `--bg`·`--surface`·`--ink` 등은 그대로
- **주 실행 버튼 = 바탕의 반대색** — AI 영상 서비스 6곳 실측에서 6/6 공통이었던 규칙이다
- **모서리 3단**(`--r-card`/`--r-ctl`/`--r-pill`)
- **화면 로직·라우팅·단계 구조** — `lib/steps.js`에서 바꾸는 것은 `no` 문자열뿐이다
- **`:root` 밖 hex 금지**·**그라디언트 금지** 규칙

## 범위 밖 (하지 않는다)

- 상단 벨트(42px 상시 점유)의 처리 — 정보 구조 판단이라 별건이다
- 홈 "빠른 생성"과 "단계별 만들기"의 통합 — 흐름 변경이다
- 밝은 테마 · 편집 도구형 레이아웃 — 사장님이 "정밀도만"으로 범위를 정했다
