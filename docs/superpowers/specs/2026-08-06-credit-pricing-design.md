# 크레딧 가격표 (2026-08-06)

크레딧을 **실비용 연동**에서 **정가 가격표**로 바꾼다. 사장님은 누르기 전에 얼마가 나가는지
알고, 우리는 원가와 청구를 따로 본다.

전 설계([[2026-08-05-credits-design]])는 "잔액 = 충전 − 실지출(USD)"이었다. 그 결과
"2편 넣었는데 1편으로 보인다" 같은 일이 생겼고(내림 + 기존 지출), 무엇보다 **사장님이
버튼을 누르기 전에 가격을 알 수 없었다.**

## 실측 원가 (2026-08-06, 원장 63건 = 전부 진짜 지출)

| 단계 | 건당 | 비고 |
|---|---|---|
| 클립(i2v) | **$0.420** | 5초 기준. 원가의 대부분 |
| 이미지 | **$0.080** | 컷당 1장 |
| 화면 설계 | $0.0102 | |
| VLM 검수 | $0.0033 | |
| 대본(초안+되돌리기+교정) | 합 $0.049 / 3편 | |
| 브리핑 | $0.0093 | |
| 목소리 | $0.0018 | |
| 캐스팅·컷 분할 | 합 $0.014 / 6건 | |

완주 프로젝트 실측(`ef031678`): **$2.82** (클립 $2.10 + 이미지 $0.64 + 나머지 $0.08).

```
편당 원가 ≈ $0.06(LLM 고정비) + 컷당 $0.50 × 컷 수
```

**원가는 "편"이 아니라 길이(=컷 수)에 비례한다** — 15초 ~$1.6, 30초 ~$3.06, 60초 ~$6.1.
길이는 사장님이 ①자료에서 고르므로 **시작 전에 알 수 있는 축**이다.

## 확정된 결정

| 결정 | 내용 |
|---|---|
| 가격 축 | **길이별 정가.** 15/30/45/60초 = 25/50/75/100 크레딧 |
| 환산 기준 | **1크레딧 ≈ $0.06 원가.** 마진 없음 — 지금 크레딧은 사실상 사용 한도이고, 판매가는 결제를 붙일 때 정한다 |
| 재생성 | **컷당 1회 무료**, 2·3회째는 정가(이미지 2 · 클립 8 · 목소리 1). 3회 상한은 그대로 |
| 단계별 경로 | ④이미지 시작 시점에 **같은 정가**를 한 번 받는다. 그전 단계는 LLM만 써서 편당 $0.06 |
| 이중 청구 | 자동 관통으로 이미 산 프로젝트는 단계별에서 다시 받지 않는다 |
| 기본 지급 | 자동 지급 없음. 백오피스 [크레딧 넣기]의 **기본값이 500**(고칠 수 있음) |
| 가짜 모드 | 지금처럼 전부 건너뛴다 |
| 변경 가능성 | **모든 숫자가 `lib/pricing.js` 한 곳에 있다** — 값이 바뀔 것을 전제로 설계한다 |

## 아키텍처 — 장부를 둘로 가른다

지난 설계의 "원장이 곧 차감"은 **실비용 차감**이었기에 성립했다. 정가로 가면 청구의
알갱이가 달라진다 — 청구는 **프로젝트·행위 단위**인데 `cost_records` 는 **fal 호출 단위**다.
섞으면 둘 다 거짓말이 된다. 그래서 가른다:

| 장부 | 담는 것 | 단위 | 누가 본다 |
|---|---|---|---|
| `cost_records`(기존, **무수정**) | 우리가 쓴 돈 | USD | 회계·마진 |
| `credit_charges`(신설) | 사장님이 낸 값 | 크레딧 | 잔액·청구 |
| `credit_grants`(변경) | 충전·회수 | 크레딧 | 잔액 |

**잔액 = `sum_grants(user)` − `sum_charges(user)`**. 둘 다 크레딧이라 단위가 섞이지 않는다.

같은 프로젝트를 두 장부로 나란히 보면 **마진이 그대로 보인다**(사장님 50크레딧 / 우리 $3.06).
단가가 오르면 원가만 오르고 크레딧은 그대로 — 그 격차가 곧 재가격 신호다.

### 스키마

```sql
create table if not exists credit_charges (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references auth.users(id) on delete cascade,
  project_id  uuid,
  kind        text not null,             -- "video" | "regen_image" | "regen_clip" | "regen_voice" | "refund"
  credits     numeric not null,          -- 양수=청구, 음수=환불
  idem_key    text not null unique,      -- 같은 청구를 두 번 하지 않는다
  created_at  timestamptz not null default now()
);
create index if not exists credit_charges_user on credit_charges (user_id);

create or replace function sum_charges(p_user_id uuid)
returns numeric language sql stable as $$
  select coalesce(sum(credits), 0) from credit_charges where user_id = p_user_id;
$$;
```

`credit_grants.amount_usd` → **`amount_credits`** 로 바꾸고, `sum_grants` 도 그 열을 센다.
기존 행(검증 충전 1건)은 크레딧으로 환산해 옮긴다.

`idem_key` 규약: 영상은 `video:<project_id>`, 재생성은 `regen_<kind>:<project_id>:<cut idx>:<회차>`.
**이 키가 이중 청구를 막는 유일한 방어선**이다(`cost_records.request_id` 와 같은 역할).

## 언제 얼마가 빠지나

```
빠른 생성   → POST /auto 시작 시 VIDEO_PRICE[target_seconds] 청구
단계별      → POST /images 시작 시 같은 값 청구 (video 청구가 이미 있으면 건너뜀)
재생성      → regen 3종에서 그 컷의 회차를 보고 2회째부터 REGEN_PRICE 청구
자동 관통 실패 → auto.state="failed" 로 끝나면 음수 행(kind:"refund")으로 되돌림
```

- 청구는 **유료 흐름이 시작되기 전에** 일어난다. 잔액이 모자라면 청구도 시작도 없다(402)
- 환불은 삭제가 아니라 **음수 행**이다 — 장부는 지우지 않는다
- 단계별에서 ①~③(브리핑·대본·컷 분할·목소리)은 무료다. 편당 $0.06 이라 값을 매길 이유가 없고,
  받으면 "대본만 보고 그만두는" 정상 행동에 값을 물리게 된다

## 게이트

지난 설계의 게이트 둘을 **크레딧 기준으로** 옮긴다.

1. **시작 게이트** — 잔액 < 그 행위의 정가면 **402**. 자동 관통·`/images`·regen 3종이 대상
2. **호출 게이트**(`assertBudget`) — 사용자 축을 **잔액 > 0** 판정으로 바꾼다.
   정가를 이미 받았으므로 컷 단위로 다시 잴 것이 없다. 다만 잔액이 음수인 채 fal 이 나가는
   일은 막아야 한다(청구 없이 도는 경로가 생겼을 때의 그물)
3. 전역·프로젝트 USD 상한은 **회사 안전핀으로 그대로**

`/clips` 의 "남은 컷 × 단가" 하한은 **사라진다** — 클립은 영상 정가에 포함되므로 별도 하한이
필요 없다. 그 코드는 걷어낸다.

## 화면

- **사이드바**: "크레딧 320" (편수 환산을 그만둔다 — 정가가 길이마다 다르므로 "N편"이 거짓말이 된다)
- **빠른 생성 요약 카드**: "30초 · 9:16 · 실사 · 차분한 여성 — **50 크레딧**". 모자라면 버튼 비활성 + 부족분 안내
- **단계별 ④이미지**: 시작 버튼에 정가 표기("이미지 만들기 · 50 크레딧")
- **재생성 버튼**: 첫 회는 "다시 만들기(무료)", 이후 "다시 만들기 · 8 크레딧"
- **백오피스**: 잔액(크레딧) + [크레딧 넣기] 기본값 500
- **`/costs`**: 프로젝트별로 청구(크레딧)와 원가(USD)를 나란히

## 테스트로 못 박을 것

- 길이별 정가가 **그 값만큼** 깎는다(15/30/45/60 네 값 전부)
- 컷당 **첫 재생성은 0**, 둘째부터 정가
- 자동 관통 실패 시 **되돌아온다**(음수 행이 생기고 잔액이 복구된다)
- **자동 관통으로 산 프로젝트를 `/images` 에서 다시 받지 않는다**(idem_key 로 막힌다)
- 잔액 부족 시 402 이고 **파이프라인이 안 불린다**
- 합계는 SQL 함수를 거친다(행 상한 1000을 넘겨도 맞는다)
- 가짜 모드에서는 청구도 게이트도 없다
