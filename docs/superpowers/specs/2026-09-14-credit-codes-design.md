# 크레딧 코드 — 와디즈 서포터에게 크레딧을 건넨다 (설계 · 2026-09-14)

브랜치 `feat/credit-codes`(워크트리 `.claude/worktrees/credit-codes`) — `feat/credit-unit` 의 프론트 작업과
섞이지 않게 따로 판다.

## 왜

와디즈 **후원형** 프로젝트의 리워드가 크레딧이다. 와디즈에는 서포터별 코드를 건네는 기능이 없고,
같은 후원형 선례는 *"결제 완료 시 이메일 쿠폰 발송 → 서비스에서 등록 → 즉시 이용"* 을 스토리에 적고
심사를 통과했다. 우리도 그 방식이다. 경위는 `OUTSTANDING.md` 남은 일 1.

## 사장님이 정한 것 (09-14)

| | |
|---|---|
| 코드 등록 계정 자동 승인 | **안 한다** |
| 유효기간 | **없다** |
| 메일 발송 | **메일 머지**(우리는 발송하지 않는다) — 관리자 화면에서 코드를 만들고 내려받는다 |
| 승인 대기 중 등록 | **된다(A안)** — 크레딧은 쌓이고, 쓰는 것은 승인 뒤. 운영자는 서포터를 알아보고 승인한다 |
| 리워드 구성 | 미정 — 그래서 **크레딧 양은 코드마다 자유**다 |

## 흐름

1. 종료+결제 2일 뒤 메이커 스튜디오에서 발송 정보 엑셀을 받는다.
2. 운영자가 `/admin/codes` 에 **엑셀에서 표를 복사해 붙여 넣는다**(첫 줄=머리글).
   리워드 열을 고르면 리워드 이름별로 크레딧 양을 적는 칸이 뜬다.
3. [코드 만들기] → 행마다 고유 코드 1개. 곧바로 **CSV 내려받기**(원래 열 + `코드` + `크레딧`).
4. 그 CSV 로 메일 머지를 돌린다(우리 밖).
5. 서포터가 가입 → 승인 대기 화면(또는 승인 뒤 `/me`)에서 코드를 넣는다 → 충전.
6. 운영자는 `/admin/codes` 목록에서 "등록함 · 승인 대기" 계정을 보고 승인한다.
7. 와디즈에 `직접 전달` 로 일괄 발송 처리(300건씩) — 우리 코드 밖.

### 붙여 넣기인 이유
엑셀 파서 의존성이 없다(`package.json` 에 xlsx·csv 라이브러리 0). 파일 업로드는 한국어 엑셀 CSV 가
**CP949** 라 글자가 깨지는 함정이 있다. 엑셀에서 복사한 것은 **탭으로 갈린 유니코드 텍스트**라 둘 다 피한다.
내려받는 CSV 에는 **UTF-8 BOM** 을 붙인다 — 없으면 한국어 엑셀이 열 때 깨진다.

## 데이터

새 테이블 `credit_codes` (`db/schema.sql`, 통째로 다시 올려도 안전하게):

| 열 | |
|---|---|
| `code text primary key` | 12자 · 헷갈리는 글자(0 O 1 I L) 뺀 31자 알파벳 · 보일 때 `XXXX-XXXX-XXXX` |
| `amount_credits integer not null check (> 0)` | |
| `batch text not null` | 한 번 붙여 넣은 묶음 이름(예: "와디즈 1차 09-30") |
| `meta jsonb not null default '{}'` | 붙여 넣은 원래 행 — 나중에도 CSV 를 다시 뽑는다 |
| `created_by uuid not null` · `created_at` | |
| `redeemed_by uuid null references auth.users` · `redeemed_at` | 한 번만 — 조건부 갱신이 지킨다 |

RLS 켜고 정책 0(다른 표와 같다).

**등록은 한 트랜잭션이다** — SQL 함수 `redeem_credit_code(p_code, p_user)`:
`update credit_codes set redeemed_by=…, redeemed_at=now() where code=… and redeemed_by is null returning amount_credits`
→ 한 줄이 잡혔을 때만 같은 함수 안에서 `credit_grants` 에 충전 행(사유 `크레딧 코드 XXXX-XXXX-XXXX`, `granted_by` = 등록한 본인)을 넣는다.
두 단계를 앱에서 나누면 "코드는 먹혔는데 크레딧이 없는" 반쪽 상태가 생긴다. 결과는 `ok` / `used` / `not_found` 셋.
메모리 저장소도 같은 세 결과를 낸다.

잔액 계산은 **그대로다** — 충전 장부에 한 줄이 늘 뿐이다.

## 코드 모양 · 추측 방어

31자 알파벳 12자 = 약 8×10¹⁷ 가지. 코드 1만 개를 뿌려도 한 번 추측이 맞을 확률이 10⁻¹³ 이라
**시도 횟수 제한은 두지 않는다**(서버리스라 셀 곳도 없다 — 만들면 DB 쓰기가 는다). 생성은 `crypto.randomInt`.
입력은 대소문자·하이픈·공백을 무시하고 정규화한다.

## 라우트

| | 누가 | 무엇 |
|---|---|---|
| `POST /api/admin/codes` | 운영자 | `{ batch, rows: [{ credits, meta }] }` → 만든 코드들. 한 번에 최대 2,000행 · credits 는 양의 정수 |
| `GET /api/admin/codes` | 운영자 | 전체 목록 + 등록한 계정의 이메일·이름·승인 상태 |
| `DELETE /api/admin/codes/[code]` | 운영자 | **안 쓴 코드만** 지운다(잘못 만든 것). 쓴 코드는 409 |
| `POST /api/credits/redeem` | 로그인한 본인 · **승인 대기 포함** · 차단 제외 | `{ code }` → `{ credits, balance }` · 없음 404 · 이미 씀 409 |

승인 대기를 들이려고 `withUser` 에 옵션 `pending: true` 를 더한다 — `status === "pending"` 만 통과,
`blocked` 는 여전히 403. 이 라우트 하나만 쓴다.

## 화면

- **`/admin/codes`**(새 페이지 — `app/admin/page.js` 는 안 건드린다): 붙여 넣기 → 리워드 열 선택 →
  리워드별 크레딧 → 묶음 이름 → [코드 만들기] → [CSV 내려받기]. 아래에 목록(묶음·코드·크레딧·등록 계정·상태) ·
  묶음별 CSV 다시 받기 · 안 쓴 코드 지우기 · 승인 대기 계정은 [승인] 버튼(기존 승인 라우트를 부른다).
- **`/pending`**: 기존 문구 아래 코드 입력칸 — 성공하면 "N 크레딧이 들어왔어요. 승인되면 바로 쓰실 수 있어요."
- **`/me`**: 크레딧 내역 절의 잔액 줄 아래 같은 입력칸(컴포넌트 하나를 둘이 쓴다).
  ⚠️ `/me` 는 `feat/credit-unit` 에서 프론트 작업 중일 수 있다 — 고치는 줄을 **입력칸 한 줄 삽입**으로 줄인다.
- 관리자 사용자 목록의 "코드 등록함" 표시는 **넣지 않는다** — `app/admin/page.js` 충돌을 피하고, 같은 정보를
  `/admin/codes` 목록이 준다.

## 안 하는 것

메일 발송 · 유효기간 · 자동 승인 · 코드 부분 사용 · 엑셀 파일 파싱 · 시도 횟수 제한.
