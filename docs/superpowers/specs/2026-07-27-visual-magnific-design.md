# 시각 개편 — Magnific 규칙 이식 (다크 단일)

작성: 2026-07-27
상태: 설계 확정, 구현 전
관련: [UX/UI 3분할 중 C(시각) 축]

---

## 1. 왜 하는가

"개발자 툴처럼 보인다"는 문제의 원인을 실측했다. **방향을 잘못 고른 게 아니라, 고른 방향을 안 지킨 것**이었다.

`app/globals.css` 첫 줄에 이미 `dropshot aistudio 다크 시스템 기반`이라고 적혀 있고, 토큰 값도 실제 dropshot 사이트에서 읽은 값과 같다. 그런데 최근 화면들이 그 시스템에서 이탈했다.

### 실측한 이탈 (재조사 불필요)

| 항목 | 현재 | 문제 |
|---|---|---|
| 모서리 | 10종 (`4·5·6·7·8·9·10·12·14·999`) | 같은 위계의 요소가 서로 달라 보임 |
| 굵기 | `400·600·700·800` | 위계를 굵기로 만들어 화면이 시끄러움 |
| 글자 크기 | 14종 (`9` ~ `24`, 소수점 포함) | 9~11px은 사장님이 읽기에 작음 |
| 액센트 퍼플 | 15곳 | 정작 크레딧 상자가 묻힘 |
| 하드코딩 색 | `#B9A0FF`(10회) · `#8A5CFF` · `#5527E0` · `#3D1DAD` | 토큰 밖의 색 |
| 그라디언트 | 3곳 (벨트·로고·챗 아바타) | 레퍼런스 6곳 중 쓰는 곳이 없음 |
| 인라인 스타일 | 38곳 | 아래 분포 참조 |
| 웹폰트 | **로드 안 됨** | `font-family`에 Pretendard가 적혀 있으나 `@font-face`도 `next/font`도 없다. 실제로는 시스템 대체 서체로 보이는 중 |

인라인 스타일 분포:
`synopsis 12` · `script 10` · `briefing 5` · `create 4` · `images 3` · `home 2` · `SoonStep 2`

### 레퍼런스 조사 결과

AI 영상 서비스 6곳(dropshot · Krea · Runway · Luma · Higgsfield · Magnific)을 실제로 열어 값을 읽었다. **여섯 곳이 전부 지키는 규칙이 있었고, 우리는 그중 5개를 어기고 있다.**

가장 확실한 것: **주 실행 버튼에 브랜드 색을 쓰는 곳이 한 곳도 없다.** 바탕이 어두우면 흰 버튼, 밝으면 검정 버튼. 브랜드 색(dropshot 퍼플 · Higgsfield 라임 · Magnific 핑크)은 전부 가입·구독 자리에만 붙고 본문 UI에서는 사라진다.

## 2. 무엇을 하는가

**Magnific(구 Freepik)의 값과 규칙을 가져와 다크 한 벌로 정리한다.**

Magnific은 한 페이지 안에서 다크와 라이트를 번갈아 쓰지만, **그 부분은 가져오지 않는다.** 화면마다 바탕이 바뀌면 단계를 넘어갈 때 다른 앱처럼 보인다는 판단(사용자 결정). 앱 전체가 검정 한 벌이다.

## 3. 토큰

### 3.1 색 — 전량 교체

```css
:root {
  /* 바탕 — 지금 #15191E는 푸른 기가 돈다. Magnific은 완전한 중성 회색 */
  --bg:        #1A1A1A;   /* was #15191E */
  --surface:   #232323;   /* was #1F242A */
  --surface2:  #2E2E2E;   /* was #2A2F36 */
  --deep:      #101010;   /* was #0A0D0F */
  --line:      #3A3A3A;   /* was #393E46 */

  /* 글자 */
  --ink:       #F5F5F5;   /* was #F0F3F6 */
  --ink-soft:  #A0A0A0;   /* was #9CA3AF */

  /* 액센트 — 크레딧·결제 자리에만 */
  --accent:      #FF58AE;                  /* was #6633FF */
  --accent-soft: rgba(255, 88, 174, 0.10); /* was rgba(102,51,255,.16) */

  /* 주 실행 버튼 — 바탕의 반대색 (신규) */
  --btn:     #F5F5F5;
  --btn-ink: #1A1A1A;

  /* 상태 — 유지 */
  --good: #57B383;  --good-soft: rgba(87, 179, 131, 0.14);
  --warn: #DFAF54;  --warn-soft: rgba(223, 175, 84, 0.14);
}
```

**제거 대상 (토큰 밖 하드코딩):** `#B9A0FF` · `#8A5CFF` · `#5527E0` · `#3D1DAD` · `linear-gradient` 전부

`--accent-soft`의 알파를 `.16` → `.10`으로 낮춘다. 핑크가 퍼플보다 명도·채도가 높아 같은 알파에서 더 튄다.

### 3.2 형태

```css
--r-card: 16px;   /* 패널 · 카드 · 큰 입력 */
--r-ctl:   8px;   /* 버튼 · 작은 입력 · 배지 */
--r-pill: 999px;  /* 칩 · 태그 */
```

이 세 값 외의 `border-radius`는 쓰지 않는다.

### 3.3 서체

**두 벌을 실제로 로드한다.** 지금은 이름만 적혀 있고 로드되지 않는다.

- **라틴 · 숫자: Geist** — Vercel 오픈소스. `npm i geist` 후 `next/font`로 주입. 우리 스택(Next 15)에서 추가 설정 없이 동작한다.
- **한글: Pretendard** — `next/font/local`로 셀프호스팅. CDN 링크를 쓰지 않는다(빌드 재현성).

`font-family` 순서는 `Geist, Pretendard, system-ui, sans-serif`. Geist에 한글 글리프가 없어 한글은 자동으로 Pretendard가 받는다.

**크기 5단:** `12 · 14 · 15 · 16 · 24`
본문 기준이 `14px` → **`15px`**로 올라간다(Magnific 실측 기준값, 387회로 지배적).
`h1.pgtitle`은 `20px` → `24px`.

**굵기 3단:** `400` 본문 / `500` UI 강조 · 버튼 / `800` 제목
`600` · `700`은 쓰지 않는다. 제목의 `800`에는 `letter-spacing: -0.02em`을 함께 준다.

## 4. 규칙

구현 중 판단이 갈리면 이 순서로 결정한다.

1. **주 실행 버튼은 `--btn` 바탕에 `--btn-ink` 글씨.** 한 화면에 하나만. 크레딧이 드는 동작이면 버튼 안에 `✦ N`을 넣는다.
2. **핑크는 크레딧 상자와 결제 자리에만.** 배지·태그·선택 상태·링크·포커스링·호버는 전부 무채색(`--surface2` / `--ink-soft` / `--line`).
3. **위계는 굵기가 아니라 밝기로.** 강조는 `--ink`, 보조는 `--ink-soft`.
4. **UI는 물러난다.** 화면에서 가장 밝고 채도 높은 것은 항상 생성된 이미지·영상이어야 한다.
5. **그라디언트를 쓰지 않는다.**
6. **모서리·크기·굵기는 §3의 값만.**

## 5. 적용 범위

| 대상 | 할 일 |
|---|---|
| `app/globals.css` (626줄) | 토큰 교체, 모서리·크기·굵기 정리, 하드코딩 색 제거, `.cta`를 흰 버튼으로 |
| `app/layout.js` | 벨트 그라디언트 → `--surface` 단색, `next/font` 주입 |
| `components/Sidebar.jsx` | 로고 아이콘 그라디언트 제거 |
| 인라인 38곳 | 클래스로 회수. 일회성이 아닌 것은 `globals.css`에 클래스를 만든다 |
| `package.json` | `geist` 추가, Pretendard 폰트 파일 추가 |

### 하지 않는 것

- **밝은 면 / 종이 시트** — 다크 한 벌로 간다
- **3열 레이아웃 재배치** — 화면 구조는 건드리지 않는다
- **상태 표현 컴포넌트 신설** — UX 3분할 중 A(상태) 축. 별도 스펙
- **흐름 개선**(유료 호출 예고 흐름, `contentEditable` 대체, 되돌리기) — B(흐름) 축. 별도 스펙
- **스토리보드 카드 재설계** — 라이브 출력을 보고 디자인해야 한다. 크레딧 복구 후로 분리

버튼 안 크레딧 표기(`✦ N`)는 **시각 층에서만** 한다. 실제 비용 계산·예고 흐름은 B축이다. 지금은 이미 알고 있는 값을 버튼에 표시하는 것까지.

## 6. 검증

### 6.1 자동

- `npm test` (vitest) — **전량 그린 유지가 조건.** 시각 변경이 로직 테스트를 깨면 안 된다. 깨졌다면 CSS가 아니라 마크업을 잘못 건드린 것이다.
- 금지 값 잔존 확인 — 아래 grep이 **0건**이어야 한다.
  ```
  grep -rn '#B9A0FF\|#8A5CFF\|#5527E0\|#3D1DAD\|#6633FF\|linear-gradient' app components
  ```
- 모서리 확인 — `border-radius` 값이 `16px` · `8px` · `999px` · `50%`(원형 아바타) 외에 없어야 한다.
- 인라인 잔존 — `grep -rc 'style={{' app components` 합계가 **38 → 10 이하**.
  (0을 목표로 하지 않는다. 계산된 값·조건부 표시처럼 클래스로 뺄 수 없는 것이 남는다.)

### 6.2 눈으로

시각 변경은 자동 테스트로 잡히지 않는다. `npm run dev` 후 **7개 화면을 전부 연다.**

- [ ] 홈(챗) — 내 말풍선이 퍼플에서 무채색으로 내려갔는가
- [ ] ①자료 · ②기획 · ③구성 · ④대본 — 주 버튼이 화면에서 유일하게 가장 밝은가
- [ ] ⑥이미지 — 생성된 사진이 UI보다 밝고 선명한가 (규칙 4)
- [ ] 비용 기록 — 표의 배지가 읽히는가
- [ ] 사이드바 — **핑크가 크레딧 상자에만 있는가**
- [ ] 실패 상태 — 에러 문구의 `--warn`이 핑크와 헷갈리지 않는가

마지막 항목이 이 방향의 유일한 위험이다. 핑크(`#FF58AE`)와 경고 노랑(`#DFAF54`)은 색상환에서 멀어 부딪히지 않을 것으로 보지만, **실패 화면에서 직접 확인한다.** 헷갈리면 `--warn`을 더 붉은 쪽이 아니라 더 노란 쪽(`#E5B93C`)으로 옮긴다.

## 7. 남는 위험

- **서체 인상은 적용 후에야 보인다.** Geist의 좁고 반듯한 인상이 이 방향의 큰 부분인데, 지금까지 본 시안은 전부 시스템 대체 서체로 렌더된 것이다. 적용 후 인상이 기대와 다르면 서체만 되돌릴 수 있게, 폰트 주입을 `layout.js` 한 곳에 모은다.
- **본문 15px 상향으로 세로가 길어진다.** 대본·구성 화면에서 스크롤이 늘어난다. 화면당 한 번 확인한다.
