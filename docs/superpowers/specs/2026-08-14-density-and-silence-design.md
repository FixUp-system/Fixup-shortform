# 말의 밀도와 여백 — 15초를 말로 채우지 않는다

> 2026-08-14 · 대상: `lib/script.js` · `lib/cuts.js` · `lib/subtitles.js` · `lib/compose.js` ·
> `lib/clip-limits.js` · `lib/steps.js` · ③목소리·②대본 화면
>
> **광고 경로(`lib/ad/*`)는 이번 범위가 아니다** — 거기서 배우되 거기를 고치지 않는다.

## 무엇을 바꾸나

지금 분할생성은 **영상 길이가 원고 길이의 결과값**이다. 사장님이 15초를 골라도 그 값은
fal 에 가지 않고 "원고를 83자로 써라"는 목표로만 번역된다. 원고가 63자로 나오면 영상이
11초가 된다.

앞으로는 **고른 초가 주문값**이 되고, 원고는 그 시간을 **다 채우지 않는다.**

## 근거는 실측이다 (2026-08-14)

### ① 짧게 나온 것이 결함으로 잡히지 않았다

저장된 문서에 판정 코드를 그대로 돌린 결과:

| 프로젝트 | 원고 | 목표 | 비율 | 결함 | 결과 |
|---|---|---|---|---|---|
| `5d8a9a1e` | 63자 | 83자 | 76% | 없음 | 11초 |
| `c2abe051` | 64자 | 83자 | 77% | 없음 | 완성본 11초 |
| 측정(`shallow` 자료) | 50자 | 83자 | 60% | 없음 | **9.1초** |

`underTarget` 이 "자료에 안 쓴 사실이 없으면 짧아도 봐준다"였기 때문이다.

### ② 광고는 15초를 말로 채우지 않는다

저장된 광고 3편의 시나리오(`doc.scenario.shots`)를 전수 확인했다.

| 프로젝트 | 주문 | 장면 | 무음 장면 | 대사 총량 | **밀도** |
|---|---|---|---|---|---|
| `57b5b5c2` | 15초 | 4개 | 1개 | 36자 ≈ 6.5초 | 43% |
| `a130db84` | 15초 | 4개 | 0개 | 39자 ≈ 7.1초 | 47% |
| `d092fc45` | 15초 | 4개 | 1개 | 31자 ≈ 5.6초 | 37% |
| | | 12개 | **2개(17%)** | | **평균 42%** |

★ **무음 장면은 17%뿐이다.** 진짜 차이는 **말하는 장면에서도 대사가 장면을 다 안 채우는
것**이다 — 4초 장면에 `"하루의 끝, 지친 피부에게."`(12자 = 2.2초)를 싣고 나머지 1.8초는
펌프 클릭음과 피아노가 채운다.

분할생성은 컷 길이 = 그 문장의 낭독 시간이므로 **정의상 밀도 100%** 다. 쉬는 자리가
구조적으로 없다. 사용자가 지적한 *"그냥 정보를 읽는 느낌"* 의 뿌리가 여기다.

## 구조

### 1. 밀도 계수 — 원고 목표를 낮춘다

`lib/script.js` 의 `targetChars` 에 계수를 곱한다.

```
지금:  15초 × 5.5자        = 83자
새로:  15초 × 5.5자 × 0.45 = 37자
```

- `SPEECH_DENSITY = 0.45` 를 `lib/script.js` 에 **한 자리로** 둔다(값이 두 벌이면 갈린다)
- ⚠️ **표본이 광고 3편뿐이다.** 이 저장소 규율("임계는 실측 분포에서 뽑는다")에 비추면
  얇다. 실측 범위가 37~47% 라 평균 45% 로 시작하되, **분할생성 실측이 쌓이면 다시 뽑는다.**
  값을 바꾸는 곳이 한 자리이므로 다시 뽑는 비용은 작다

★ **`underTarget` 은 그대로 필요하다.** 목표가 낮아졌을 뿐 "목표에 못 미치면 잡는다"는
살아 있어야 한다.

⚠️ **2026-08-14 오전의 미커밋 변경을 어떻게 할지 — 명시한다.** 그날 `underTarget` 에서
재료 검사(`unusedFacts`)를 걷어내 글자 수만 보게 했고, 측정에서 60%→95% 를 얻었다.
그러나 **그 값은 목표가 83자였을 때의 것**이고 이 설계는 목표를 37자로 내린다.

| 그날의 변경 | 이 설계에서 |
|---|---|
| `underTarget` 재료 검사 제거 | **되돌린다** — 목표가 37자면 얕은 자료도 대개 닿는다. 지어내기 위험(이 저장소가 실측한 실패)을 다시 질 이유가 없다 |
| 되돌리기 지문의 `[더 깊이 갈 자리]` 블록 | **유지한다** — 판정과 무관하게 "채울 재료가 없을 때 무엇을 하라"는 지시는 옳고, 해가 없다 |
| `REWRITE_SYSTEM` 에서 "그럴 바에는 짧은 채로 둔다" 삭제 | **되돌린다** — 목표가 낮아지면 그 문장이 다시 안전판이 된다 |
| 대본 화면 문구 정리 · 화면 설명 기본 펼침 | **유지한다** — 이 설계와 무관한 별건이다 |
| `scripts/measure/run-pipeline.mjs` 의 `shallow` 자료 | **유지한다** — 이 설계의 측정 자료가 바로 그것이다 |

### 2. 컷 길이가 낭독에서 분리된다

지금은 컷 초가 문장에서 나온다(`lib/cuts.js` 의 `secondsForText`). 앞으로는:

1. 컷 분할은 지금 그대로 — **원고를 잘라서** 컷을 만든다(구조적 보장 유지)
2. 컷마다 **최소 초 = 낭독 추정**(말이 잘리면 안 된다)
3. **고른 초에서 낭독 합계를 뺀 나머지**를 컷에 배분한다 — 그것이 여백이다
4. 배분된 값이 그 컷의 주문 초가 된다(모델 상한 3~15초 안에서)

★ **Seedance 경로는 절반이 이미 되어 있다.** `cutSeconds`(`lib/subtitles.js:31`)가 소리
파일이 없는 컷에서 **받은 클립 길이**를 쓰고, 합성도 그 컷을 자르지 않는다. 즉 긴 클립을
주문하기만 하면 여백이 그대로 남는다.

⚠️⚠️ **Kling+TTS 경로는 반드시 함께 고친다 — 선택이 아니다.**

그 경로는 컷 초 = 낭독이고 합성이 클립을 낭독 길이로 자른다(`lib/compose.js` 의 `fit`).
따라서 총 길이 = 낭독 합 = **원고 길이**다. 밀도 계수만 넣고 이 경로를 그대로 두면
원고가 83자에서 37자로 줄어드는 만큼 **영상이 15초에서 7초가 된다** — 고치려던 결함이
같은 경로에서 두 배로 나빠진다.

→ 낭독보다 긴 컷 초를 받으면 자르지 말고 `tpad` 로 늘린다(그 코드는 이미 있다 —
지금은 클립이 낭독보다 **짧을 때만** 쓴다). 즉 `fit` 의 판정을 "낭독에 맞춘다"에서
"**컷에 배분된 초에 맞춘다**"로 옮긴다.

★ 여백의 질은 두 경로가 다르다. Seedance 는 모델이 그 시간을 연기로 채우고, Kling 은
마지막 프레임이 멈춰 선다(`tpad=stop_mode=clone`). 후자가 밋밋하면 켄번즈(로컬 ffmpeg,
0원)가 그 자리의 후보다 — 이번 범위는 아니다.

### 3. 자막이 정적 구간까지 떠 있으면 안 된다 ← 새로 생기는 문제

`buildCues` 는 컷의 자막 span 을 `cutSeconds(c)` 로 잡는다. 컷이 5초인데 대사가 2.2초면
**자막이 2.8초 동안 말 없이 떠 있는다.** 지금은 컷 초 = 낭독 초라 이 문제가 없었다.

→ 자막 span 을 **컷 초가 아니라 말하는 길이**로 잡는다. 여백에는 자막이 없다.

★ 이것이 밀도 변경의 **가장 눈에 띄는 부작용**이다. 놓치면 "자막이 안 사라진다"로 보인다.

### 4. 무음 컷 — 말하지 않기로 한 컷

광고 실측 17% 에 해당하는 자리. 오프닝 훅과 엔딩 여운이 주 용도다.

- 컷에 `silent: true` 를 둔다. **`sentence` 가 빈 것으로 판정하지 않는다** — 다음 항목 참조
- 무음 컷은 원고에서 나오지 않는다(원고에 없는 시간이다). 그래서 **구조적 보장은 유지된다**:
  "컷의 문장을 이어붙이면 원고와 글자 그대로 같다" 는 무음 컷이 문장을 안 가지므로 그대로다
- 자막 없음, 낭독 없음, 이미지·클립은 그대로 만든다

### 5. `projectSpeaks` 를 다시 짠다 ← 이것이 없으면 4번이 작동하지 않는다

지금 판정(`lib/clip-limits.js`):

```js
return cuts.every((cut) =>
  typeof cut?.sentence === "string" && cut.sentence.trim() !== "" &&
  cast.some((p) => p.cuts.includes(cut.idx))
);
```

**모든 컷에 문장이 있어야 말하는 프로젝트다.** 무음 컷을 넣는 순간 모든 Seedance
프로젝트가 `false` 로 떨어져 **통째로 TTS 경로로 간다** — 무음 컷 하나 때문에 나머지 컷의
목소리까지 우리 TTS 가 되고, 목소리 일관성 게이트가 무의미해진다.

→ **"말할 사람이 없는 컷"과 "말하지 않기로 한 컷"을 가른다.**

| 컷 | 지금 | 앞으로 |
|---|---|---|
| 문장 있음 + 캐스팅 있음 | 정상 | 정상 |
| 문장 있음 + 캐스팅 **없음** | 전체 TTS 로 | **그대로 전체 TTS 로**(사고다 — 말할 사람이 없다) |
| `silent: true` | (존재하지 않음) | **건너뛴다 — speaks 판정에서 제외** |

즉 판정을 `cuts.filter(c => !c.silent).every(...)` 로 좁히고, 무음 컷이 **하나도 없는
프로젝트**의 동작은 지금과 글자 그대로 같게 둔다(회귀 없음).

### 6. Seedance 에서 ③목소리 단계를 숨긴다

지금 그 화면은 아무것도 안 산다 — "목소리는 영상이 함께 만들어요 → 이미지 만들러 가기"
버튼 하나다. 사장님에게는 **눌러야 할 것 같은 죽은 단계**다.

- `lib/steps.js` 의 단계 표가 프로젝트를 받아 목록을 낸다(지금은 상수 배열)
- 스테퍼·라우팅 가드·`currentStepKey` 가 **같은 표**를 계속 본다(두 벌이 되면 갈린다)
- ⚠️ `currentStepKey` 의 `status === "cuts" → "voice"` 를 함께 고쳐야 한다. 안 고치면
  숨긴 단계로 보내 놓고 가드가 되돌린다(2026-08-13 에 겪은 "화면이 여는 문과 가드가
  닫는 문이 갈린다" 와 같은 결함이다)
- 사장님이 고른 목소리(`voice_label`)는 버리지 않는다 — 캐스팅에 힌트로 넘기는 자리는
  이미 설계돼 있다

## 값

- 클립이 실제로 15초가 되므로 **원가가 오른다**: Seedance 15초 기준 $3.33 → $4.54
- 정가는 안 바뀐다(`lib/pricing.js` 손대지 않는다) — 사장님은 이미 15초 값을 냈다
- ⚠️ 크레딧에 마진이 없으므로 **장부상 손실이 커지는 방향**이다. 결제를 붙일 때 판매가에
  반영할 사실로 남긴다
- TTS 는 Seedance 경로에서 원래 안 만든다(변화 없음)

## 구현 순서

값이 흐르는 차례대로 간다. **앞 단계만으로도 영상이 깨지지 않아야** 중간에 멈출 수 있다.

1. **밀도 계수 + 컷 초 배분** (`lib/script.js` · `lib/cuts.js`) — 여기까지만 하면 Seedance 는
   길이가 맞고 Kling 은 짧아진다. 그래서 2번과 **한 묶음으로 끝내야 한다**
2. **Kling+TTS 경로의 `fit` 을 배분된 초 기준으로** (`lib/compose.js`) — 두 모델의 길이가 같아진다
3. **자막 span 을 말하는 길이로** (`lib/subtitles.js`) — 여백에 자막이 안 뜬다
4. ← 여기서 한 번 측정한다(밀도·길이·자막). 무음 컷 없이도 값이 나온다
5. **`projectSpeaks` 재설계** (`lib/clip-limits.js`) — 무음 컷이 판정에서 빠지게. **4번보다
   먼저 하면 안 되는 것이 아니라, 6번보다 먼저 해야 한다**
6. **무음 컷 도입** (`lib/cuts.js` 분할 · 화면)
7. **③목소리 단계 숨기기** (`lib/steps.js`) — 나머지와 독립이라 언제 해도 된다

★ **1~3 이 한 덩어리다.** 하나만 넣고 멈추면 어느 한 모델의 길이가 깨진 채 남는다.

## 측정 (구현 뒤에 반드시)

`scripts/measure/run-pipeline.mjs` 의 `shallow` 자료(실제로 11초를 만든 그 자료)로 잰다.

| 재는 것 | 지금 | 목표 |
|---|---|---|
| 완성본 길이 / 고른 초 | 60~77% | **95~105%** |
| 원고 밀도(대사 초 / 완성본 초) | 100% | **40~50%** |
| 무음 컷 비율 | 0% | 광고 실측 17% 근처 |
| 지어낸 사실(숫자·실적·수상) | 0건 | **0건 유지** |
| 자막이 무음 구간에 뜨는가 | 해당 없음 | **0건** |

★ 표본 1회로 결론 내지 않는다 — 같은 자료로 3회 이상.

## 지켜야 할 것

- **컷 분할·컷별 재생성·편집을 깨지 않는다** — 이것이 이 제품의 장점이고 한 번에 생성하지
  않는 이유다(사용자 결정 2026-08-14)
- **"컷의 문장을 이어붙이면 원고와 같다"** 는 구조적 보장을 유지한다
- 광고 경로(`lib/ad/*`)를 건드리지 않는다 — 사용자가 지금 품질에 만족하고 있다
- `lib/pricing.js` 의 정가표를 바꾸지 않는다
- 무음 컷이 없는 프로젝트의 동작은 **지금과 글자 그대로 같아야 한다**
- 측정 없이 품질을 주장하지 않는다

## 이번에 안 하는 것

- 사장님이 컷 길이를 직접 조절하는 UI — 구조만 열어 두고 필요해지면 그때
- 컷별 `sound`(음향·정적 설계) 축 — 광고에는 있고 분할생성에는 없다. 직교하는 축이라
  나중에 얹을 수 있다
- 밀도를 사장님이 고르게 하는 것("차분히 / 꾸밈없이") — 이 저장소는 그런 선택을 걷어낸
  전력이 있다(초점·연출 바람)
- 목소리 일관성 정지 게이트 — 별건으로 남아 있다
