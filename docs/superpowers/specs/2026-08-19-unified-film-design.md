# 한 번에 굽는 영상 — 두 방식을 나란히 놓고 재는 설계

2026-08-19

## 한 줄

컷마다 클립을 사서 이어붙이는 대신, **컷별 이미지를 먼저 만들어 눈으로 확인하고 한 편을 통째로 굽는다.** 이미지를 모델에게 무엇이라고 말해 줄지를 **두 방식으로 갈라** 같은 조건에서 잰다.

## 왜

사장님이 꼽은 것 셋이다: **컷 사이 이음새 · 목소리 일관성 · 제품과 인물의 일관성.**

앞의 둘은 **이어붙이지 않는 것만으로** 사라진다. 지금은 컷마다 클립을 따로 사서 잇기 때문에 경계가 튀고(2026-08-19 실측: 컷 0이 전신 샷으로 시작해 가방 클로즈업으로 끝나고 컷 1이 다시 손바닥 샷으로 시작), 낭독도 컷마다 따로 만들어 톤이 갈린다.

셋째는 **이미지를 참조로 주는 것**이 푼다. 말로 그리면 틀린다는 것을 이미 값을 치르고 배웠다 — 참조 사진은 라벤더 토끼인데 프롬프트가 "cream-white … pastel pink ribbon" 을 시켜 크림색 토끼가 나왔다(2026-08-19). **그림으로 주면 그 사고가 구조적으로 안 난다.**

여기에 통짜 경로에 없던 이점이 하나 더 붙는다: 광고는 $3.63 을 치르기 전까지 무엇이 나올지 모르는데, 이 경로는 **이미지($0.08)로 먼저 보고 마음에 들 때만 굽는다.**

## 성립 조건은 아니다 — 두 방식으로 가르는 이유

`r2v`(reference-to-video)가 이미지 여러 장을 **순서대로 장면으로** 쓰는지는 아무도 확인한 적이 없다. 이 엔드포인트는 원래 "이 참조물들의 생김새를 지켜라"를 위한 것이지 스토리보드용이 아니다.

**다만 그것이 안 되어도 이 경로는 성립한다.** 위 목적 셋 중 어느 것도 순서에 의존하지 않는다:

| 목적 | 무엇이 해결하는가 | 순서가 필요한가 |
|---|---|---|
| 컷 사이 이음새 | 통짜로 굽는 것 자체 | 아니오 |
| 목소리 일관성 | 통짜로 굽는 것 자체 | 아니오 |
| 제품·인물 일관성 | 이미지를 참조로 주는 것 | 아니오 |

그래서 "될까 안 될까"를 미리 판정하지 않고 **두 방식을 다 만들어 사장님이 직접 잰다.**

## 두 방식

### A. 장면 순서 (`/film/order`)

- 이미지: **장면마다 한 장**(시나리오 `shots` 수만큼)
- 프롬프트: 첨부한 그림들이 **차례로 장면**이라고 말한다
- 기대: 스토리보드대로 흘러간다
- 위험: `r2v` 가 순서를 안 보면 그림이 뒤섞이거나 무시된다

### B. 참고 그림 (`/film/refs`)

- 이미지: **축마다 한 장** — 제품 · 인물 · 배경 셋 고정(장면 수와 무관)
- 프롬프트: 첨부한 그림은 **생김새 참조**이고 장면 순서는 글이 정한다고 말한다
- 기대: 제품·인물이 흔들리지 않는다
- 위험: 장면 구성이 전부 글에 달려 있어 통제가 약하다

## 흐름 (둘 다 같다)

```
자료 입력 → 시나리오 → 이미지 생성(눈으로 확인) → 한 번에 굽기 → 자막
```

### 새로 만들 것이 거의 없다

| 단계 | 쓰는 것 |
|---|---|
| 시나리오 | `lib/ad/scenario.js` — 이미 `shots[{beat,camera,lighting,action,sound,line,seconds}]` 를 낸다 |
| 이미지 | `lib/imagegen.js` 의 `generateImage({ prompt, aspect_ratio, refs, projectId })` |
| 굽기 | `lib/ad/generate.js` 의 `submitAdVideo`·`collectAdVideo` — 이미 `kind === "r2v"` 에서 `image_urls` 배열을 싣는다 |
| 자막 | `lib/ad/subtitles.js` + `lib/compose.js` 의 `burnSubtitles` |
| 접수/수거 | `lib/ad/pipeline.js` 의 `startAdRender`·`collectAdRender` 모양 |

**하는 일은 이어 붙이는 것이다.** 새 모듈은 `lib/film/` 하나이고, 그 안에서 두 방식이 갈린다.

## 갈리는 곳은 정확히 두 군데

`lib/film/mode.js` 하나가 두 방식의 차이를 전부 쥔다.

1. **어떤 이미지를 만드는가** — `imagePlanFor(mode, scenario)`
   - `order`: 장면마다 한 장, 프롬프트는 그 장면의 `beat`·`camera`·`lighting`·`action` 에서 나온다
   - `refs`: 축 셋(제품·인물·배경), 프롬프트는 시나리오 전체에서 뽑는다
2. **프롬프트가 그 그림들을 뭐라고 부르는가** — `attachClauseFor(mode)`
   - `order`: 차례로 장면이다
   - `refs`: 생김새 참조다, 장면은 글이 정한다

★ 두 곳을 한 파일에 모으는 이유: 나중에 한 방식이 이기면 **지울 자리가 한 곳**이다. 흩어 두면 어느 쪽 코드인지 구별이 안 된다.

## A/B 가 성립하게 — 같은 시나리오·같은 이미지로 두 번 굽는다

각 섹션에서 따로 만들면 시나리오가 매번 달라져(LLM) **결과 차이가 방식 때문인지 시나리오 때문인지 알 수 없다.**

그래서 **한 프로젝트가 두 방식으로 각각 구울 수 있다.** 화면에 [다른 방식으로 굽기]를 둔다.

- 시나리오는 하나다
- 이미지는 방식마다 다르다(A는 장면별, B는 축별) — 그래서 문서가 **방식별로** 이미지를 들고 있어야 한다
- 굽기 결과도 방식별로 남는다 → 두 영상을 나란히 볼 수 있다

### 문서 모양

```
kind: "film"
mode: "order" | "refs"            ← 마지막으로 고른 방식(화면 초기값)
scenario: { text, shots[], ... }   ← 하나뿐이다. 두 방식이 공유한다
films: {
  order: { images: [{url, of}], video: {url, seconds, rawUrl, subtitled}, status, error },
  refs:  { images: [...],       video: {...},                            status, error }
}
```

★ `films` 를 방식별로 가르는 이유: 한 자리에 덮어쓰면 비교할 대상이 사라진다. **비교가 이 기능의 목적**이므로 두 벌을 남기는 것이 설계의 핵심이다.

## 화면

사이드바에 둘을 나란히 둔다 — **라벨 자체가 실험 조건을 말한다.**

- **장면 순서** → `/film/order`
- **참고 그림** → `/film/refs`

각 화면의 단계는 광고와 같은 결이다: ①입력 → ②시나리오 → ③이미지 → ④완성.
③에서 이미지를 확인하고 [이 그림들로 굽기]를 누른다. ④에 [다른 방식으로 굽기]가 있다.

★ 보관함 카드는 `kind` 로 갈라 그린다(지금 `p.kind === "ad"` 하나뿐이다) — `"film"` 을 더한다.
★ `lib/projects.js` 의 `KINDS` 에 `"film"` 을 더한다. 안 더하면 `createProject` 가 던진다.

## 값

한 번 비교에 **약 $4.6**:

| | 값 |
|---|---|
| 이미지 (A: 장면 3~4장 / B: 축 3장) | $0.24 ~ $0.32 |
| 굽기 15초 480p × 2회 | 약 $4.04 |

★ 길이는 **15초로 시작한다.** 2.0 이 15초까지이고 30초는 2.5 가 필요한데 초당 단가가 더 비싸다(0.3034 → 0.4622, 720p 기준). 방식을 재는 자리에서 굳이 비싼 쪽을 쓸 이유가 없다.
★ 해상도도 **480p 로 시작한다.** 방식의 차이(순서를 지키는가·제품이 유지되는가)는 480p 로도 보인다.

## 테스트

- `lib/film/mode.js` 가 방식마다 다른 이미지 계획과 다른 부착 문구를 낸다
- 모르는 방식은 **던진다** — 조용히 한쪽으로 떨어지면 사장님은 A 를 골랐는데 B 가 구워진다
- `films.order` 를 구워도 `films.refs` 가 그대로 남는다(비교 대상이 사라지지 않는다)
- 굽기 앞에서 **이미지가 없으면 막는다** — 참조 없이 `r2v` 로 나가면 이 경로의 뜻이 사라지는데 값은 그대로 든다
- 유료 호출 없음(전부 주입·가짜)

## 범위 밖

- **30초 이상·1분 이상** — Seedance 는 최대 30초다. 1~3분은 통짜로 만들 방법이 아예 없고, 그때는 이어붙이기가 다시 필요하다. 이 설계는 거기까지 답하지 않는다
- **자막 타이밍** — 광고와 같은 한계를 그대로 물려받는다(낭독 실측이 없어 시나리오가 적은 초로 깐다). 사장님이 "모델이 말하게 둔다"를 골랐으므로 감수하는 대가다
- **기존 두 경로는 손대지 않는다** — 실패해도 지금 쓰는 흐름이 다치지 않는 것이 이 설계의 안전장치다

## 미검증

- **`r2v` 가 순서를 보는가** — 이 문서가 답하지 않는다. 두 방식을 만들어 사장님이 재는 것이 답이다
- **모델이 지정한 대사를 그대로 읽는가** — 광고에서도 아직 미검증이다(2026-08-19 기준). 여기서도 같은 위험을 진다
- **대사가 화면에 글자로 이중으로 그려지지 않는가** — 같은 이유로 미검증
