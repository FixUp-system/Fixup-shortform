# 단계별 영상 화질 선택 — 가격의 셋째 축

> 2026-08-13 · 광고 경로(`lib/ad/models.js`)의 구조를 단계별로 이식

## 왜

`lib/clip-limits.js` 가 Seedance 프로필에 `resolution: "720p"` 를 **하드코딩**하고 있다.
사장님은 고를 수 없고, 우리는 720p 원가만 낸다. 광고 경로는 이미 **모델 × 길이 × 해상도**
세 축으로 정리돼 있다(`AD_MODELS[].resolutions` · `perSecUsd[해상도]` · `AD_VIDEO_PRICE`).
같은 구조를 단계별로 가져온다.

## 데이터

### 1. 모델이 실제로 여는 해상도만 둔다

`CLIP_PROFILES` 에 `resolutions` 배열을 더한다. 광고 `models.js` 의 규율을 그대로 쓴다 —
**모델이 안 여는 값을 목록에 두면 고른 순간 fal 이 거절한다.**

| 모델 | resolutions |
|---|---|
| `bytedance/seedance-2.0` | `["480p", "720p", "1080p"]` |
| `fal-ai/kling-video/v3` | `[]` — 해상도 파라미터가 없다 |
| `fal-ai/ltx-2` | `[]` (옛 모델) |

**빈 배열이면 화면에 선택지를 안 띄운다.** "고를 수 있는 척"이 가장 나쁘다.

⚠️ Kling 의 해상도 파라미터 유무는 **구현 전에 fal 문서로 확인한다.** 있으면 목록을 채운다.
확인 못 하면 빈 배열로 두고 그 사실을 주석에 남긴다 — 모르는 값을 보내면 조용히 무시되거나
거절되고, 어느 쪽인지 알 수 없다.

`extra.resolution` 하드코딩은 걷어낸다. 요청 시점에 `settings.resolution` 으로 채운다
(`lib/i2v.js`). 프로필의 `extra` 는 **모델별 고정 필드**만 남긴다(`generate_audio` 등).

### 2. 기본값은 `720p` 다

옛 문서(`settings.resolution` 없음)를 이 값으로 읽는다. **지금까지 실제로 fal 에 보낸 값이
720p 하드코딩**이라, 반대로 두면 이미 만든 프로젝트의 가격과 각인이 소급해 달라진다.
광고 쪽 `DEFAULT_AD_RESOLUTION` 이 같은 이유로 720p 다.

## 가격 — 세 축 표

```js
VIDEO_PRICE["seedance-2.0"]["720p"][30]   // 지금: VIDEO_PRICE["seedance-2.0"][30]
```

배수 계산을 쓰지 않는다 — 표에 **박아 둔다**. 배수는 반올림이 생기고 모델마다 배율이 다른 것을
못 담는다(광고 `AD_VIDEO_PRICE` 가 같은 판단).

### 원가 근거

단계별은 **i2v** 다(광고의 t2v 와 단가가 다르다). 광고 `models.js` 주석의 fal 문서 확인값:

- Seedance 2.0 i2v **720p = $0.3024/s** (문서값)
- **1080p** — 720p:1080p 원가비가 가로폭 제곱비(1080²/720² = 2.25)와 거의 같다(광고 t2v 실측:
  0.682/0.3034 = 2.248). 같은 식으로 `0.3024 × 2.25 ≈ 0.680/s`
- **480p** — 같은 식으로 `0.3024 × (480/720)² = 0.3024 × 4/9 ≈ 0.1344/s`

★ 480p·1080p 는 **계산값이지 실측이 아니다.** 주석에 그렇게 적는다(광고 `models.js` 가 같은
표기를 쓴다). 실제 청구서와 어긋나면 표를 고친다.

### 크레딧 값

1크레딧 ≈ $0.06 원가 기준을 유지한다. 720p 열은 **지금 값 그대로 두어** 옛 프로젝트의 가격이
변하지 않게 한다. 480p·1080p 열은 위 비율로 계산해 **올림**한다(올림은 기존 표의 방식이다 —
720p 30초가 $9.07/0.06 = 151.2 인데 160 으로 잡혀 있다).

`REGEN_PRICE.clip` 도 같은 축이 필요하다 — 컷 하나를 다시 만들 때도 해상도가 원가를 가른다.

## ⚠️ 각인 — 가장 위험한 자리

`clipKey`(`lib/steps.js`)에 해상도를 더한다. 안 하면 **화질을 바꿔도 클립이 안 낡아** 옛 화질이
그대로 남고, 사장님은 바꿨는데 아무 일도 안 일어나는 것을 본다.

**단 값이 있을 때만 덧붙인다.** 무조건 붙이면 옛 각인(`url|초|움직임`)이 전부 불일치가 되어
**이미 값을 치른 클립이 통째로 낡는다**(Seedance 30초 한 편 ~$9). 이 저장소가 `style_of` ·
자막 위치 · 오늘 `tone_of` 에서 세 번 같은 규칙을 썼다:

★ **값을 어디서 읽는가**가 갈림길이다. `clipKey` 의 `speed` 는 컷에서 읽고 `spokenOf` 는
**지금 프로젝트에서 판다**(저장해 두면 저장값과 비교값이 같은 출처가 되어 영영 안 낡는다).
해상도는 **프로젝트 설정**이므로 `spokenOf` 쪽 규칙을 따른다 — `project.settings.resolution`
에서 읽고, **컷에 저장하지 않는다.**

```js
// clipKey(cut, project) 안에서 — 컷이 아니라 프로젝트에서 판다
const res = project?.settings?.resolution;
const withRes = res ? `${withSpeed}|${res}` : withSpeed;
```

⚠️ `project` 는 `clipKey` 의 **선택 인자**다(포인트프리로 넘기면 배열 번호가 들어온다는 기존
주석 참고). `project` 가 없으면 해상도를 안 붙인다 — 덜 알리는 쪽이 안전하다는 이 저장소의
기존 방침(`isImageStale` 의 `style_of` 처리)과 같다.

## 어디서 고르나 — ②대본(결제 앞)

모델 칩 옆이다. `CLAUDE.md` 에 사고 기록이 있다:

> 정가는 ③에서 걷히는데 모델 칩은 ⑤에 있었다 — Seedance 로 160 내고 Kling 으로 바꾸면
> 사장님이 110 크레딧 손해, 반대면 우리가 편당 ~$6

해상도도 가격을 바꾸므로 **반드시 결제 앞**이고, 모델과 같이 **첫 클립 뒤 잠긴다**.

**모델을 바꿀 때 해상도가 따라간다.** 새 모델의 `resolutions` 에 지금 값이 없으면(Seedance
1080p → Kling) 그 모델의 기본값으로 떨어뜨린다. 안 하면 저장된 값이 모델과 어긋난 채 남아
fal 이 거절한다.

## 테스트

| # | 무엇 | 왜 |
|---|---|---|
| 1 | 옛 프로젝트(`resolution` 없음)의 `clipKey` 가 **글자 그대로** 안 바뀐다 | 이 작업의 하드 제약 — 틀리면 재구매 ~$9/편 |
| 2 | 옛 프로젝트의 가격이 720p 값과 같다 | 소급 변경 방지 |

| 4 | 모델에 없는 해상도는 거절된다 | 고른 순간 fal 이 거절하는 것보다 앞에서 막는다 |
| 5 | 모델을 바꿔 해상도가 사라지면 기본값으로 떨어진다 | 어긋난 채 저장되는 것을 막는다 |
| 6 | `VIDEO_PRICE` 키와 `CLIP_PROFILES[].resolutions` 가 어긋나면 실패 | **두 목록이 갈릴 자리를 코드가 판정** — `tests/ad-options.test.js` 와 같은 방식 |
| 7 | `resolutions` 가 빈 모델은 화면에 선택지를 안 낸다 | "고를 수 있는 척"을 막는다 |

## 범위 밖

- **광고 경로**는 이미 해상도가 있다 — 건드리지 않는다
- 해상도별 화면 비율·픽셀 치수(`lib/aspects.js`)는 지금도 비율이 정한다. 해상도는 fal 파라미터일 뿐이다
- 라이브 검증 — 480p·1080p 원가가 계산값이라 **첫 실사용 청구서와 대조**해야 한다. 이 문서 밖의 과제로 남긴다
