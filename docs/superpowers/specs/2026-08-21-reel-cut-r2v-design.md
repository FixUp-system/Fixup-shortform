# 컷마다 참조를 들고 굽는다 — 영상 프롬프트를 LLM 에 넘기고, 흐름을 새로 하나 판다

2026-08-21 · 브랜치 `feat/reel-cut-r2v` · 워크트리 `.claude/worktrees/step-gate`

## 왜 지금 하는가

사장님 지시: **"기존에 순서대로 이미지를 전달하는 방식을 좀 더 고도화한다."**
전체 흐름을 사장님이 직접 그었다:

> 먼저 전체 시나리오를 작성해 작성된 시나리오를 컷별로 분할하고 이미지를 생성할거야.
> 생성된 이미지를 영상 프롬프팅 후 영상모델 r2v를 통해서 영상 생성을 진행할거야.
> 단 생성된 이미지에는 한글이 포함되면 안되며 영상 프롬프팅의 경우에는 별도의
> 영상 프롬프팅 전용 llm을 통해서 진행할거야.

### 이것은 새 발명이 아니라 **빠진 칸을 채우는 것**이다

업계 조사(2026-08-21)로 확인한 것:

- **모델 제공사가 이미 프롬프트를 다시 쓴다.** Google Veo 는 LLM 리라이터가 짧거나 모호한
  프롬프트에 *영상 묘사·카메라 움직임·대사·음향효과* 를 덧붙인다. Veo 2 는 기본 켜짐,
  **Veo 3·3.1 은 끌 수조차 없다.** 즉 짧은 프롬프트를 그대로 받는 영상 모델은 사실상 없다.
- **편 단위 도구는 한 겹을 더 쓴다.** LTX Studio 는 스크립트를 씬·샷으로 쪼개고, 샷마다
  스틸을 만들고, **그 스틸이 영상 모델의 출발점**이 된다. 그리고 반복 등장하는 인물·소품을
  **Element** 로 뽑아 샷에서 샷으로 옮긴다.

우리 `cut.ref_ids`(캐스팅이 인물·소품을 컷에 꽂는 것)가 그 **Element 와 같은 장치**다.
지금까지 그것을 그림에만 쓰고 **영상 모델에는 안 보냈다** — 이 설계가 그 자리를 잇는다.

그리고 ⑤영상 프롬프트를 지금은 **코드가 조립한다**(`buildClipPrompt`). 업계는 LLM 이 쓴다.
사장님이 말한 "영상 프롬프팅 전용 LLM"이 정확히 그 칸이다.

## 결정된 것 (사장님 확인 2026-08-21)

| 물음 | 답 |
|---|---|
| r2v 를 몇 번 부르나 | **컷마다 한 번** (통짜 한 번이 아니다) |
| 목소리 | **클립이 직접 말한다** (`speaks: true`, 우리 TTS 없음) |
| 넘버링 | **컷 순번을 모델에게** (`scene 2 of 4`). 첨부 번호는 **안 쓴다** |
| "전용 LLM" 의 뜻 | **영상 생성에 특화된 프롬프트** (모델을 바꾸는 것이 아니다) |
| 모델 | **`claude-fable-5`** |
| LLM 이 쓰는 범위 | **본문만** — 꼬리(대사·순번·립싱크·금지)는 코드가 붙인다 |
| 컷마다 r2v 에 넣을 것 | **컷 그림 + 인물/제품 참조** (`ref_ids`) |
| 이미지 글자 | **모든 글자 금지** (한글만이 아니다). 글자는 ffmpeg 자막이 맡는다 |
| 08-18 에 걷어낸 제품 절 | **그대로 둔다 — 다시 넣지 않는다** |
| 놓을 자리 | **흐름 전체를 새로** (`reel`) |

### ⚠️ 방향이 한 번 바뀐 것을 적어 둔다

물음 "놓을 자리"에 처음 답은 **"단계별을 제자리에서 고친다"**였고, 그 다음에
**"흐름 전체를 새로"**로 바뀌었다. 후자가 작업량이 크고 **장치가 두 벌이 될 위험**이 따른다.
그 위험을 아래 §2 의 표 하나로 막는다 — 이 설계에서 가장 중요한 절이다.

## 1. 새 흐름의 모양

이름은 **`reel`**. 화면 구성은 film 의 것을 그대로 따른다(아래 ★ 참고).

```
/reel/new                프로젝트가 아직 없는 자리 — 컨셉·길이·화질·모델·화풍을 받는다
                         만들자마자 시나리오로 보낸다 (부르는 문은 POST /api/reel 하나)
/reel/[id]/layout.js     문서를 한 번 읽어 컨텍스트에 담고 스테퍼·라우팅 가드를 건다
  ├ briefing             1 입력 — **보여 주기만 한다** (만든 뒤에는 조건을 못 바꾼다)
  ├ scenario             2 시나리오          ← 사람이 멈추는 유일한 자리
  ├ images               3 컷별 이미지        (글자 없음)
  ├ prompts              4 ★ 영상 프롬프트    ← 새 섹션 (fable5)
  ├ video                5 컷별 r2v 굽기
  └ done                 6 합성·자막·완성
```

> ★ **`new` 와 `briefing` 이 왜 따로인가** — `layout.js` 는 문서를 읽어야 일할 수 있는데
> `new` 에는 읽을 문서가 없다. 그래서 "만들기 전"만 레이아웃 **밖**에 둔다.
> (`app/film/new/page.js:5` 의 주석이 근거다. 같은 함정을 다시 밟지 않는다.)
>
> ★ **화면마다 자기 fetch 를 두지 않는다** — 같은 문서를 여섯 번 읽게 되고, 한 화면이
> 갱신한 값을 옆 화면이 모른다. 레이아웃이 읽은 것을 컨텍스트로 내린다.

**③목소리 단계가 없다** — 클립이 직접 말하므로 만들 것이 없다. 이것은 새 판단이 아니라
`stepsFor()` 가 `speaks: true` 에서 이미 하는 일이다(2026-08-14).

**단계 표는 `lib/reel/steps.js` 하나다** — 스테퍼·라우팅 가드·현재단계 판정이 **모두** 그
표를 본다. 한 곳이라도 표를 안 보고 손으로 적으면 화면이 여는 문과 가드가 닫는 문이
갈린다(2026-08-13 에 겪은 결함).

### 2-1. 빌려 쓰려면 손대야 하는 자리 — 전부 **가산 한 자리**다

⚠️ **이 절은 구현 중에 셋 → 다섯으로 늘었다**(2026-08-21). 처음 셋은 설계 때 알았고,
넷째·다섯째는 **구현이 드러냈다.** 늘어난 것 자체가 기록할 값어치가 있어 남긴다 —
"빌려 쓴다"고 적어 둔 모듈도 실제로 빌려 보면 광고 전용 가정이 박혀 있었다는 뜻이다.

다섯 다 처방이 같다: **안 넘기면(또는 안 쓰면) 예전과 글자 그대로 같다**(회귀 0).
새 파일을 만들어 피하면 그 순간 장치가 두 벌이 된다.

| 파일 | 왜 못 빌리나 | 무엇을 더하나 | 언제 드러났나 |
|---|---|---|---|
| `lib/ad/llm.js` | 거절 문구가 `"시나리오"` 로 박혀 있고, 가짜 모드가 광고 시나리오를 준다 | `stage` 를 문구에 쓰고, `fake` 인자를 받는다 (§5-1) | 설계 |
| `lib/i2v.js` | `image_url` 한 장뿐이고 엔드포인트가 i2v 로 고정이다 | `refs` 인자 — 있으면 r2v (§5) | 설계 |
| `lib/cuts.js` | `buildClipPrompt` 의 본문을 코드가 조립하고, 꼬리 ④가 "첫 프레임"으로 박혀 있다 | `opts` 인자 — 본문·컷순번·첨부설명 (§4-2) | 설계 |
| **`lib/ad/llm.js`** | ★ `output_config` 에 **`SCENARIO_SCHEMA` 가 하드코딩**돼 있다 — 구조화 출력이 광고 시나리오 모양을 강제하므로 `{"body":…}` 는 **애초에 나올 수 없다** | `schema` 인자 (기본값 `SCENARIO_SCHEMA`) | **Task 6 리뷰** |
| **`lib/projects.js`** | ★ `KINDS = ["ad","film"]` 이라 `createProject({kind:"reel"})` 가 던진다 | `KINDS` 에 `"reel"` 한 줄 | **Task 11 구현** |

★ `lib/cuts.js` 를 고치는 대신 `lib/reel/` 에 꼬리를 새로 지으면 **꼬리가 두 벌**이 된다.
대사·립싱크·금지문이 두 곳에 살면 한쪽이 반드시 낡고, 그때 갈리는 것은 **들리는 말과
ffmpeg 자막**이다. 꼬리는 한 벌로 둔다.

> ### ★★ 넷째가 왜 위험했나 — **진짜 경로만 죽어 있었다**
> `callJson` 이 스키마를 박아 보내는 바람에 `writeClipPromptBody` 의 실제 경로는 늘
> 빈 `body` 를 받게 돼 있었다. 그런데 **테스트는 전부 그린이었다**: 테스트는
> `callJsonImpl` 을 주입해 진짜 `callJson` 을 안 지나고, 가짜 모드는 API 호출 **앞에서**
> 조기반환한다. 즉 이 결함이 처음 드러나는 자리는 **유료 구간**이었다.
> → 교훈: **의존성을 주입해 테스트한 경로는 "그 배선이 맞다"를 증명하지 않는다.**
>   주입 지점 **바깥**을 한 번은 실제로 지나 봐야 한다(§10 의 5단계가 그 자리다).

> ### ★ 다섯째가 왜 돈 문제였나 — `isStepDoc` 가 격리 관문이다
> `kind` 를 안 붙이면 `isStepDoc(doc) = doc.kind == null` 이 참이 되어, reel 프로젝트가
> **옛 단계별 흐름의 유료 라우트를 그대로 통과한다.** 그 관문을 무는 라우트가 10곳이 넘고
> 그중 `app/api/projects/[id]/clips` 는 **청구하고 i2v 로 굽는다** — `clip_prompt` 를
> 모른 채. 그래서 `kind: "reel"` 은 표기가 아니라 **격리 장치**다.

## 3. ★ 새 섹션 — 영상 프롬프트 (`/reel/[id]/prompts`)

```
컷1  [ 프롬프트 본문 ...................... ]  [다시 쓰기]
컷2  [ .................................... ]  [다시 쓰기]
컷3  [ .................................... ]  [다시 쓰기]
                                      [영상 만들기 →]
```

**이 섹션을 따로 둔 값어치는 "굽기 전이라 틀려도 공짜"라는 것 하나다.** 컷 하나를 다시
굽는 데 12크레딧(480p)이 들지만, 여기서 고치는 것은 0원이다.

### 3-1. 부품 — `lib/reel/clip-prompt.js`

`lib/ad/llm.js` 의 `callJson` 을 그대로 부른다(원장·예산·재시도·거절처리가 딸려온다).

| | |
|---|---|
| 모델 | `claude-fable-5` (`lib/ad/llm.js` 의 `CLAUDE_MODEL`) |
| stage | `"영상프롬프트"` |
| 입력 | 컷의 `shows`·`camera`·`lighting`·`action`·`sound` / **컷 순번(n/총)** / 앞 컷의 `shows` / 화풍·톤·무대 |
| 출력 | `{ "body": "..." }` — 장면·움직임·카메라·빛만 |
| **안 쓰는 것** | 대사 · 글자 · 첨부 번호 |

### 3-2. system 프롬프트의 규율

Seedance 2.0 공식 가이드(§1.1)의 공식을 쓴다 — **누가 + 무엇을 + 배경/조명/스타일 + 음향**.

> ★★ **금지 목록을 쌓지 않는다.** 근거가 둘이고 같은 방향이다:
> ① `claude-fable-5` 는 지시가 과하게 박히면 **오히려 품질이 떨어진다**.
> ② 이 저장소가 08-19~21 실측으로 같은 결론에 도달했다 — `music`·대사 규칙·연출 강제·
>    초 표기를 걷어내자 사장님 평이 **"훨씬 자연스럽다"** 였다
>    ([[shotform-control-restraint-2026-08-19]] 의 제목이 "통제를 자제한다"다).
>
> 그래서 이 system 은 **무엇을 쓰는 자리인지**만 말하고 판단은 모델에 맡긴다. 넣는 규칙은 둘뿐:
> - 읽힐 글자·숫자가 보이는 장면은 적지 않는다 (`SHOWS_SYSTEM` 과 같은 줄)
> - 희귀·모호한 단어와 복잡한 특수 기호를 피한다 (Seedance 가이드 §2 모범 사례)

⚠️ 프롬프트 예시는 **테스트 자료와 소재도 동사도 겹치지 않게** 고른다(CLAUDE.md 규율).
08-21 에 이 규율을 어겨 모델이 예시를 어절 단위로 베낀 사고가 있었다.

## 4. 컷 프롬프트 — 무엇이 바뀌고 무엇이 안 바뀌나

지금 `buildClipPrompt` 는 다섯 덩어리다. **④ 하나만 바뀐다.**

```
┌─ 본문 ────────────────────────────────────────────────
│  ★ 지금은 코드(promptBodyOf)가 조립 → 새로는 LLM 이 쓴다
├─ 꼬리 ① 대사 ─────────────────────────────────────────  그대로
│  <인물> speaks to the camera with natural lip sync.
│  Voice: <voice>. Says exactly, in <언어>: "<대사 원문>".
├─ 꼬리 ② 맥락 (clipContextClause) ─────────────────────  그대로
│  Setting: … / Characters in this frame: …
├─ 꼬리 ③ 공통 지시 (promptNoteClause) ─────────────────  그대로
├─ 꼬리 ④ 첨부 설명 ───────────────────────────────────  ★ 여기만
│  (지금) The attached image is the first frame — continue naturally from it.
│  (새로) This is scene 2 of 4.
│         The attached images show what this scene, the person
│         and the product look like.
└─ 꼬리 ⑤ 금지 ────────────────────────────────────────  그대로
   Keep the subject and style unchanged. No text or letters.
```

**대사가 원문 그대로라 ffmpeg 자막과 갈리지 않는다** — 이것이 ①을 안 건드리는 이유다.

### 4-1. 제품 절은 다시 넣지 않는다 (사장님 결정)

08-18 에 `clipContextClause` 에서 제품 절을 걷어냈고, 그 근거가 이것이었다(`lib/cuts.js:1509`):

> 클립(i2v)은 사진이 안 간다 — 이미지 한 장 + 글로 쓴 묘사뿐이라 **묘사가 이미지를 이긴다.**

⚠️ **이 전제를 우리 변경이 뒤집는다** — r2v 로 가면 사진이 간다. 그래서 제품 절을 되살릴
자리가 생기지만, **사장님 결정은 "그대로 둔다"** 다. 첨부가 완전히 익명이 되지는 않는다 —
꼬리 ④가 "이것들이 각각 장면·사람·제품이다"라고 뭉뚱그려 말한다. 08-21 에 film 이 도달한
자리와 같다: **무엇인지는 말하되 생김새를 글로 못 박지 않는다. 생김새는 사진이 말한다.**

### 4-2. 어떻게 — `buildClipPrompt(cut, project, opts)`

꼬리를 한 벌로 두려면 **같은 함수**가 두 흐름을 다 낳아야 한다. 선택 인자 하나로 한다.

```js
buildClipPrompt(cut, project)                    // 단계별 — 옛 경로, 글자 그대로 같다
buildClipPrompt(cut, project, {                  // reel
  body,          // LLM 이 쓴 본문. 없으면 promptBodyOf 가 조립한다(옛 경로)
  sceneNo,       // 2  → "This is scene 2 of 4."
  sceneCount,    // 4     둘 다 있을 때만 그 문장이 붙는다
  attach: "refs" // 꼬리 ④를 참조 문구로. 없으면 "first frame"(옛 경로)
})
```

★ 꼬리 ④가 **엔드포인트를 따라간다** — i2v 면 첫 프레임, r2v 면 참조. 그것이 사실이니까.
★ `opts` 를 안 넘긴 호출은 **한 글자도 안 달라진다.** 각인이 그 위에 서 있다.

## 5. r2v 배선 — `lib/i2v.js` 에 인자 하나

새 파일을 만들지 않는다. 원장·예산(`assertBudget`)·멱등이 이미 거기 있다.

```js
generateClip({ imageUrl, refs, ... })   // refs 가 없으면 예전 그대로 i2v — 회귀 0
```

- `refs` 가 있으면 엔드포인트가 `bytedance/seedance-2.0/reference-to-video`
- `input.image_urls = [컷 그림, ...loadCutRefs(cut, project).refs]`
- 순서는 지금 `ref_ids` 규율 그대로 — **사물 먼저, 인물 뒤**(`lib/pipeline.js:178`)

> ⚠️ 엔드포인트 문자열이 fal 의 경로와 **글자 그대로** 같아야 한다. 한 글자만 달라도 404 인데
> 그때는 이미 값을 치른 뒤다. 테스트가 문자열을 대조한다(`tests/ad-two-models.test.js` 선례).

### 5-1. `lib/ad/llm.js` 에 손대는 두 줄 (§2-1 의 예외 하나)

두 자리가 광고 전용으로 박혀 있어 그대로는 못 빌린다. 둘 다 **안 넘기면 예전과 글자 그대로**다.

| 무엇이 문제인가 | 어떻게 고치나 |
|---|---|
| 거절 문구가 `"시나리오 생성이 거절됐어요"` 로 박혀 있다(`:221`). `stage` 인자가 있는데 안 쓴다 — 우리가 부르면 사장님이 **영상 프롬프트 단계에서 "시나리오"** 를 본다 | 문구가 `stage` 를 쓰게 한다 |
| `if (fakeLlm()) return fakeAdResponse()` — 가짜 모드가 **광고 시나리오 JSON** 을 준다. `SHOTFORM_FAKE=all` 0원 관통이 그 자리에서 깨진다 | `fake` 인자를 받아 부르는 쪽이 정하게 한다. 없으면 `fakeAdResponse` |

## 6. 각인 — LLM 이 매번 달라도 낡음이 안 튀게

`cut.clip_prompt` 에 **만든 프롬프트를 저장**하고, 낡음 판정(`lib/reel/steps.js` 의
`isClipStale` — 단계별의 것과 같은 결이되 이 흐름의 표를 본다)은 **저장된 문자열**을 본다.

- ⑤영상 시작 때 컷마다 없으면 만들고 **있으면 재사용**한다
- 사장님이 화면에서 고친 값이 그대로 굽기로 간다
- "다시 쓰기"가 그 칸을 비운다

★ 이것이 없으면 LLM 이 부를 때마다 다른 문장을 내므로 **이미 산 클립이 매번 낡는다**
(컷당 12크레딧 재구매).

## 7. 시험

코드가 판정한다(CLAUDE.md: *지켜져야 하는 것은 프롬프트가 아니라 코드가 판정한다*).

- 대사 원문이 프롬프트에 **글자 그대로** 들었는가
- system 에 글자 금지 줄이 있는가
- `image_urls` 의 **순서** (컷 그림 → 사물 → 인물)
- 컷 순번 문구(`scene N of M`)가 실제 컷 수와 맞는가
- 엔드포인트 문자열 대조
- `refs` 를 안 넘기면 옛 i2v 경로가 **글자 그대로** 같은가 (회귀 0)
- 거절 문구가 `stage` 를 말하는가 / 가짜 응답을 부르는 쪽이 정하는가
- `SHOTFORM_FAKE=all` 로 0원 관통

⚠️ **화면 파일을 손댔으면 한 번 굽는다** — 이 저장소의 화면 계약은 소스 문자열을 훑어 재기
때문에 문법이 깨진 파일을 못 잡는다. dev 서버를 끄고 `npx next build && rm -rf .next`.

## 8. 안고 가는 위험 (전부 미검증)

| | 위험 | 되돌리는 법 |
|---|---|---|
| 1 | **컷 간 목소리 일관성.** 설계가 "무너지면 구현하지 않는다"로 건 **정지 게이트**인데 통과된 적이 없다. `seeded: true`(컷마다 같은 씨앗)가 유일한 방어선이다 | `lib/clip-limits.js` 의 `speaks: true` → `false` **한 줄** |
| 2 | **첫 프레임 못 박기를 잃는다.** r2v 는 그림을 참고로 본다 — 그림과 영상 첫 장면이 달라 보일 수 있다. LTX Studio 같은 업계 주류는 스틸을 **seed** 로 쓰므로 이것은 주류에서 벗어나는 선택이다 | `refs` 를 안 넘기면 i2v 로 복귀 |
| 3 | **컷 단위 r2v 를 불러본 적이 없다.** film 이 통짜로만 써 봤다 | 첫 호출 422 면 그 자리에서 고친다(값 치르기 전) |
| 4 | **Seedance 가 프롬프트를 리라이트하는가 — 미확인.** fal 문서가 클라이언트 렌더라 스키마를 못 읽었다. 리라이트가 있으면 우리 **컷 순번·대사 원문이 흔들려** 자막과 갈릴 수 있다 | 첫 호출 응답에 리라이트된 프롬프트가 오는지 본다 |
| 5 | **장치가 두 벌이 될 위험.** §2 의 표가 유일한 방어선이고, 예외 셋(§2-1)은 전부 *선택 인자 하나 · 회귀 0* 이어야 한다 | 오른쪽 칸에 손이 가면 멈추고 여쭙는다 |

## 9. 이 설계가 하지 않는 것

- **film 의 두 방식(`order`·`refs`)을 건드리지 않는다.** 지우지도 않는다 — 지우면 그것으로
  만든 옛 영상이 보관함에서 죽는다(`seedance-2.0-fast` 로 한 번 겪은 사고).
- **단계별 흐름(①~⑥)을 건드리지 않는다.** `reel` 은 옆에 선다.
- **결제·법적 페이지는 범위 밖이다.**
- **첨부 번호(`[1] the product`)를 굽기 지시문에 넣지 않는다** — 사장님이 08-21 에
  *"참조번호는 사용하지 않는 게 맞다 — 자유도를 부여하기로 했으니까"* 로 정했다.
  ⚠️ 다만 Seedance 공식 가이드의 번호 예시는 **전부 영상 생성 프롬프트**다(§2.2·§3.2·§4).
  즉 공식 문법과는 어긋나는 선택이고, 굽기 한 번($2.48)이면 갈린다. **이번 범위 밖으로 남긴다.**

화면부터 지으면 §8 의 위험 넷을 **전부 마지막에** 만나게 된다. 순서를 뒤집는다.
