## 0. ⚠️ 이 문서가 뒤집는 것 — 먼저 읽어라

**하루 전(2026-09-08) 이 저장소는 화면을 「밝은 벌 한 벌」로 바꿨고, 어두운 벌을
되돌릴 수 없게 지웠다.** 오늘 아침에는 결과물 띠까지 밝게 바꿨다(사장님: *"뒤에
백그라운드가 검정색이라 뭔가 이질감이 드는데"*).

이 문서는 **그 결정과 정면으로 어긋난다.** 그래서 무엇을 뒤집고 무엇을 지키는지
먼저 못 박는다 — 안 적으면 다음 세션이 "어느 쪽이 최신인가"를 못 가른다.

| | 09-08~09 결정 | 이 문서 |
|---|---|---|
| 작업 화면(만들기·보관함·비용) | 밝은 벌 | **그대로 밝게 둔다** |
| 랜딩(첫 화면) | 밝은 벌 | **어둡게 간다** |
| 자막 무대 | 어둡다(벌을 안 탄다) | 그대로 |

즉 **경계가 하나 더 생긴다.** 이 저장소가 이미 쓰는 말로 하면
*"보는 면은 어둡게, 조작하는 면만 밝게"* — 자막 무대에만 살던 그 규칙이
**랜딩까지** 넓어지는 것이다.

🔴 **아직 사장님 확정이 아닌 것**: "랜딩만 어둡게"인지 "전체를 어두운 벌로 되돌리는지".
이 문서는 **전자**를 전제로 쓴다(작업 화면의 밝은 벌은 어제 하루를 들여 만든 것이고,
그것까지 되돌리면 09-08 회차가 통째로 버려진다). 후자로 가려면 §7을 본다.

## 1. 측정한 값 — 눈이 아니라 픽셀에서 뽑았다

캡처는 978×1565 이고, 그 안에 화면 세 컷이 세로로 쌓여 있다. 첫 컷의 실제 크기는
**832×~490px**(바깥 여백 `#F1EFE9` 와 검정의 경계로 잰 값)이다.

> ⚠️ **배율은 모른다.** 원본 화면 폭이 1440 이면 ×1.73, 1512 면 ×1.82 다.
> 아래 "환산" 열은 **1440 기준**이고, 어디까지나 출발점이다 — 구현할 때 눈으로 맞춘다.

### 1-1. 색 (`sharp` 로 영역을 잘라 통계를 냈다)

| 자리 | 측정 | 비고 |
|---|---|---|
| 바탕 | **`#000000`** | 평균·최대·최소가 전부 0 — **완전한 검정**이다. 우리 옛 `--bg`(#1A1A1A)보다 훨씬 깊다 |
| 바닥 격자선 | 가장 밝은 곳이 **`#121212`** | 거의 안 보인다. 선이 아니라 **질감**에 가깝다 |
| 상단바 글자 | 가장 밝은 곳 **`#D1D1D1` / `#BEBEBE`** | 흰색이 아니라 **한 단계 눌린 회색** |
| 하단바 글자 | **`#D9D9D9`** | 상단바와 같은 급 |
| 패널 라벨 | **`#F7F7F7`** | 거의 순백. **패널 위에서만 밝다** |

★ 읽어야 할 성질은 색 값이 아니라 **층이 셋**이라는 것이다:
**바탕(0) → 껍데기 글자(≈#C8) → 내용 글자(≈#F7)**. 껍데기(상단바·하단바)는
일부러 뒤로 물러나 있고, 밝은 것은 작품 위 라벨뿐이다.

### 1-2. 타이포 (밝기 임계로 글자 픽셀을 세어 잰 값)

| 자리 | 캡처 실측 | 환산(1440 기준) | 성질 |
|---|---|---|---|
| 상단바 | 글자 높이 **5px** | ≈ 12px | **대문자** · 자간 넓음 · 굵기 보통 |
| 하단바 | 글자 높이 **5px** | ≈ 12px | 상단바와 같은 급 |
| 패널 라벨 | 글자 높이 **10px** | ≈ 17px | **문장 표기**(대문자 아님) · 자간 보통 |

★ **큰 글자가 하나도 없다.** 이 화면에는 전시층(`.display`)에 해당하는 것이 없고,
제목 노릇은 **작품 이미지 자체**가 한다. 우리 지금 랜딩의 `소재만 적으면 / 한 편이
나옵니다`(30px 전시층)와 정반대의 태도다 — §5의 열린 결정 ①.

### 1-3. 여백

| 자리 | 캡처 실측 | 환산 |
|---|---|---|
| 상단바 좌우 안쪽 여백 | 44px | ≈ 76px |
| 상단바 위 여백 | 21px | ≈ 36px |
| 하단바 아래 여백 | 27px | ≈ 47px |
| 패널 라벨 안쪽 여백 | 16px | ≈ 28px |

★ 화면 가장자리 여백이 **크다**. 우리 `.panel` 은 카드 안에 갇혀 있는데, 이 레퍼런스는
**화면 끝까지 쓰고 글자만 안쪽으로 들여쓴다**.

## 2. 토큰 제안

이 저장소의 규약을 따른다 — **색은 반드시 토큰으로 참조하고 `:root` 밖 hex 를 금지**한다
(`tests/design-system.test.js`). 랜딩 전용이므로 이름 앞에 `--stage-` 를 붙여
**앱층 토큰과 섞이지 않게** 한다.

| 토큰 | 값 | 무엇 |
|---|---|---|
| `--stage-bg` | `#000000` | 랜딩 바탕. 완전한 검정 |
| `--stage-grid` | `#121212` | 바닥 격자선. 배경과 거의 안 갈린다 |
| `--stage-chrome` | `#C8C8C8` | 껍데기 글자(상단바·하단바) |
| `--stage-ink` | `#F7F7F7` | 작품 위 라벨 |
| `--stage-edge` | `rgba(255,255,255,.14)` | 패널 테두리·구분선(측정 아님 — 눈으로 정할 값) |

⚠️ **`--stage-dark`(#101010)와 헷갈리지 마라.** 그것은 **자막 무대** 전용이고
이미 판이 지키고 있다(*"자막을 판단하는 무대는 벌이 밝아져도 어둡다"*).
같은 "어둡다"라도 목적이 다르다 — 하나는 **판정**, 하나는 **전시**다.

⚠️ 09-09 오전에 지운 넷(`--band`·`--band-ink`·`--band-soft`·`--accent-fill`)을
**되살리지 마라.** 그것들은 밝은 벌 안의 어두운 띠를 위한 값이었고, 여기서 필요한 것은
**화면 전체가 어두운 벌**이라 성질이 다르다. 옛 값은 `app/globals.css` 의 `:root`
주석에 남아 있다.

### 글자

| 토큰 | 값 |
|---|---|
| `--stage-fs-chrome` | `12px` · 대문자 · `letter-spacing: .08em` |
| `--stage-fs-label` | `16px` (사다리 값. 측정 환산은 17px 이지만 이 저장소의 크기 사다리는 **12·14·16·18·30** 뿐이고 판이 그것을 잰다) |

★ **사다리를 깨지 않는다.** 09-09 오전에 `.home-more` 를 13px 로 뒀다가 판에 잡혔다.
새 값이 정말 필요하면 사다리에 **먼저 추가하고** 판의 기대 목록을 함께 고친다.

## 3. 배치 — 무엇이 화면을 이끄는가

```
┌─────────────────────────────────────────────┐
│ SHORTFORM                          로그인   │ ← 껍데기(12px 대문자, #C8)
│                                             │
│        ╭────╮  ╭──────────╮  ╭────╮        │
│        │    │  │          │  │    │        │ ← 원근 캐러셀
│        │    │  │  가운데   │  │    │        │   (가운데가 정면, 옆은 안으로 휨)
│        ╰────╯  ╰──────────╯  ╰────╯        │
│                 편 이름              ⊕      │ ← 라벨 16px #F7 · 우하단 원형 버튼
│                                             │
│                    ·  ·  ·                  │ ← 바닥 격자(#121212)
│ 만든 것 / 전체                              │ ← 껍데기
└─────────────────────────────────────────────┘
```

레퍼런스에서 읽어야 할 규칙 넷:

1. **화면에 큰 글자가 없다.** 작품이 제목이다
2. **껍데기는 네 귀퉁이에만** 있다(좌상·우상·좌하). 가운데는 통째로 작품의 것이다
3. **가운데 하나만 정면이고 옆은 원근으로 눕는다** — 그래서 "지금 보는 것"이 자명하다
4. **바닥 격자**가 공간을 만든다. 없으면 패널이 허공에 뜬다

## 5. 열린 결정 — 사장님 몫

① **제목을 살릴 것인가.** 레퍼런스의 힘은 "작품 + 이름"에서 온다. 우리는 이름을
   못 쓴다(프롬프트 원문). 살리려면 **사장님이 고른 편에 손으로 이름을 다는**
   큐레이션이 필요하다. 안 하면 그림만 흐르는 화면이 된다.

② **큰 글자를 없앨 것인가.** 레퍼런스에는 없다. 우리는 09-09 에 `소재만 적으면 /
   한 편이 나옵니다`(30px)를 첫 화면에 뒀다. 손님이 처음 오는 화면이라
   **무엇을 파는 곳인지 한 줄은 있어야 한다**는 것이 지금 판단이었다.

③ **작업 화면까지 어둡게 갈 것인가**(§0). 이 문서는 "랜딩만"을 전제한다.

④ **3D 를 어디까지 할 것인가**(§6).

## 6. 3D 를 어떻게 만들 것인가 — 두 갈래

| | CSS 원근 | WebGL(three.js 등) |
|---|---|---|
| 곡면 | **못 한다**(평면을 눕히는 것까지) | 레퍼런스처럼 휜다 |
| 무게 | 0 — 지금 번들 그대로 | 라이브러리가 붙는다 |
| 이 저장소와의 궁합 | 좋다. 의존성 11개를 지켜 왔다 | ⚠️ 화면이 서버 전용 모듈을 끌어 빌드가 깨진 사고를 세 번 겪었다 |
| 모바일 | 안전 | 발열·배터리 |

**추천은 CSS 다.** 레퍼런스의 곡면은 멋있지만, 우리가 얻으려는 것은
*"가운데가 정면이고 옆이 물러난다"*는 **읽히는 구조**이고 그건 `rotateY` 로 선다.
곡면이 정말 필요하다고 판단되면 그때 별도 회차로 올린다.

`prefers-reduced-motion` 에서는 원근을 끄고 **평평한 가로 흐름**으로 떨어뜨린다
(지금 `.home-reel` 이 이미 그 모양이라 폴백이 공짜다).

## 7. 만약 "전체를 어두운 벌로" 라면

09-08 스펙(`2026-09-08-light-theme-mcs-design.md`)을 되살리는 것이 아니라
**그 반대 방향으로 다시 한 회차**다. 그때 실제로 든 일:
토큰 한 곳을 바꾸자 34개 화면이 따라왔고, 코드 커밋이 여덟이었다.
되돌리는 것도 비슷한 규모이고, **이번에는 되돌릴 어두운 벌이 남아 있지 않다**
(09-08 에 파일째 지웠다 — `components/ThemeToggle.jsx` · `tests/theme-light.test.js`).

즉 **"되돌리기"가 아니라 "다시 만들기"**다. 그 값을 알고 정해야 한다.

## 8. 판(테스트) 계획

이 저장소의 화면 계약은 소스 문자열로 잰다. 새로 세울 것:

1. **랜딩 토큰이 `:root` 에 있고 값이 이 문서와 같다** — `tests/design-system.test.js` 의
   기대 표에 `--stage-bg` 외 넷을 넣는다
2. **랜딩만 어둡다** — `--stage-*` 를 쓰는 선택자가 전부 `.stage`(랜딩 뿌리) 아래임을
   **선택자로 증명**한다. 09-08 의 `.home .home-band .eyebrow` 가 쓴 그 방법이다
   (이름 앞자리로 면제를 주면 `.home-header` 같은 앱층 화면이 딸려 나간다)
3. **영상 태그 0** — 지금 판을 랜딩 파일로 넓힌다
4. **칸이 셋 이하면 캐러셀을 안 그린다** — 표지가 다섯 장뿐인 현실(§4)
5. **글자 크기 사다리** — 기존 판이 이미 잡는다. 새 값을 넣으면 그 표도 함께 고친다

★ 판을 세울 때는 **변이 검증**을 한다 — 이 저장소의 판은 "항상 참"이 되기 쉽다
(09-09 에 실제로 하나 잡았다: 이름만 세는 단정이 배선을 끊어도 초록이었다).
