# 로그인 화면 시각 개선 (2026-08-06)

비밀번호 로그인이 붙으면서 화면이 "입력 두 칸 + 버튼"이 됐는데, 칸이 작고 다 붙어 있다.
네이버·구글 로그인을 **실측해서** 규칙을 뽑고, 색은 우리 다크 토큰을 그대로 쓴다.

## 실측 (2026-08-06, 브라우저로 직접 잼)

| | 구글(`accounts.google.com`) | 네이버(`nid.naver.com`) | 지금 shotform |
|---|---|---|---|
| 상자 폭 | ~450px | **520px**(반경 20, 안쪽 여백 49) | 760px (`panel--narrow`) |
| 입력칸 높이 | **52px** | **60px**(밑줄식) | ~40px |
| 입력 글자 | 16px | 17px | 16px |
| 입력칸 사이 | — (한 번에 한 칸) | **43px** | **10px** |
| 마지막 칸 → 버튼 | — | **110px** | 12px |
| 주버튼 | 40px·반경 20·파랑 | **48px**·반경 8·초록 | 높이 자동 |
| 화면당 입력칸 | **1** | 2 | 2 |
| 보조 링크 | 계정 만들기 | 아이디/비번 찾기·회원가입 | 없음 |

두 사이트가 **함께 지키는 것 넷**이 우리가 가져올 전부다: 입력칸이 크다 · 사이가 넓다 ·
상자가 좁다 · 주버튼이 폭을 꽉 채우고 크다.

## 확정된 결정

| 결정 | 내용 |
|---|---|
| 명암 | **다크 유지.** 색 토큰(`--surface`·`--line`·`--btn`…)을 그대로 쓴다 — 앱 내부와 끊기지 않게 |
| 입력 방식 | **두 칸 한 화면**(네이버식). 구글의 2단계는 "어느 이메일이 가입돼 있는지"를 드러내 우리의 계정 열거 차단 계약과 어긋난다 |
| 상자 폭 | **420px** — 구글 450·네이버 520보다 좁게. 우리는 로고·약관·소셜 버튼이 없어 담을 것이 적다 |
| 입력칸 | 높이 **52px**(구글 값), 글자 16px 유지 |
| 간격 | 칸 사이 **16px**, 마지막 칸 → 버튼 **28px**(네이버 43/110의 축소판 — 상자가 더 작으므로) |
| 주버튼 | 높이 **48px**(네이버 값), **폭 100%** |
| 보조 안내 | 자가 재설정이 없으므로 "비밀번호를 잊으셨다면 운영자에게 문의해 주세요" 한 줄로 대신한다(새 화면 없음) |

## 화면

```
        shotform                    ← 기존 pgtitle(28px)
   (탭에 따라 바뀌는 한 줄 소개)

  ┌────────── 420px ──────────┐
  │  로그인 | 회원가입          ← 선택된 쪽만 뚜렷하게
  │                            │
  │  [ 이메일            ]  52px│
  │            16px            │
  │  [ 비밀번호          ]  52px│
  │            28px            │
  │  [      로그인       ]  48px, 폭 100%
  │                            │
  │  (실패 문구 자리)           │
  └────────────────────────────┘
   비밀번호를 잊으셨다면 운영자에게…
```

- **탭**: 지금은 작은 버튼 둘이 나란히 있어 어느 쪽이 켜졌는지 약하다. 선택된 쪽만
  뚜렷하게(밑줄) 하고 나머지는 `--ink-soft`. 탭 자체는 지금 구조(state 하나)를 유지한다
- **가입 탭**일 때만 승인 안내가 붙는다(지금 문구 그대로)
- 실패 문구 위치·내용은 **바꾸지 않는다**(서버 문구 그대로 출력이 인증 스펙의 계약)

## 무엇을 손대고 무엇을 안 건드리나

**손댄다**: `app/login/page.js`(마크업·탭 표현), `app/globals.css` 에 **로그인 전용 클래스**
(`.login-card`·`.login-tabs`·`.login-tab`·`.sent-input--lg`·`.cta--block` 정도).

**안 건드린다**:
- 색 토큰·`.cta` 의 색 규칙(`--btn` 바탕에 `--btn-ink` 글씨)·폰트 크기 5종·반경 3종
- **`.sent-input` 기본형** — 브리핑(`app/create/[id]/briefing/page.js`)과 `StylePicker` 가
  쓰고 있어 키우면 그 화면들이 흔들린다. 로그인만 **큰 변형**을 쓴다
- 인증 로직·라우트 계약·실패 문구

## 테스트

- `tests/design-system.test.js` 가 **그대로 통과**해야 한다: hex 는 `:root` 밖에 없다 ·
  그라디언트 없다 · 반경은 토큰 3종 + 50% · font-size 는 12·14·16·18·28px · font-weight 는
  400·600·700 · `style={{}}` 는 10곳 이하 · `.cta` 색 규칙
- `tests/auth-ui.test.js` 에 소스 판정 추가: 로그인 화면이 **큰 입력 변형**과 **폭을 채우는
  버튼**을 쓴다(클래스 존재), 그리고 그 클래스가 `app/globals.css` 에 실재한다
- 실패 문구·라우트 호출을 무는 기존 단정은 유지한다

## 검증

구현 뒤 가짜 모드로 화면을 띄워 **실측값이 실제로 나오는지** 잰다(입력 52 · 간격 16/28 ·
상자 420 · 버튼 48/100%). 어긋나면 그 자리에서 조정한다. ⚠️ `SHOTFORM_DEV_USER` 를 비워야
로그인 화면을 볼 수 있다.

## 이번 스펙에 넣지 않는 것

- 소셜 로그인 버튼(구글·네이버로 로그인) — 인증 방식 변경이라 별개
- 자가 비밀번호 재설정 화면
- 앱 전체의 라이트 테마 전환
