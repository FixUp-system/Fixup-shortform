# 완성본을 Supabase Storage 로 — 설계

> 2026-08-12 · 내부 테스트 준비 1순위
> ([[2026-08-12-internal-test-readiness-plan]])

## 왜 하는가

완성 mp4 가 `data/renders/` **로컬 파일**이다. 서버를 다시 만들거나 여러 대로 늘리면
**사장님이 만든 영상이 사라진다.** 업로드 사진은 07-31 에 비공개 버킷으로 옮겼는데
렌더만 남았다 — 입력은 지켰고 출력은 안 지킨 셈이다.

## ★ 실측이 뒤집은 전제

계획 초안은 "mp4 37개를 옮긴다"였다. 실제로 디렉터리를 세어 보니 다르다:

| | 개수 | 무엇 |
|---|---|---|
| `<uuid>.mp4` | **6** | **최종 완성본** — 이것만 지켜야 한다 |
| `<uuid>-<N>.mp4` | 31 | 내려받은 클립 (중간물) |
| `<uuid>-<N>.m4a` | 27 | 내려받은 소리 (중간물) |
| `<uuid>.ass` | 7 | 자막 (중간물) |
| **합계** | **71** · 215MB | |

**중간물이 65개, 최종본이 6개다.** 중간물은 fal CDN 에서 다시 받을 수 있고(만료 없음)
합성이 끝나면 쓸모가 없는데 **지금은 지워지지 않고 쌓인다.** 215MB 중 대부분이 그것이다.

> 그래서 이 작업은 "옮기기"가 아니라 **"최종본은 Storage 로, 중간물은 쓰고 버리기"** 다.

## 무엇을 만드는가

### A. 버킷 — `renders`(비공개)

`uploads` 와 같은 방식이다. `db/schema.sql` 에 한 줄 더한다.

```sql
insert into storage.buckets (id, name, public)
values ('renders', 'renders', false)
on conflict (id) do nothing;
```

⚠️ 대시보드에서 권한에 막히면 수동 생성(07-31 에 `uploads` 가 그랬다).

### B. 합성 — 만들고, 올리고, 치운다

`lib/compose.js` 의 흐름을 바꾼다.

```
지금:  data/renders/ 에 중간물·최종본을 만들고 그대로 둔다
바꾼 뒤: 임시 폴더에 중간물·최종본을 만들고
        → 최종본만 Storage 에 올리고
        → 임시 폴더를 통째로 지운다
```

- 임시 폴더는 `fs.mkdtemp(os.tmpdir())` — 프로젝트마다 새로 만든다
- **ffmpeg 는 여전히 로컬 파일에 쓴다.** 자식 프로세스라 스트림을 못 받는다.
  "만들고 나서 올린다"가 유일한 순서다
- 지우기는 `finally` 에서 한다 — **합성이 실패해도 치운다**(지금은 실패하면 그대로 쌓인다)
- 반환 URL 은 **`/api/renders/<projectId>.mp4` 그대로**

★ **URL 형태를 바꾸지 않는다.** `renderKey`/`render.of` 각인이 URL 로 낡음을 판정한다
(`lib/steps.js`). 형태가 바뀌면 **기존 완성본이 전부 "낡음"이 되어** 다시 만들기 버튼이 뜬다 —
그 버튼은 유료다.

### C. 읽기 — 라우트가 Storage 에서 흘려준다

`app/api/renders/[name]/route.js` 가 파일 대신 `getObject("renders", …)` 를 부른다.

**소유자 검사는 지금 방식을 그대로 둔다** — 파일명이 곧 프로젝트 id 라
`getProject(id, user.id)` 로 판정한다(`uploads` 와 달리 `upload_owners` 매핑이 필요 없다).
`UUID_MP4` 정규식도 그대로다 — 중간물(`<uuid>-0.mp4`)은 애초에 이 라우트로 못 온다.

⚠️ **Range 요청**: 지금은 파일 전체를 읽어 보낸다. Storage 도 같다 — 이번에 바꾸지 않는다.
영상이 25초·수 MB 라 전체 전송으로 재생된다(지금 그렇게 돌고 있다).

### D. 이관 스크립트 — 최종본 6개만

`scripts/migrate-renders-to-storage.mjs`

- `data/renders/` 에서 **`<uuid>.mp4` 형태만** 골라 올린다(중간물은 건너뛴다)
- **멱등** — 두 번 돌려도 6개다. `uploads` 이관 스크립트와 같은 규칙
- 올린 뒤 로컬 파일을 지우지 **않는다** — 확인 후 사람이 지운다
- 실행 결과를 개수로 보고한다(올림 N · 건너뜀 M · 이미 있음 K)

## 건드리지 않는 것

- **ffmpeg 자체** — 인자·필터·자막 처리 전부 그대로
- `SHOTFORM_COMPOSER=fal` 경로 — 그쪽은 로컬 파일을 안 쓴다
- `/api/renders` 의 소유자 검사·정규식
- `render.of` 각인 규칙
- 병렬 세션이 만지는 파일(`lib/costs.js`·`lib/llm.js`·`app/api/chat` 등)

## 검증

1. `npx vitest run` — 1,261 그린 위에서 는다. `tests/compose*.test.js` 가 기존 계약을 지킨다
2. **임시 폴더가 남지 않는지** — 합성 성공·실패 두 경로 모두. 실패 경로는 ffmpeg 를 일부러
   깨서 확인한다
3. **URL 형태가 안 바뀌는지** — 기존 완성본이 `isRenderStale` 로 낡았다고 판정되면 안 된다
4. 이관 스크립트 **2회 실행 후 6개** 유지(멱등)
5. 라이브: 완성본 하나를 화면에서 재생

⚠️ **버킷을 먼저 만들어야 한다.** 없으면 합성 끝에 업로드가 실패한다 — ffmpeg 값(시간)은
이미 치른 뒤다.

## 범위 밖

- Range 요청 지원(구간 탐색) — 지금도 안 되고 이번에도 안 한다
- 중간물을 Storage 에 두는 것 — 버릴 것을 옮길 이유가 없다
- fal 산출물(클립·소리·그림) 비공개화 — 별건이다
