# 마이페이지와 상단 계정 바 (2026-08-07)

이용자가 **자기 정보를 스스로 고칠 수 있게** 한다. 그리고 계정에 관한 것(이름·크레딧·
로그아웃)을 사이드바에서 **상단 우측 한 자리로 모은다**.

지금은 이용자가 고칠 수 있는 것이 **하나도 없다.** `profiles` 에는 `email·status·role·
created_at·approved_at` 밖에 없고, 비밀번호조차 운영자가 `/admin` 에서 대신 바꿔 줘야 한다
([[2026-08-06-password-auth-design]] 에서 "자가 재설정 화면을 안 만든다"고 정한 것은
**메일 왕복이 필요한 재설정**을 말한 것이다 — 로그인한 사람이 현재 비밀번호를 알고 바꾸는
것은 메일이 필요 없다. 그래서 이번에 연다).

## 용어

이 문서는 사람을 둘로 나눈다. 저장소 주석의 "사장님"이 **이용자**다.

| 이 문서 | 저장소 주석 | 누구 |
|---|---|---|
| **이용자** | 사장님 | 가입해서 영상을 만드는 소상공인. `role=user` |
| **운영자** | 운영자 | 승인·크레딧을 관리하는 우리. `role=admin` |

## 확정된 결정

| 결정 | 내용 |
|---|---|
| 이용자가 고치는 것 | **이름(표시명)** 과 **비밀번호** 둘뿐 |
| 안 고치는 것 | 이메일(메일 왕복이 되돌아온다) · 가게 정보(생성 파이프라인과 엮인다) |
| 상단 우측 | **크레딧 잔액 + 이름 버튼 → 드롭다운(마이페이지·로그아웃)** |
| 사이드바 | 로그아웃 버튼과 **크레딧 상자를 뺀다** |
| 마이페이지 | `/me` 한 장. 보관함은 **흡수하지 않고 링크로 잇는다** |
| 이름 저장 | `profiles.display_name` (신규 컬럼) |

### 왜 보관함을 흡수하지 않나

**보관함은 이미 회원별로 갈려 있다.** `listProjects(ownerId)` 가 `requireOwner` 로 소유자를
필수 인자로 요구한다(`lib/projects.js:88`). 즉 "회원별 페이지"의 절반은 이미 있다.
잘 도는 화면을 옮기면 회귀 위험만 생기므로, 마이페이지는 **"내 영상 N편 → 보관함 열기"**
한 줄로 잇기만 한다.

## 화면

### 상단 계정 바 — `components/UserMenu.jsx` (신설)

`.belt` 은 지금 BETA 안내만 가운데 있고 **우측이 비어 있다**(`app/globals.css:49`,
높이 42px sticky). 그 오른쪽에 붙인다.

```
┌────────────────────────────────────────────────┐
│  BETA  시험 서비스 — 대본부터…   크레딧 85.18 │ 윤재찬 ▾ │
└────────────────────────────────────────────────┴─────────┘
                                                  │ 마이페이지 │
                                                  │ 로그아웃   │
                                                  └───────────┘
```

- 이름이 없으면 **이메일의 `@` 앞부분**을 보여준다(빈 버튼이 생기지 않게)
- 드롭다운은 **바깥 클릭·Esc 로 닫힌다.** 버튼에 `aria-expanded`·`aria-haspopup="menu"`
- 로그아웃 로직은 `Sidebar.jsx` 의 `handleLogout` 을 **그대로 옮긴다**(새로 쓰지 않는다)
- ⚠️ **`.belt` 이 지금 `justify-content: center` 다.** 우측 묶음을 그냥 더하면 BETA 문구가
  왼쪽으로 밀린다 — 좌/중/우 3영역으로 바꾸되 **BETA 는 화면 가운데를 유지**한다

로그인·승인대기 화면에는 **자동으로 안 나온다** — `AppShell` 이 `isBarePath` 로 이미
갈라서 `.belt` 자체를 안 그린다(`components/AppShell.jsx:23`). 손댈 것이 없다.

### 마이페이지 — `app/me/page.js` (신설)

```
내 정보
  이름     [ 윤재찬            ] [저장]
  이메일   jaechan@…            (바꿀 수 없어요)
  가입일   2026-08-03

비밀번호 변경
  현재 [……]  새 [……]  확인 [……]   [바꾸기]

내 영상 12편                        → 보관함 열기
```

middleware `matcher` 가 이미 전 경로를 덮으므로 **경로 설정이 필요 없다.**
`PUBLIC_PATHS`·`BARE_PATHS` 도 손대지 않는다 — `/me` 는 공개도 아니고 사이드바도 있다.
승인 대기자는 기존 규칙대로 `/pending` 으로 튕긴다(정상).

### 사이드바에서 빼는 것

로그아웃 버튼(`Sidebar.jsx:116-118`)과 크레딧 상자(`:120-128`), 그리고 그것이 쓰던
`/api/credits` fetch(`:70-78`)를 뺀다. **"설정 준비 중" 버튼은 그대로 둔다** — 앱 설정은
계정 정보와 다른 것이라, 지금 합치면 나중에 다시 갈라야 한다.

## 데이터

### `profiles.display_name`

```sql
alter table profiles add column if not exists display_name text;
```

`db/schema.sql` 에 넣는다. 이 파일은 **통째로 다시 올려도 안전**해야 하므로
`add column if not exists` 를 쓴다(기존 규약과 같다).

**왜 `app_metadata` 가 아닌가** — 이 저장소는 `profiles` 가 원장이고 `app_metadata` 는
middleware 가 매 요청 읽는 **게이트용 캐시**다(`middleware.js:119`). 이름은 게이트가
아니므로 metadata 에 둘 이유가 없고, 두면 `status`·`role` 처럼 **이중 쓰기를 지켜야 하는
자리**가 하나 더 는다(그 순서를 틀려 "원장은 승인인데 게이트는 대기" 가 되는 사고를
승인 라우트 주석이 이미 경고하고 있다).

### 스토어 — 양쪽 다 고친다

`lib/store/supabase.js` 와 `lib/store/memory.js` **둘 다**(테스트는 memory 를 쓴다).

| 무엇 | 지금 | 바뀐 뒤 |
|---|---|---|
| `findProfiles` | `id, email, role, status` | **`display_name`·`created_at` 추가** |
| `countProjects(ownerId)` | 없음 | **신설** |

**`listProjects().length` 를 세면 안 된다** — 그 쿼리에 `.limit(100)` 이 있어
(`lib/store/supabase.js:170`) 영상이 100편을 넘는 이용자에게 **조용히 틀린 숫자**를
보여준다. supabase 쪽은 `select("id", { count: "exact", head: true })` 로 센다.

## 라우트 셋

모두 `withUser` 로 감싼다(승인 대기자는 403 — 기존 계약과 같다).

### `GET /api/me`

```json
{ "email": "…", "name": "윤재찬", "created_at": "…", "balance": 85.18, "gated": true, "projectCount": 12 }
```

상단바와 마이페이지가 **같은 라우트 하나**를 쓴다. 이름과 크레딧을 따로 부르면 왕복이
두 번이 된다. `balance`·`gated` 는 기존 `/api/credits` 와 **같은 계산을 재사용**한다
(`balanceFor` · `!fakeFal()`).

> ⚠️ `gated` 는 "잔액 부족"이 **아니라** "크레딧 게이트가 켜져 있음"이다. 실모드면 잔액과
> 무관하게 항상 `true`. 화면이 잔액을 판정할 때는 `gated && balance < 가격` 으로 본다.

`GET /api/credits` 는 **남긴다** — `QuickCreate` 등이 이미 쓰고 있고, 이번 작업의 범위가
아니다.

### `PATCH /api/me`

`{ name }` 만 받는다.

- 앞뒤 공백 제거. **빈 문자열이면 `null` 로 저장**한다(이메일 폴백으로 돌아간다)
- 길이 상한 **20자**. 넘으면 400
- 그 외 필드는 **무시한다** — `status`·`role` 이 몸통으로 들어와도 절대 반영되지 않게
  화이트리스트로 뽑는다(권한 상승 자리)

### `POST /api/me/password`

`{ current, next }`.

1. `next` 가 6자 미만이면 400 (`MIN_LENGTH` 는 운영자 재설정 라우트와 같은 값)
2. **현재 비밀번호를 재검증한다** — `signInWithPassword({ email, password: current })`
3. 통과하면 service_role 의 `admin.updateUserById(id, { password: next })`
4. 감사 로그 한 줄. **비밀번호 자체는 절대 남기지 않는다**(운영자 라우트와 같은 규칙)

> ★ **왜 재검증이 필요한가** — Supabase 의 `updateUser({ password })` 는 **현재 비밀번호를
> 묻지 않는다.** 세션만 살아 있으면 바뀐다. 그대로 열면 이용자가 자리를 비운 사이 누군가
> 비밀번호를 바꿔 **계정을 통째로 뺏을 수 있다.**

> ★ **재검증이 현재 세션을 흔들면 안 된다** — `signInWithPassword` 를 쿠키에 붙은
> 클라이언트로 부르면 세션 쿠키를 덮어쓴다. 재검증은 **`persistSession: false` 로 만든
> 별도 클라이언트**로 하고, 그 결과는 버린다. 실제 변경만 service_role 로 한다.
> (매직링크 시절 middleware 가 공개 경로에서 쿠키를 건드려 PKCE verifier 를 지운 사고와
> 같은 계열이다 — 인증 쿠키는 의도한 자리에서만 만진다.)

**실패 문구는 원인을 알려준다** — 현재 비밀번호가 틀리면 401 `"현재 비밀번호가 맞지
않아요"`. 로그인 라우트의 한 문구 계약(계정 열거 차단)은 **여기 적용되지 않는다**:
이미 로그인한 본인의 계정이라 숨길 대상이 없고, 숨기면 이용자가 무엇을 고쳐야 할지 모른다.

## 테스트

이 저장소에 React 렌더 테스트가 없다 — 화면 배선은 **소스를 읽어 판정**한다
(`tests/credits-ui.test.js` 선례).

| 무엇 | 붙잡는 것 |
|---|---|
| **`credits-ui.test.js` 이전** | `:21` 의 "**사이드바**가 잔액을 읽는다" 를 **상단바**로 옮긴다. 지우지 않는다 — 크레딧이 화면에서 조용히 사라지는 회귀를 계속 막아야 한다 |
| 상단바 | 로그아웃·마이페이지 링크가 있다 · 사이드바에는 **더 이상 없다** |
| `GET /api/me` | 승인자는 200 + 여섯 필드 · 승인 대기자는 403 |
| `PATCH /api/me` | 이름이 저장된다 · 공백만 넣으면 `null` · 21자는 400 · **`role` 을 실어 보내도 안 바뀐다** |
| `POST /api/me/password` | 바뀐다 · **현재 비밀번호가 틀리면 401 이고 비밀번호가 안 바뀐다** · 6자 미만 400 |
| 스토어 | `countProjects` 가 소유자별로 센다 · `findProfiles` 가 `display_name`·`created_at` 을 준다 |

## 범위 밖

- **이메일 변경** — 확인 메일 왕복이 필요해, 매직링크를 걷어낸 이유를 뒷문으로 되돌린다
- **가게 정보(가게명·업종)** — 생성 파이프라인과 엮여 범위가 커진다
- **비밀번호 변경 후 다른 기기 세션 강제 종료** — 지금은 기존 세션이 남는다
- **운영자용 회원 상세 페이지**(`/admin/users/[id]`) — 이번 요청은 이용자 쪽이다
- **`GET /api/credits` 정리** — 다른 화면이 쓰고 있어 남긴다
