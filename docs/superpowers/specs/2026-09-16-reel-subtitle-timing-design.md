# 단계별(reel) 자막 시각 재설계 — 소리를 재서 맞춘다

- 날짜: 2026-09-16
- 범위: **단계별(reel) 통짜 영상만.** 원클릭 광고·film·legacy·컷별 갈래는 **건드리지 않는다**
- 배경 신고: 사장님 — *"V라인 리프팅 디바이스 영상이 자막이 하나도 안 맞아"*, 이어서 *"얼추 맞는데 조금 일찍 뜬다"*

## 1. 문제

자막 글자는 원고(`cuts[0].video.said`)를 쓰고, **시각만** 소리에서 잰다. 그 재는 방법이 틀렸다.

| 증상 | 뿌리 |
|---|---|
| 두 번째 문장부터 자막이 통째로 밀린다 | whisper `segment` 조각을 **문장과 1:1 순서로** 짝지었다. 조각은 쉼표에서도 끊겨 개수가 다르다 (2026-09-15 수정, 미배포) |
| 남은 문장이 **최대 2.8초 일찍** 뜬다 | whisper 조각 경계가 **연속**이라(앞 조각 끝 = 다음 조각 시작) 문장 사이 쉼이 다음 문장 시작에 붙는다 |
| 자막이 말보다 먼저 사라진다 | 표시 시간이 `min(잰 말 길이, 화면 시간)`이라 잘못 잰 값이 그대로 짧은 자막이 된다 |
| 못 재면 자막이 영상 끝까지 늘어진다 | 폴백이 **영상 전체 길이**에 글자 비례로 펼친다 (말이 13.6초에 끝나도 15초까지) |
| 모델이 원고와 다르게 말해도 아무도 모른다 | `Says exactly` 는 약속일 뿐이고, 받아쓴 글자를 **버려서** 대조할 자료가 없다 |
| 틀린 시각이 영원히 남는다 | `reel.narration_timing` 을 지우는 곳이 자막 글자 수정(`putSaid`) **한 곳뿐**이다. 다시 굽기·`attach` 는 안 지운다 |

## 2. 실측 (2026-09-15~16, 운영 영상 2편)

실제 말 시작은 ffmpeg 로 잰 값이다(음성 대역 300~3400Hz, 0.05초 창, 배경음 때문에 ±0.1~0.2초 오차).

| 문장 | 지금(whisper segment) | whisper word | **Scribe v2 word** |
|---|---|---|---|
| 3856b99d ① | -0.04 | -0.04 | **+0.10** |
| 3856b99d ② | -2.32 | -2.75 | **+0.09** |
| 115387f3 ② | -0.40 | -0.30 | **+0.29** |
| 115387f3 ③ | -0.98 | -0.86 | **+0.11** |

- ★ **whisper 는 낱말 단위로 바꿔도 낫지 않는다.** 쉼이 다음 문장 **첫 낱말**에 통째로 들어간다 — "하루"(2글자)가 `7.50~10.28`(2.78초)로 기록됐다. 성질이 같고 범위만 좁아진다.
- ★ **Scribe v2 는 낱말 사이 쉼을 빈 구간으로 남긴다** — `…"밴드." 7.26` 다음이 `10.34 "하루"` 다. 그래서 문장 시작이 맞는다.
- Scribe 는 받아쓴 글자도 준다("벤트가", "갸늘한", "브이라인"). **대조 자료가 공짜로 생긴다.**
- 비용: whisper $0.0006/초(15초 $0.009) → **Scribe $0.008/분(15초 $0.002)**. 더 싸다.

조사 근거(2026-09-16): fal `elevenlabs/speech-to-text/scribe-v2` 는 `words[]{text,start,end,type}` 을 준다.
mp4 는 안 받고 오디오 포맷만 받는다(422 `unsupported_audio_format`). 정렬 도구 일반 성질로 **드물게 수 초씩 어긋나는 이상치**가 보고돼 있어(대화체 WhisperX 평균 11.7초 / 중앙값 30ms) **코드가 이상치를 걸러야 한다.**

## 3. 목표 / 비목표

**목표**
1. 문장 시작 오차 **±0.3초 이내**(측정으로 확인한다)
2. 잘못 잰 값이 조용히 쓰이지 않는다 — 코드가 판정하고, 걸리면 그 문장만 폴백
3. 다시 구우면 시각을 다시 잰다
4. 모델이 원고와 크게 다르게 말하면 사장님이 **안다**

**비목표 (이번에 안 한다)**
- 원클릭 광고·film 의 자막 시각(계획 초 방식 유지) · legacy · 컷별 갈래
- 내레이션 TTS 분리, 립싱크 — 화면 안 대사 연출을 못 하게 되므로 이번 설계에서 제외
- 자막을 굽지 않고 재생 화면에 겹치는 구조
- 자막 번역(`subtitle_lang` 을 골라도 한 벌 내레이션은 원문이 나가는 문제) — 별건으로 남긴다
- LLM 으로 받아쓴 글자와 원고를 대조하는 판정 — 4.6 의 코드 판정을 먼저 쓰고, 부족하면 후속

## 4. 설계

### 4.1 흐름 (⑥완성 라우트 안)

```
① 자막 원본 확정      bakedNarration → splitSentences        (기존)
② 소리 추출          ffmpeg -vn -c:a copy → /tmp/<id>.m4a     (신규, 0원)
③ 낱말 시각 측정      fal scribe-v2 (data URI)                (신규, whisper 대체)
④ 낱말 → 문장 묶기    alignSpeech (글자 수 기준)               (2026-09-15 구현분)
⑤ 검증·이상치 제거    코드 판정 → 걸린 문장만 폴백             (신규)
⑥ 리드인 적용        시작 -0.15초                            (신규)
⑦ 합성·자막 굽기      composeVideo                            (기존)
⑧ 대조 경고          받아쓴 글자 vs 원고                      (신규, 문제 있을 때만)
```

### 4.2 모듈 경계

| 파일 | 역할 | 변경 |
|---|---|---|
| `lib/speech-probe.js` | **소리 → 낱말 시각**. 엔드포인트·요청·원장 기록 | Scribe 로 교체, 반환에 `words`·`text` 포함 |
| `lib/speech-audio.js` (신규) | mp4 → 오디오 추출(로컬 ffmpeg) + data URI | 신규. `lib/compose.js` 의 ffmpeg 실행부를 재사용하되 **합성과 섞지 않는다** |
| `lib/speech-timing.js` | 낱말 ↔ 문장 묶기, **검증·이상치 판정** (리드인은 여기서 안 건다 — 4.6) | 검증 추가(묶기는 구현됨) |
| `lib/reel/narration.js` | 저장된 시각을 문장 단위에 얹기 | 저장 자리 이름·모양 확장 |
| `app/api/reel/[id]/render/route.js` | 순서 오케스트레이션 | ②③⑤⑥⑧ 배선 |
| `lib/reel/pipeline.js` | 다시 굽기·`attach` 시 **시각 무효화** | 무효화 한 줄씩 |
| `lib/subtitles.js` | 리드인 상수와 적용(`buildCues`) | 상수 한 줄 + 시작 시각에 반영 |
| `lib/costs.js` | Scribe 단가 | 표에 한 줄 |

★ 측정(`speech-probe`)·묶기(`speech-timing`)·추출(`speech-audio`)을 **셋으로 나눈다.** 측정 제공자는 바뀔 수 있고(Scribe → 강제 정렬), 묶기·검증은 제공자와 무관하게 같은 규칙이어야 한다.

### 4.3 데이터

```js
project.reel.speech = {
  at: 1789...,                 // 측정 시각 — 클립보다 오래됐는지 코드가 본다
  source: "scribe-v2",         // 제공자. 나중에 강제 정렬로 바뀌면 이 값이 바뀐다
  lead: 0.15,                  // 적용한 리드인
  units: [                     // 문장 수와 길이가 같다
    { start: 1.15, seconds: 6.11, ok: true },
    { start: 10.19, seconds: 3.45, ok: true },
    // ok:false 면 start/seconds 는 null 이고 그 문장은 비례 폴백으로 흐른다
  ],
  heard: { chars: 33, text: "턱선을 감싸는 …" },  // 대조용. 자막에는 쓰지 않는다
};
```

- 옛 `reel.narration_timing` 은 **읽기만** 유지한다(옛 편 회귀 0). 새 측정이 생기면 `speech` 가 이긴다.
- `units[i].ok === false` 는 "재 봤는데 못 믿는다"는 뜻이고, `speech` 자체가 없으면 "아직 안 쟀다"는 뜻이다. **둘을 구분한다** — 전자는 다시 재도 같은 결과일 가능성이 높다.

### 4.4 측정 (③)

- 엔드포인트 `fal-ai/elevenlabs/speech-to-text/scribe-v2`, 입력 `{ audio_url: data URI, language_code: "ko" }`
- 언어는 `speechLangOf(project)` 를 넘긴다 — 지금 whisper 호출은 언어를 안 넘겨 자동 감지에 맡기고 있다
- `type === "word"` 인 항목만 쓴다(`spacing`·`audio_event` 는 버린다)
- 실패·429·타임아웃이면 **던지지 않고 빈 목록** — 자막 하나 때문에 이미 값을 다 치른 한 편을 잃지 않는다(기존 규율 유지)
- 원장에 기록한다. `lib/costs.js` 에 `{ prefix: "fal-ai/elevenlabs/speech-to-text", perSec: 0.000133 }`($0.008/분)

**오디오 추출(②)**: `-vn -c:a copy` 로 재인코딩 없이 뽑는다(실측 15초 0.36MB, 1초 미만). base64 가 6MB 를 넘으면 측정을 건너뛰고 폴백한다 — 긴 영상이 생겼을 때 요청이 조용히 죽는 것을 막는 상한이다.

### 4.5 검증과 이상치 (⑤) — 임계값은 실측에서 뽑았다

문장 단위로 판정하고, 걸린 문장만 `ok:false` 로 떨군다.

| 판정 | 규칙 | 근거 |
|---|---|---|
| 순서 | 앞 문장 끝 ≤ 다음 문장 시작 | 뒤집히면 자막이 겹친다 |
| 범위 | `0 ≤ start`, `end ≤ 영상 길이` | 실측 15초 영상에 18·24초 자막이 생긴 전례(2026-08-25) |
| 낱말 길이 이상치 | 낱말 길이 > `글자수 / 5.5 × 3` 이면 그 낱말이 **쉼을 머금었다**고 본다 | 정상 최장 실측 2.3배("올리고" 1.28초/3글자), 병리적 7.6배(whisper "하루" 2.78초/2글자). 그 사이를 잡았다 |
| 들은 양 | 받아쓴 글자 수 ÷ 원고 글자 수가 0.75~1.5 밖이면 **전체** 버린다 | 발음 차이는 실측 +2~3%. 4분의 1 넘게 못 들었으면 다른 말이다 |

`CHARS_PER_SEC`(5.5)는 `lib/script.js` 의 값을 그대로 쓴다 — 여기서 다시 적지 않는다.

### 4.6 리드인 (⑥)

시작에서 **0.15초**를 뺀다(0 미만이면 0). 근거: Scribe 실측이 실제 발화보다 +0.09~+0.29초 **늦다**. 편집 통상값(0.1~0.2초)과도 맞다.

★ **거는 자리는 `lib/subtitles.js` 의 `buildCues` 하나다** — 잰 값(`reel.speech`)에는 리드인을 섞지 않는다. 저장된 값은 "모델이 실제로 말한 때"여야 나중에 리드인을 바꿔도 다시 재지 않고, 대조·검증도 같은 자로 할 수 있다. 상수도 그 파일에 둔다(화면·라우트가 모르게 한다).

### 4.7 무효화 (C1·C2)

`reel.speech` 를 지우는 자리:
- 통짜 굽기 접수(`runReelOneShot`) · 수거 완료(`collectReelOneShot`) · 운영자 `attachReelVideo`
- 자막 글자 수정(`putSaid`, 기존)

즉 **소리가 바뀌면 시각을 버린다.** 다음 완성에서 다시 잰다(편당 $0.002).

### 4.8 대조 경고 (⑧)

코드만으로 판정한다(LLM 없이). 아래 중 하나면 완성 화면에 경고와 [자막 글자 수정하기] 를 띄운다.
- 낱말이 하나도 안 묶인 문장이 있다 → "말하지 않은 문장이 있어요"
- 들은 양이 0.75 미만 → "영상 속 말이 원고보다 짧아요(잘렸을 수 있어요)"

경고는 **막지 않는다.** 완성본은 그대로 나오고, 사장님이 고칠지 정한다. 문구는 들은 글자를 함께 보여 준다 — 근거 없는 경고는 무시하게 된다.

### 4.9 폴백 (A5 개선)

측정이 없거나 `ok:false` 인 문장은 글자 비례로 흐르되, 기준 총 길이를 **영상 길이**가 아니라 **측정된 말 구간**(첫 낱말 시작 ~ 마지막 낱말 끝)으로 쓴다. 측정 자체가 없으면 지금처럼 영상 길이를 쓴다(회귀 0).

## 5. 오류 처리 요약

| 상황 | 동작 |
|---|---|
| 추출 실패·오디오 없음 | 측정 건너뜀 → 비례 폴백, 완성은 계속 |
| Scribe 실패/한도 초과 | 같음. 원장에 기록 없음 |
| 일부 문장만 이상 | 그 문장만 비례, 나머지는 측정값 |
| 자막이 꺼진 프로젝트 | 측정 자체를 하지 않는다(지출 0) |
| 가짜 모드 | 호출 없음(기존 `fakeFal()` 규율) |

## 6. 테스트

- **묶기**(구현됨): 쉼표 조각, 조각 하나에 두 문장, 글자 없음, 들은 양 이상 — `tests/speech-timing.test.js`
- **검증**: 순서 역전·범위 초과·낱말 길이 이상치·들은 양 이상 → 해당 문장만 `ok:false`
- **리드인**: 0.15초 적용, 0 미만 방지, 상수 한 곳
- **무효화**: 굽기·수거·attach 각각에서 `reel.speech` 가 사라진다
- **라우트 배선**: 측정 실패에도 합성이 계속된다 / 자막이 꺼져 있으면 측정하지 않는다 / 가짜 모드에서 호출 0
- **원장**: Scribe 단가가 표에 있고 기본가로 떨어지지 않는다(`merge-audios` 가 $1.7 로 찍힌 전례)
- **실측 검증(배포 후)**: 두 편을 다시 합성해 ffmpeg 로 잰 실제 말 시작과 비교. **±0.3초 안**이어야 채택으로 본다

## 7. 남은 것 / 후속

- 원클릭·film 은 계획 초 방식 그대로다. 같은 장치를 쓰게 할지는 이 구조가 자리 잡은 뒤에 판단한다
- 배경음이 크면 정렬이 흔들린다. `fal-ai/elevenlabs/audio-isolation`(mp4 직접 입력, $0.1/분)을 보조로 붙일 수 있다 — **지금은 안 넣는다**(필요한지 아직 모른다)
- 잔차가 ±0.3초를 못 맞추면 **강제 정렬**(ElevenLabs Forced Alignment, 원고를 정답으로 준다, ~$0.0037/분, 파일 업로드 전용·새 키)로 올린다. `speech.source` 가 그 교체를 받아 준다
- 자막 번역(`subtitle_lang`)이 한 벌 내레이션에서 조용히 원문으로 나가는 문제
- 받아쓴 글자와 원고의 **의미 차이** 판정(LLM 대조) — 코드 판정으로 못 잡는 "다르게 말했다"를 잡으려면 필요하다. 단 이 저장소는 LLM 검수가 조용히 통과만 시킨 전례가 있어(VLM 9회) 근거를 함께 받는 형태로만 넣는다
