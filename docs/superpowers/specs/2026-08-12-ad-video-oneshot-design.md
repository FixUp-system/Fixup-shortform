# 광고 영상 한 방 만들기 — 프롬프트 하나로 15초 CF

> 2026-08-12 · **기존 6단계와 `/auto` 옆에 나는 제3의 경로.** 기존 시스템은 손대지 않는다.

## 무엇을 만드나

CF·브랜드·제품 홍보 쇼츠를 **옵션 고르기 + 프롬프트 + 사진 첨부** 한 번으로 만든다.
컷 분할·이미지 생성·낭독·합성이 없다. LLM 이 시나리오를 쓰고, fal 의 Seedance 가
**영상과 소리를 한 번에** 만든다.

### 사장님이 겪는 것

```
① 옵션 고르기       길이 15초(고정) · 비율 · 나레이션 언어 · 포맷 · 화풍 · 분위기
② 프롬프트 + 사진   글 + 사진 0~4장
        ↓  [시나리오 만들기]   ← LLM 만. ~$0.01. 몇 번이든 공짜
③ 시나리오 카드     장면별 앵글·카메라·액션·분위기·대사가 보인다
        ↓  [이대로 만들기]     ← ★ 여기서 크레딧이 나간다 (65)
④ 만드는 중         폴링
⑤ 완성              mp4 재생·내려받기
```

비싼 문이 **하나**이고, 그 앞에 **싼 문**이 있다. ③에서 되돌리는 것은 공짜다.

## 왜 이 구조인가 — 씬 연속성 고민이 사라진 이유

처음 고민은 "60초를 만들려면 씬을 4~15개로 나눠야 하는데, 이어붙였을 때 연속성이
유지되는가"였다. **이 고민은 Seedance 2.0(15초 상한)을 전제한 것이었다.**

fal 문서 확인 결과:

- **Seedance 2.5 는 한 번의 생성 안에서 멀티샷을 한다.** 캐릭터·제품·의상·화풍을
  유지한 채 샷 전환까지 모델이 처리하고, 오디오도 영상과 함께(따로 붙이는 것이 아니라)
  만든다. 최대 30초 단일 패스이고 "multiple rounds of extension" 을 지원한다
- 즉 **우리가 컷을 나눌 필요가 없다.** 15초는 클립 1개, 30초도 클립 1개다.
  이어붙임 문제는 45·60초에서 **처음** 생긴다

| 목표 길이 | 우리가 만드는 클립 수 | 모델 |
|---|---|---|
| 15초 | **1개** | 2.0 또는 2.5 |
| 30초 | **1개** | 2.5 |
| 45·60초 | 2개 (또는 extension) | 2.5 |

v1 을 15초로 고정하는 근거가 바뀐다: "짧아서 안전"이 아니라 **"컷이 하나라 이어붙일
것이 없어서"** 다.

> 60초는 2.5 의 **extension(이어 생성)** 이 우리 이어붙임보다 나을 가능성이 크다.
> 다만 fal 이 그것을 API 파라미터로 여는지는 **확인하지 못했다**(아래 "아직 모르는 것").

## 정한 것과 그 이유

| 결정 | 값 | 이유 |
|---|---|---|
| 기존 시스템과의 관계 | **제3의 새 경로** | 기존 사용자·기존 프로젝트가 무사하고, 실패해도 되돌리기 쉽다 |
| 자막 | **v1 없음** | 네이티브 오디오를 쓰면 "모델이 실제로 뭐라 했는지"를 우리가 모른다. 자막을 넣으면 어긋날 수 있고, 어긋난 것을 판정할 방법이 없다. 안 넣으면 그 결함 자체가 안 생긴다 |
| 오디오 | **Seedance 네이티브** | fal 이 지원한다. 기존 TTS·ffmpeg 합성은 이 경로에서 안 쓴다 |
| 모델 | **Seedance 2.0 fast · 720p** | 15초 $3.63. 지금 30초 한 편($3.06)과 같은 자릿수라 크레딧 표를 크게 안 흔든다 |
| 엔드포인트 | **백엔드 자동 배치** | 사장님은 사진만 올린다. 어느 엔드포인트인지는 우리 일이다 |
| 시나리오 게이트 | **보여주고 승인받는다** | 한 번이 $3.63 이다. 시나리오 되돌리기는 공짜라, 싸게 고치고 비싸게 굽는다 |
| 재생성 | **매번 정가 재청구** | 원가가 그대로 또 나간다. 마진이 안 샌다 |
| 저장 위치 | **같은 `projects` 테이블, `doc.kind = "ad"`** | 소유자 격리·낙관적 락·직렬 큐·멱등 청구·원장·actor 를 그대로 쓴다. 새 테이블은 이것을 한 벌 더 만드는 일이고, 그러면 저장 계층 통째로 "두 벌이면 갈린다"가 된다 |

## 값 — 모델과 원가

fal 실측 단가(2026-08-12 문서 확인):

| 모델 | 엔드포인트 | 720p 초당 | 15초 |
|---|---|---|---|
| **2.0 fast** ← v1 | `bytedance/seedance-2.0/fast/{text\|image\|reference}-to-video` | **$0.2419** | **$3.63** |
| 2.0 standard | `bytedance/seedance-2.0/{…}` | $0.3034(t2v) · $0.3024(i2v·r2v) | $4.54 |
| 2.5 | `bytedance/seedance-2.5/{…}` | ≈$0.462 (계산값) | ≈$6.93 |

- 2.5 는 **초당 단가가 아니라 토큰식**이다: `tokens = (h × w × 초 × 24) / 1024`,
  1000토큰당 $0.0214. 9:16 720p(720×1280) 로 계산한 값이 위 숫자다.
  **해상도가 원가를 정한다** — 480p 면 절반 아래로 떨어진다
- reference-to-video 에 **영상 파일**을 참조로 넣으면 0.6배 할인이 있다(standard 기준 $0.1814/s)
- 오디오는 가격에 포함이다. `generate_audio` 를 꺼도 값은 같다

### 크레딧 정가

1크레딧 ≈ 원가 $0.06 기준(`lib/pricing.js` 의 기존 환산과 같다).

| 항목 | 크레딧 | 근거 |
|---|---|---|
| 광고 영상 15초 | **65** | 원가 $3.63 (약 8% 여유) |
| 시나리오 만들기·다시 쓰기 | **0 (무료)** | LLM 만 ~$0.01 |
| 재생성 | **65** (매번 정가) | 원가가 그대로 또 나간다 |

⚠️ 시나리오 다시 쓰기가 무료·무제한이면 원가가 조금씩 샌다.
**프로젝트당 20회 상한**을 건다(`MAX_REGEN_PER_CUT` 과 같은 성격의 안전핀). 넘으면 400.

값은 전부 `lib/pricing.js` 에 **덧붙인다.** 기존 `VIDEO_PRICE`·`REGEN_PRICE` 는 손대지 않는다.

## 데이터

### 문서 모양 — `projects` 테이블, `doc.kind = "ad"`

```js
{
  id, kind: "ad", created_ts,
  status: "draft" | "scenario" | "rendering" | "done",

  settings: {
    seconds: 15,                    // v1 은 15만 받는다(닫힌 목록)
    aspect_ratio: "9:16",
    narration_lang: "ko",
    format:  "unboxing",            // 광고 포맷  ┐
    style:   "photo",               // 화풍       ├ 세 축
    mood:    "premium",             // 분위기     ┘
    model:   "seedance-2.0-fast",   // ★ 만들 때 명시 저장
  },

  material: { text: "사장님이 쓴 글", photos: [{ url, ... }] },
  scenario: { text, shots: [...], endpoint: "reference-to-video", tries: 0 },
  videos: [{ url, seconds }],       // ★ 배열. v1 은 길이 1만 허용
  video_error: null,
}
```

★ **`model` 을 만들 때 명시 저장한다.** 나중에 2.5 를 붙일 때 "값이 없으면 어느 모델로
볼 것인가"가 옛 문서의 뜻을 바꾼다. `2026-08-12-i2v-model-selection-design.md` 가 이미
그 함정을 적어 뒀다 — 같은 실수를 처음부터 안 하는 쪽이 싸다.

★ **`videos` 는 배열이다.** 60초에서 스키마가 안 바뀐다. 다만 **v1 은 코드가 길이 1을
강제한다** — 열어두고 안 지키면 조용히 깨진다.

★ **`seconds` 필드는 지금부터 둔다.** 값은 15만 받는다.

### 상태 전이

```
draft ──시나리오 생성──▶ scenario ──승인·청구·fal──▶ rendering ──▶ done
  ▲                         ▲                          │
  └─ 옵션·프롬프트 수정 ─────┘                          │
                            └────── 실패: 환불 ─────────┘
```

- 옵션이나 프롬프트를 고치면 **`scenario` 를 버리고 `draft` 로 되돌린다.**
  낡은 시나리오로 굽는 길을 아예 막는다(낡음 판정을 새로 만들 필요가 없다)
- `done` 뒤에 또 만들면 새 회차다. `charges.js` 의 회차 셈을 그대로 쓴다

### 옵션 값 — 세 축 (초안)

⚠️ **아래 문구는 초안이다.** `lib/styles.js` 의 프리셋이 그랬듯, 실제 결과를 나란히 보고
확정한다. 측정 없이 품질을 주장하지 않는다.

**포맷** (`format`) — 시나리오의 뼈대. LLM 이 이 틀에 맞춰 15초를 짠다. 가장 크게 작용하는 축이다.

| id | 라벨 | 15초 구성 |
|---|---|---|
| `hero` | 제품 히어로 | 제품을 주인공으로 — 등장 → 클로즈업 → 사용 → 마무리 |
| `unboxing` | 언박싱 | 손이 상자를 연다 → 꺼낸다 → 첫인상 |
| `before_after` | 비포·애프터 | 문제 상황 → 전환 → 달라진 결과 |
| `story` | 브랜드 스토리 | 장면 몇 개로 분위기를 쌓고 로고로 닫는다 |
| `testimonial` | 사용 후기 | 사람이 말한다 — 나레이션이 주인공 |

**화풍** (`style`) — `lib/styles.js` 의 id 를 **재사용한다**(`photo`·`illust`·`anime`·`studio`…).
⚠️ 다만 `medium`·`finish` 문구는 **이미지 프롬프트용으로 쓰인 말**이다
("High-quality photographic still"). 영상 프롬프트에 그대로 실으면 어색하다 —
`lib/ad/options.js` 가 **영상용 문구를 따로 든다.** id 만 공유하고 문구는 갈라 둔다.

**분위기** (`mood`) — 음악·조명·편집 속도에 작용한다.

| id | 라벨 |
|---|---|
| `bright` | 밝고 경쾌한 |
| `premium` | 고급스러운 |
| `dynamic` | 역동적인 |
| `warm` | 감성적인 |

**나레이션 언어** (`narration_lang`) — v1 은 `ko`·`en` 둘. 프롬프트에 명시해서 넘긴다
(별도 파라미터가 있는지는 확인하지 못했다 — 아래 "아직 모르는 것").

**비율** (`aspect_ratio`) — `lib/aspects.js` 의 목록을 **그대로 재사용한다**(9:16·1:1·16:9).
새 표를 만들지 않는다.

| 파일 | 하는 일 | 의존 |
|---|---|---|
| `lib/ad/options.js` | 포맷·분위기·나레이션 언어 표. **순수 데이터** | 없음 |
| `lib/ad/models.js` | 모델 id → 엔드포인트 3종·길이·초당 원가. **순수 데이터** | 없음 |
| `lib/ad/scenario.js` | 옵션+프롬프트+사진 → 시나리오. LLM 호출·검증 | `llm.js` |

`fs` 가 딸려오면 번들이 깨진다 — `pricing.js`·`styles.js`·`aspects.js` 와 같은 규율이다.
이 저장소는 이 사고를 세 번 겪었다.

### 라우트

```
POST   /api/ads                옵션+프롬프트+사진 → draft 문서 생성
PATCH  /api/ads/[id]           옵션·프롬프트 수정 → scenario 버리고 draft 로
POST   /api/ads/[id]/scenario  시나리오 생성·다시 쓰기 (LLM 만, 무료, 20회 상한)
POST   /api/ads/[id]/render    ★ 승인. 여기서 청구하고 fal 을 띄운다
GET    /api/ads/[id]           조회
GET    /api/ads/[id]/status    폴링
```

`/render` 는 기존 유료 라우트와 **같은 모양**이다: 청구(동기) → fire-and-forget → 응답.
전부 `withUser` 로 감싼다. `middleware.js` matcher 가 `/api/*` 를 이미 덮으므로
신원 헤더는 그대로 들어온다.

### ★ 양방향 격리 — `kind` 설계의 전부

- 기존 라우트(`/api/projects/[id]/*`)가 `kind === "ad"` 문서를 받으면 **404**
- 새 라우트(`/api/ads/*`)가 `kind !== "ad"` 문서를 받으면 **404**

한쪽만 막으면 반대쪽으로 샌다. 이 저장소는 `/clips`·`/voice` 를 열어 둬서 환불된
프로젝트로 클립을 순지불 0 에 산 전례가 있다 — 같은 실패 모양이다. 테스트로 못 박는다.

## 자동 배치 — 코드가 먼저 좁힌다

```
사진 0장   → text-to-video       코드 고정. LLM 에 안 묻는다
사진 2장~  → reference-to-video  코드 고정. i2v 는 물리적으로 1장만 받는다
사진 1장   → LLM 이 i2v / r2v 중 하나를 고른다
             코드가 닫힌 목록으로 검증. 모르는 값 → r2v (안전한 쪽)
```

**값이 나가는 판정이라 LLM 에 통째로 맡기지 않는다.** 결정 지점을 한 곳(사진 1장)으로
좁히고 나머지는 코드가 정한다. 이 저장소의 규칙 — "지켜져야 하는 것은 프롬프트가 아니라
코드가 판정한다" — 를 그대로 적용한 것이다.

엔드포인트 문자열은 `lib/ad/models.js` **한 곳**에만 둔다.

> ⚠️ `image-to-video` 는 첫 프레임을 고정하므로 **멀티샷의 이점을 대부분 버린다.**
> 15초 내내 그 사진의 구도에 묶인다. 로고 한 장을 i2v 로 넣으면 "움직이는 로고"가 나오지
> CF 가 안 나온다. 실제로 i2v 가 이기는 경우는 "완성된 키비주얼 한 장을 살아 움직이게 할
> 때"뿐일 가능성이 크다. **실측에서 r2v 가 이기면 v1 에서 뺀다.**

## 사진을 fal 에 넘기는 법 — 기존 방식 그대로

업로드는 **비공개 버킷**이라 `/api/uploads/<name>` 을 fal 이 못 읽는다.
`generateImage` 가 이미 푼 문제다: `readRefBytes()` 로 바이트를 읽어 `toDataUri()` 로
넘긴다(`lib/refs-io.js`). 그대로 쓴다.

⚠️ **상한이 필요하다.** 사진 한 장이 10MB 까지 허용되는데 base64 는 1.33배로 분다.
9장이면 요청 본문이 100MB 를 넘는다. **v1 은 4장 · 합계 8MB 로 막는다** — 실측하고 올린다.
(reference-to-video 자체는 이미지 9장까지 받는다.)

## 반드시 고쳐야 하는 기존 파일 — 전부 덧붙이기만

| 파일 | 무엇을 | 왜 |
|---|---|---|
| **`lib/costs.js`** | `FAL_PREFIXES` 에 `"bytedance/"` | ★★ 안 하면 `SHOTFORM_FAKE=fal` 에서 **진짜 호출이 나간다.** 지금 `isFakeFor` 는 `fal-ai/` 가 아니면 전부 LLM 축으로 본다 — 0원인 줄 알고 돌린 테스트가 **$3.63을 쓴다** |
| `lib/costs.js` | `PRICE_TABLE` 에 seedance fast 단가 | 없으면 원가가 조용히 $0 으로 기록되고 전역 상한이 함께 무력해진다 |
| `lib/pricing.js` | 광고 영상 정가(새 표) | 가격은 이 파일 하나 |
| `lib/charges.js` | `adKey`·`chargeAd`·`refundAd` **추가** | 기존 함수는 한 줄도 안 고친다 |
| `lib/projects.js` | `createProject` 가 `kind` 를 받고, `listProjects` 요약이 `kind` 를 싣는다 | 목록 화면이 두 종류를 갈라 그린다 |
| `lib/store/{memory,supabase}.js` | 목록 요약에 `kind` | **store 계약은 두 벌이다.** 한쪽만 고치면 테스트는 통과하고 라이브가 깨진다 |
| `components/ProjectCards.jsx` | 카드에 종류 표시 | |

`db/schema.sql` 은 **안 건드린다.** `doc` 이 jsonb 통짜라 `kind` 는 그냥 필드다.

> ⚠️ `isFakeFor` 의 **판정 방향을 뒤집지 마라**(`openai/` 만 LLM 으로 보고 나머지를 fal 로
> 보는 것). 뒤집으면 모르는 엔드포인트가 fal 축으로 떨어져 `SHOTFORM_FAKE=fal` 에서
> `assertBudget` 게이트가 통째로 꺼진다. **접두사 목록만 넓힌다.**

## 청구와 환불

```js
adKey(projectId, attempt)  =  `ad:<pid>:<n>`   // 기존 `video:` 와 이름공간이 다르다
chargeAd({ userId, projectId })                // 회차·멱등키 규칙은 기존과 동일
refundAd({ projectId })                        // 지우지 않고 음수 행
```

- **청구는 fal 호출 전**이다. 잔액 없이 돈이 나가는 길을 안 만든다
- 실패하면 **환불**한다. 못 준 것은 안 받는다
- 두 번 눌러도 `unique(idem_key)` 가 한 번만 통과시킨다
- 환불 행의 주인은 **원 청구 행의 주인**이다(기존 `refundVideo` 와 같은 규칙)

## 실패가 어디로 보이는가

| 실패 | 사장님이 보는 것 | 응답 |
|---|---|---|
| 잔액 부족 | "크레딧이 모자라요" | **402**(동기) |
| 시나리오 LLM 실패 | 그 자리 오류. status 는 `draft` 그대로 | 500 |
| 시나리오 20회 초과 | "시나리오를 너무 많이 다시 썼어요" | 400 |
| 사진 상한 초과 | "사진은 4장까지 올릴 수 있어요" | 400 |
| fal 실패 | `video_error` + 환불 + status `scenario` 로 되돌림 | `/status` 로만 |
| 전역 상한·체험 한도 | `video_error` 에 문구가 실림 | `/status` 로만 |

아래 둘은 **fire-and-forget 이라 HTTP 로 옮길 수 없다.** 기존 `/images`·`/clips` 와 같은
제약이고 `withUser` 의 402/503 변환도 거기까지 안 닿는다.

## 결과 mp4 를 어디에 두나

**우리 `renders` 버킷으로 옮긴다.** fal 출력은 기본이 *publicly readable* 이라 URL 만
알면 누구나 본다. CLAUDE.md 가 이미 "입력은 잠그고 출력은 열어둔 셈"이라고 문제로 적어
두었는데, **미공개 캠페인 영상이면 위험이 훨씬 크다.**

기존 배선이 그대로 있다 — `renders` 버킷 + `/api/renders/<id>.mp4` 라우트.
내려받아 올리는 왕복 한 번만 는다(15초 720p 면 수 MB).

## ★ 기존 시스템을 안 건드린다는 보장 — 네 겹

말로만 하면 안 지켜진다.

1. **`kind` 없음 = 기존 종류.** 옛 문서에는 `kind` 가 없다. 반대로 두면(없으면 ad)
   기존 프로젝트 전체가 새 경로로 흘러간다 — `i2v_model` 설계가 똑같이 경계한 함정이다
2. **기존 파일 수정은 덧붙이기만.** 기존 분기의 동작을 바꾸는 수정은 없다
3. **관문은 기존 테스트다.** 착수 시점 실측 `npx vitest run` = **1334 passed / 10 skipped
   / 73 files passed / 2 skipped**. 하나라도 줄거나 깨지면 그 자리에서 멈추고 보고한다
   (숫자는 낡으므로 착수할 때 다시 센다)
4. **별도 브랜치. `main` 에 직접 쓰지 않는다.** 배포·PR 은 사용자가 요청할 때만

## 60초 확장을 위해 지금 해둘 것 — 구조만

| 지금 | 나중에 |
|---|---|
| `settings.seconds` — 값은 **15만** 허용 | 30·45·60 을 목록에 더하면 끝 |
| `settings.model` **명시 저장** | 2.5 를 더해도 옛 문서가 안 흔들린다 |
| `scenario.shots[]` 배열 | 장면을 여러 생성으로 쪼갤 때 그대로 쓴다 |
| `videos: [{url, seconds}]` 배열 — v1 은 길이 1 강제 | 60초에서 스키마가 안 바뀐다 |

## 어떻게 확인하나

- **격리(가장 중요)**: 기존 라우트에 ad 문서 → 404 · ad 라우트에 기존 문서 → 404 ·
  `kind` 없는 옛 문서가 기존 종류로 판정된다
- **★ 가짜 모드**: `isFakeFor("bytedance/…")` 가 fal 축인지.
  이 단정 하나가 `SHOTFORM_FAKE=fal` 에서 **$3.63 이 안 나간다는 증거**다
- **원가**: `PRICE_TABLE` 이 seedance 를 $0 이 아니게 센다
- **자동 배치**: 0장→t2v · 2장↑→r2v · 1장→닫힌 목록 · 모르는 값→r2v 폴백
- **돈**: 잔액 부족 402 · 성공 후 잔액이 65 줄고 · 실패 시 음수 행 · 두 번 눌러도 한 번
- **닫힌 목록**: 모르는 포맷·분위기·언어·비율·초 → 400 · 사진 4장/8MB 초과 → 400
- **상태**: 옵션을 고치면 `scenario` 가 버려지고 `draft` 로 돌아간다
- **전체**: `npx vitest run` 그린 유지

## 이번에 안 하는 것

- 자막
- 30·45·60초, Seedance 2.5
- `image-to-video` 를 뺄지 말지 — 실측 후에 정한다
- 판매가·마진 — 결제를 붙일 때 정한다
- 기존 6단계와 새 경로를 화면에서 어떻게 안내할지(진입 동선)
- fal 큐 API — 기존과 같이 `fal.run` + 우리 폴링으로 간다

## 지켜야 할 것

- **기존 시스템에 바로 적용하지 않는다.** 별도 브랜치, 덧붙이기만, 기존 테스트 그린이 관문
- 새 npm 의존성 금지. 새 CSS 금지(기존 `.chips`/`.chip` 등을 쓴다)
- `lib/ad/options.js`·`models.js`·`lib/pricing.js` 는 화면이 import 한다 — `fs` 의존 금지
- 가격 숫자를 라우트·화면에 흘리지 않는다. `lib/pricing.js` 하나다
- 모델 엔드포인트 문자열을 두 군데 두지 않는다. `lib/ad/models.js` 하나다
- `kind` 없음 = 기존 종류. 이 방향을 뒤집지 않는다
- **측정 없이 품질을 주장하지 않는다.** 유료 생성(fal)은 실행 전 반드시 사용자 승인
- **예상 못 한 실패는 고치지 말고 보고한다**

## 탐침 실측 (2026-08-12) — 4초 t2v 한 번, 약 $0.97

`scripts/measure/probe-seedance.mjs` 로 `bytedance/seedance-2.0/fast/text-to-video` 를 한 번
불렀다. 로고가 없어 r2v(항목 3)는 안 쟀다.

**요청**: `{ prompt, duration: 4, aspect_ratio: "9:16", resolution: "720p" }`
— `generate_audio` 는 **안 보냈다.**

**응답**: `200`, **134초** 걸렸다. 최상위 키는 `video` 와 `seed` 다.

```
video: { url, content_type: "video/mp4", file_name: "video.mp4", file_size: 883940 }
seed:  1635996414
```

**받은 mp4 (ffmpeg 실측)**

```
Duration: 00:00:04.09
Stream #0:0 Video: h264 (High), yuv420p, 720x1280, 1539 kb/s, 24 fps
Stream #0:1 Audio: aac (LC), 44100 Hz, stereo, 198 kb/s
```

여기서 확정된 것:

- ★ **오디오가 나온다.** `generate_audio` 를 안 보냈는데도 AAC 스테레오가 실려 왔다 —
  **기본이 켜짐**이다. v1 의 전제(자막 없이 소리로 간다)가 성립한다
- **응답 필드는 `video.url` 이 맞다** — `lib/ad/generate.js` 의 파싱 가정이 확인됐다
- **치수가 9:16 720p = 720×1280** 이고 24 fps 다. 합성이 없으므로 확대·축소가 없다
- **길이가 요청보다 조금 길다**(4초 요청 → 4.09초). 자막이 없어 밀림 문제가 없다
- **크기**: 4초에 0.84MB → 15초면 ~3MB. `renders` 버킷 이관 부담이 작다
- **134초 걸렸다** — 4초에 그렇다. 15초는 더 걸릴 수 있다.
  화면 폴링(2초)과 `fire-and-forget` 구조가 맞다는 근거이고, 배포 환경의 함수 실행 시간
  상한을 볼 때 이 숫자를 쓴다
- **계획에 없던 것: 응답에 `seed` 가 있다.** 같은 씨앗으로 다시 부르면 재현이 되는지는
  안 재봤다 — 재생성 정책·A/B 측정에 쓸 자리가 있을 수 있다

**아직 안 정해진 것**: 한국어 발화 품질(사람이 들어야 한다) · 로고·라벨 정확도(r2v 미측정).

## 아직 모르는 것 — 실측·확인이 필요하다

값을 치르기 전에는 답할 수 없는 것들이다. 구현 계획에 확인 태스크로 넣는다.
**1번은 위 탐침으로 답이 나왔다(오디오는 나온다).**

1. **Seedance 2.0 fast 가 오디오를 내는가.** 오디오는 2.0 계열의 기능이지만 fast 티어의
   `generate_audio` 동작을 문서에서 확인하지 못했다. **안 나오면 v1 의 전제가 무너진다**
   (자막도 없고 소리도 없는 영상이 된다) — 그때는 standard 로 올리거나 자막을 되살린다
2. **한국어 발화 품질.** 나레이션 언어를 옵션으로 내거는데, Seedance 의 한국어 발음·억양이
   납품 가능한 수준인지 모른다. **CF 는 카피가 제품이다** — 이것이 v1 의 가장 큰 위험이다
3. **로고·제품 라벨 정확도.** 이 저장소는 이미 데었다 — "레퍼런스는 복사가 아니라 참고다.
   작은 글자는 글자처럼 생긴 무늬로 재생성된다"(`VT PDRN` → `VT PORN`).
   브랜드 영상에서 이러면 납품이 불가능하다. **r2v 가 얼마나 개선했는지 재봐야 한다**
4. **나레이션 언어를 넘기는 방법.** 별도 파라미터가 있는지, 프롬프트에 쓰는 것뿐인지
   문서에서 확인하지 못했다. 프롬프트뿐이면 "지켜지지 않을 수 있다"가 되고,
   그것을 판정할 방법이 없다(자막이 없으므로)
5. **fal 요청 본문 크기 상한.** 사진을 data URI 로 넘기므로 상한을 모르면 4장에서도 막힐 수 있다
6. **2.5 의 extension 을 fal 이 API 로 여는가.** 60초 설계의 갈림길이다
7. **2.5 의 480p 세로 픽셀.** 원가 계산에 480×854 를 가정했다 — 실제 출력 치수를 확인해야
   숫자가 맞는다
