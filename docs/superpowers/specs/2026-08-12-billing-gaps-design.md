# 청구 없이 도는 경로를 막는다 (2026-08-12)

승인된 이용자가 **크레딧을 한 푼도 안 내고 우리 돈을 쓰는 경로가 넷** 있다. 결제를 붙이기
**전에** 막는다 — 안 막으면 첫 유료 고객이 곧바로 이 구멍을 밟는다.

이 문서는 서비스화 점검(2026-08-07)에서 나온 항목 중 "돈이 새는 자리"만 다룬다.
배포(합성)·결제·법적 페이지는 별개 과제다.

## 용어

저장소 주석의 "사장님"이 **이용자**다. **운영자**는 승인·크레딧을 관리하는 우리다.

## 아키텍처 — 새 그물을 짜지 않는다

`assertBudget`(`lib/costs.js:137`)이 이미 **"fal 로 나가기 직전에 막는"** 자리이고
사용자 축 판정(`:151-153`)도 거기 있다. 문제는 **LLM 이 그 함수를 아예 안 부른다는 것**이다.

그래서 이번 작업의 본체는 새 게이트를 만드는 것이 아니라 **기존 게이트에 LLM 을 태우는
것**이다. 지금 `assertBudget` 호출부는 셋뿐이다 — `lib/i2v.js:29` · `lib/imagegen.js:32` ·
`lib/tts.js:29`. 여기에 `lib/llm.js` 와 `/api/chat` 이 더해진다.

> ⚠️ **이 목록이 틀렸다(2026-08-12 최종 리뷰).** `lib/vlm.js` 의 **비전 호출 두 자리**
> (`selectCandidate` · `describePhoto`)가 빠져 있었다. 둘 다 gpt-4o 로 나가는 유료 호출이라
> 여기 있어야 했는데, 스펙 단계에서 안 보여 구현에서도 안 다뤄졌다.
>
> 그중 **`describePhoto` 는 실제 구멍이었다**: `POST /cuts` → `runSplitPipeline`
> (`lib/pipeline.js:69`)이 부르는데 이 자리는 `requireVideoCharge` **앞**(③목소리 전)이라
> **크레딧 0 인 체험 사장님이 밟는다.** 같은 요청의 앞선 컷 분할 `callJson` 이 한 번 막아
> 주지만, 그 한 번을 지난 뒤의 비전 호출 수는 **올린 사진 장수만큼**이다(사진 장수를 자르는
> 곳이 없다 — `app/api/projects/route.js` POST·PATCH 둘 다). 누적 $0.49 인 계정이 사진 100장을
> 붙이고 `/cuts` 한 번으로 그물 밖 지출을 만들 수 있었다. → `costActor()` 바로 뒤,
> **fail-open `try` 바깥**에 `assertBudget` 을 넣어 막았다(안에 넣으면 catch 가
> `BudgetExceeded` 를 삼켜 조용히 "사물"로 오판정한다).
>
> `selectCandidate` 는 Minor 로 남겼다 — `processCut` 에서만 불리고 그 앞이
> `requireVideoCharge` 이며, 컷마다 `imagegen` 의 게이트가 먼저 지난다.

### 무료 한도 판정 — 새 테이블도 스키마 변경도 없다

> ⚠️⚠️ **아래 한 줄짜리 판정은 폐기됐다. 정본은 `lib/costs.js:196-215` 의 주석이다.**
> 구현 중에 이것이 이 브랜치의 **유일한 Critical** 을 냈다 — **돈을 낸 사장님이 자기가 산
> 영상 도중에 무한 루프로 갇혔다.** 다음 절에 무엇이 어떻게 바뀌었는지 적었다.
> 되돌리지 마라.

~~폐기된 판정(2026-08-12 이전):~~

```
잔액 <= 0  이고  (그 사용자의 누적 원가 + 이번 호출 예상 원가) > FREE_TRIAL_USD  →  막는다
```

~~**잔액 0 이하**를 조건으로 삼는 한 줄이 세 경우를 모두 맞게 처리한다(고 생각했다):~~

| ~~누구~~ | ~~무슨 일이 생기나~~ |
|---|---|
| ~~크레딧이 있는 이용자~~ | ~~조건에 안 걸려 **그냥 통과**한다(이미 정가 체계 안이다)~~ |
| ~~갓 가입한 이용자~~ | ~~누적 원가가 한도에 닿을 때까지 체험한다~~ |
| ~~크레딧을 다 쓴 이용자~~ | ~~누적 원가가 **이미 한도를 넘어 있어** 자동으로 막힌다~~ |

#### 실물 판정 — 잔액 하나가 아니라 **청구 이력과 잔액 둘**이다 (2026-08-12 정정)

```
charged <= 0  이고  balance <= 0        ← 여기까지가 "체험자"의 정의
  이고 (그 사용자의 누적 원가 + 이번 호출 예상 원가) > FREE_TRIAL_USD  →  막는다
```

**무엇이 왜 바뀌었나.** 위 표에 **넷째 부류가 빠져 있었다** — *결제했고 그 크레딧을 지금
막 다 쓴 사장님*이다. 정가는 `requireVideoCharge` 가 **시작할 때 통째로** 받아 가므로
잔액이 정확히 0 이 되는 것이 **정상 흐름**이다:

```
잔액 50 → requireVideoCharge(30초)가 50 을 받아감 → 잔액 0
→ 첫 컷이 fal 로 나가는 순간 balance <= 0 이라 그물에 걸림
→ 30초 한 편 원가가 $3.06 이라 컷 두 개면 이미 $0.5 를 넘는다
```

게다가 **탈출구가 없다**. 실패하면 `refundVideo` 가 50 을 돌려주고, 다시 돌리면 또 50 을
내고 잔액 0 이 되어 같은 자리에서 또 막힌다 — **무한 루프**다.

그래서 **청구 이력(`charged`)** 을 함께 본다. 한 번이라도 결제했으면 체험자가 아니다.
이 **넷**이 전부 맞는다:

| 누구 | charged | balance | 무슨 일이 생기나 |
|---|---|---|---|
| 결제한 사장님(잔액 0 이어도) | > 0 | 0 | **통과** — 위의 가둠이 안 생긴다 |
| 크레딧을 받은 사장님 | 0 | > 0 | **통과** — 이미 정가 체계 안이다 |
| 갓 가입한 사장님 | 0 | 0 | 누적이 한도에 닿을 때까지 **체험**한다 |
| 체험분을 다 쓴 사람 | 0 | 0 | 누적이 이미 한도를 넘어 **막힌다** |

크레딧을 다 쓴 사람이 새로 시작하는 경우는 여기가 아니라 유료 입구의
`requireVideoCharge`/`NoCredits`(402)가 막는다 — 구멍이 아니다.

**DB 왕복이 늘지 않는다** — `assertBudget` 이 이미 `sumCosts({})` 를 부르고 있고,
사용자 축은 `creditStateFor(actor)` 가 `{ balance, charged }` 를 **한 번에** 준다
(`lib/charges.js`). 더해진 것은 `sumCosts({ actor })` 하나뿐이고, 그마저 체험자로
판정된 경우에만 돈다.

## 고칠 것 다섯

### 1. `lib/llm.js` 가 한도를 본다

호출 **앞에** 한도를 본다. `addRecord`(`lib/llm.js:55`)는 지금처럼 호출 뒤에 남는다.

★ **이번 호출의 예상 원가는 0 으로 넘긴다.** fal 은 `estimateCost(endpoint, amount)` 로
나가기 전에 값을 알지만, LLM 은 **토큰 수를 호출한 뒤에야 안다**(`estimateLlmCost` 가
`data.usage` 를 받는다 — `lib/llm.js:61`). 없는 숫자를 지어내지 않고 **"이미 넘었는가"만
판정한다.** 넘침은 최대 한 번(~$0.02)이고, 그 한 번은 원장에 남아 다음 호출이 막는다.

가짜 모드는 건너뛴다 — `assertBudget` 첫 줄이 이미 그렇게 한다(`lib/costs.js:138`).

### 2. `/api/chat` 이 기록하고 한도를 본다

- **원장에 남긴다** — 지금 이 지출은 `/costs` 화면에 존재하지 않는다.
- **한도를 본다** — 같은 `assertBudget`, 예상 원가 0(위 1번과 같은 이유).
- 구조를 `lib/llm.js` 로 합치지 않는다. 대화형이라 응답 모양이 다르고, 그건 이번 범위 밖이다.
- ⚠️ 이 라우트는 **가짜 모드가 안 먹는다**(raw fetch). 테스트·데모 중에도 진짜 돈이 나간다 —
  기록이 붙으면 최소한 **보이기는** 한다.

### 2-1. 예산 오류를 HTTP 응답으로 옮긴다 (계획 단계에서 드러난 필수 항목)

**지금 `BudgetExceeded` 를 잡는 라우트가 한 곳도 없다** — `app/` 전체에서 잡는 것은
`NoCredits` 뿐이다. 대본 라우트(`app/api/projects/[id]/script/route.js`)는 `generateScript`
를 그냥 부르므로, 1번이 붙는 순간 **한도에 걸린 사장님이 고장 화면을 본다.**

> ⚠️ **근거가 틀렸다(구현 중 반증, 2026-08-12).** 위 문장은 원래 "**프레임워크 raw 500**
> 을 본다"였다. 실제로는 raw 500 이 아니다 — `lib/script-gen.js` 의 catch 세 곳이
> `BudgetExceeded` 까지 삼켜 `null` 을 돌려주고, 라우트가 그 `null` 을 보고
> **502 "대본을 만들지 못했어요"** 를 낸다. 상태 코드도 문구도 예측과 달랐다.
>
> **결론은 그대로다**: 한도에 걸린 사장님이 402 "체험분을 다 썼어요" 대신 고장 화면을
> 본다. 다만 처방이 하나 늘었다 — `withUser` 에서 402 로 옮기는 것만으로는 부족하고,
> **오류를 삼키는 catch 들이 `BudgetExceeded` 만은 다시 던지게** 해야 한다. 실제로
> 그렇게 고친 자리가 여덟이다 — `lib/script-gen.js` 셋 · `lib/briefing-extract.js` 하나 ·
> 라우트 넷(`briefing` · `cuts/[idx]/regen` · `voice/[idx]/regen` · `clips/[idx]/regen`).

라우트마다 붙이면 새 라우트에서 또 빠뜨린다. `withUser`(`lib/auth/require-user.js:30`)
한 곳에서 옮긴다 — 이 파일이 이미 인가(`NotApproved` → 403)를 그렇게 다룬다.

축에 따라 코드가 다르다:

| scope | 코드 | 왜 |
|---|---|---|
| `trial` · `user` | **402** | 사장님이 할 일이 있다 — 크레딧을 받으면 된다 |
| `total` · `project` | **503** | 우리 안전핀이다. 사장님 잘못이 아니니 402 로 말하면 안 된다 |

예산과 무관한 오류는 **그대로 던진다** — 여기서 삼키면 진짜 사고가 402 로 뭉개진다.

### 3. `PATCH /api/projects/[id]` 가 길이를 지킨다

두 겹이다:

1. **값 검증** — `TARGET_CHOICES` 밖이면 400. 만들 때는 이미 한다(`app/api/projects/route.js:20`),
   고칠 때만 빠져 있다.
2. **결제 후 잠금** — `alreadyChargedVideo(projectId)`(`lib/charges.js:62`)가 참이면
   `target_seconds` 변경을 거부한다. 문구는 "이미 결제된 영상은 길이를 바꿀 수 없어요 —
   새로 만들어 주세요" 계열.

기존 검증들과 같은 자리(락을 잡기 전)에서 판정한다 — `app/api/projects/[id]/route.js:37-38`
주석이 그 이유를 적어 두었다(락 안에서 던지면 "없는 프로젝트"로 잘못 보고된다).

### 4. 프로젝트 상한을 $30 으로 올리고 **성격을 다시 적는다**

지금 주석(`lib/costs.js:120`)은 "30초 한 편이 약 $2 … 재생성 여지를 두어 두 배쯤"이라
적혀 있는데 **낡았다**. 실측 원가는 30초 $3.06 · 60초 ~$6.06 이다(`lib/pricing.js:5`).

더 중요한 것은 **이 상한이 무엇을 막는 물건인지**다:

- **요금 상한이 아니다.** 요금은 크레딧이 맡는다(정가 + 재생성 청구).
- **폭주 방어다** — 파이프라인이 무한 루프에 빠져 한 프로젝트가 돈을 태우는 것을 막는다.
- 그래서 **정상 사용을 막으면 안 된다.** 재생성은 크레딧을 받고 하는 정상 사용인데
  (컷당 최대 3회, 12컷이면 $18 어치까지 가능) 지금 $5 는 그것을 막는다.

$30 이 나온 계산: 60초 정가 원가 $6.06 + 재생성 최대 $18 ≈ $24. 여유를 두어 $30.

### 5. 전역 상한을 $300 으로 올린다

$20 은 전 사용자 합계 **6편**이다. 그리고 `.env.local.example` 에 `SHOTFORM_BUDGET_TOTAL_USD`
와 `SHOTFORM_BUDGET_PROJECT_USD` 를 적어 프로덕션에서 명시적으로 정하게 한다(지금 example
에 없다).

- **결제·충전 화면** — 별개 과제. 이 스펙은 "새는 것을 막는" 것만 한다
- **`/api/chat` 을 `lib/llm.js` 로 합치기** — 응답 모양이 달라 별도 작업
- **rate limit**(가입·로그인 스팸) — 인증 축이라 별개
- **하루 리셋 한도** — `sum_costs` 에 기간 인자가 필요해 라이브 스키마를 또 올려야 한다
- **청구·원가 병기 화면**(`/costs`) — 마진을 보는 화면. 결제와 함께 온다
