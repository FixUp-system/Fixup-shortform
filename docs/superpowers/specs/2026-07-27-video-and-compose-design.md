# ③목소리 · ⑤영상 · ⑥완성 — 설계

작성: 2026-07-27
상태: 설계 확정, 구현 전

---

## 1. 무엇을 만드는가

지금 파이프라인은 **④이미지에서 끝난다.** ③목소리 · ⑤영상 · ⑥완성이 전부 `SoonStep` 자리표시자다.
이 셋을 구현해 **자료 → 완성된 mp4**까지 한 줄로 잇는다.

**이번 작업에서는 실제로 돌리지 않는다.** fal에 한 푼도 쓰지 않고 전체 흐름을 클릭할 수 있어야 한다
(§7 가짜 모드). 기능 골격을 세우는 것이 목적이다.

## 1.5. 단계 순서를 바꾼다 — 목소리는 이미지 뒤로

지금 `STEPS`는 `자료 → 대본 → 목소리 → 이미지 → 영상 → 완성`이다. **이 순서로는 구현할 수 없다.**
목소리를 컷별로 만들려면 컷이 있어야 하는데, **컷 분할은 이미지 단계(`POST /cuts`)에서 일어난다.**
목소리가 먼저 오면 읽을 컷이 없다.

```
바꾼 뒤:  ① 자료 → ② 대본 → ③ 이미지 → ④ 목소리 → ⑤ 영상 → ⑥ 완성
```

목소리가 영상보다 앞이기만 하면 된다(클립 길이가 목소리 길이에서 나오므로).
이미지와의 앞뒤는 자유롭고, 컷이 이미 만들어져 있는 쪽이 자연스럽다.

번호(`no`)도 함께 재배정한다. 화면 안내 문구에 박힌 번호(`"④ 이미지 확인하러 가기"` 등)도 같이 고친다.

## 1.6. 컷이 i2v 상한보다 길 수 있다

`CLAUDE.md`의 "이어서 할 일" 4번에 기록돼 있다 — **12~13초짜리 컷이 나온다.**
i2v 모델은 보통 5~10초가 상한이라 그런 컷은 한 클립으로 만들 수 없다.

이번 작업에서는 **근본 해결(컷을 더 잘게 나누기)을 하지 않는다.** 그건 컷 분할 로직을 건드리는
별도 과제다. 대신 다음 두 가지만 한다.

- `I2V_MAX_SECONDS = 10` 상수를 두고, 그보다 긴 컷은 **10초로 잘라 클립을 만든다**
- 남는 시간은 **클립의 마지막 프레임을 정지로 늘려** 소리 길이를 맞춘다(합성 단계에서)
- 잘린 컷이 있으면 ⑤화면에 **"이 컷은 10초까지만 움직이고 나머지는 멈춰 있어요"**를 표시한다

정지 연장은 ffmpeg의 `tpad` 필터로 한다. `SHOTFORM_COMPOSER=fal` 경로에서는 이 처리를 할 수 없어
**소리가 그림보다 길어진다** — 그 경로의 알려진 한계로 기록한다.

## 2. 세 단계 설계

### ④ 목소리 — 컷마다 따로 읽힌다

**원고 전체를 한 번에 읽히지 않는다.** 그러면 각 컷이 몇 초인지 알 수 없어서
클립 길이도 자막 타이밍도 만들 수 없다. 컷은 이미 문장 단위로 잘려 있어 끊어 읽어도 자연스럽다.

- 화면: 목소리 후보 3~4개(성별·톤) 중 고르기 → 한 문장 미리듣기 → 확정 → 컷별 생성
- 진행은 ④이미지와 같은 방식으로 폴링해 보여준다
- 컷별 다시 만들기 가능 (④와 같은 ≤3회 제한)

**핵심: TTS 실제 길이로 `cut.seconds`를 덮어쓴다.**
지금 `cut.seconds`는 글자 수 ÷ `CHARS_PER_SEC`(5.5)로 어림한 값이다. 목소리가 실제로 4.3초면
클립도 4.3초여야 소리와 그림이 안 어긋난다. 이 단계를 지나면 `cut.seconds`는 추정치가 아니라 실측이다.

### ⑤ 영상 — 이미지를 시작 프레임으로

- 컷마다 `cut.image.url`을 시작 프레임으로 i2v 호출
- 길이는 `min(cut.seconds, I2V_MAX_SECONDS)` (§1.6)
- 화면 구조는 ④이미지와 같다 — 목록 + 우측 미리보기 + 컷별 재생성
- 진행 폴링, 실패한 컷은 `state: "needs_attention"`

**클립 자동 검수(VLM)는 이번에 넣지 않는다.** 영상을 심사하려면 프레임을 뽑아야 하는데,
그러면 합성 전에 ffmpeg가 필요해져 단계 간 의존이 꼬인다. 사람이 보고 재생성하는 것으로 충분하다.

### ⑥ 완성 — 로컬 ffmpeg로 하나로 만든다

순서대로 한 번에 처리한다.

1. 클립 이어붙이기 (컷 순서대로)
2. 오디오 이어붙여 얹기
3. 자막 태우기 (§6)
4. 9:16(또는 선택한 비율)로 인코딩

- 결과: `data/renders/<projectId>.mp4`
- 화면: 완성본 재생 + 다운로드 버튼 + 다시 만들기

## 3. 데이터 모델

기존 컷에 두 필드가 붙고, 프로젝트에 하나가 붙는다.

```js
cut = {
  idx, sentence, seconds, shows, source, regen_count, state,
  image: { url },                    // ④ (기존)
  audio: { url, seconds },           // ③ 신규 — seconds가 실측 길이
  video: { url },                    // ⑤ 신규
}

project.render = { url, ts, seconds }  // ⑥ 신규
```

`cut.seconds`는 ③을 지나면 `cut.audio.seconds`와 같아진다. 두 곳에 같은 값을 두는 이유는
`cut.seconds`가 이미 여러 곳(길이 표시·컷 분할)에서 쓰이고 있어서다 — 그 계약을 깨지 않는다.

`status` 흐름에 세 개가 붙는다: `draft → briefing → script → cuts → voice → video → done`

## 4. 모델과 기본값

전부 env로 교체 가능하게 한다. 지금 `FAL_IMAGE_ENDPOINT` 방식과 같다.

| 용도 | env | 기본값 | 단가 |
|---|---|---|---|
| TTS | `FAL_TTS_ENDPOINT` | `fal-ai/elevenlabs/tts/turbo-v2.5` | $0.05 / 1,000자 |
| i2v | `FAL_I2V_ENDPOINT` | `fal-ai/ltx-2.3/image-to-video/fast` | $0.04 / 초 |

한국어를 지원하는 TTS는 여럿이다(ElevenLabs 계열 · Chatterbox multilingual · MiniMax · Gemini).
기본값을 ElevenLabs Turbo v2.5로 두는 이유는 한국어 지원이 확실하고 빠르기 때문이다.
**목소리 후보의 실제 `voice_id`는 구현 시 fal 문서에서 확인해 상수로 박는다** — 지금 추측하지 않는다.

30초 영상 하나 기준 실제 비용: 이미지 $0.24 + 클립 $1.20 + TTS $0.02 + 합성 $0.006 ≈ **$1.47**.
**영상 클립이 81%다.** 나머지는 반올림 오차 수준이다.

## 5. 합성 — 로컬 ffmpeg, 어댑터로 교체 가능

`lib/compose.js`가 함수 하나를 내보낸다.

```js
composeVideo({ projectId, cuts, aspect_ratio, subtitles }) → { url, seconds }
```

- 기본 구현: **로컬 ffmpeg** (`ffmpeg-static` 의존성 추가)
- `SHOTFORM_COMPOSER=fal`이면 fal ffmpeg API 경로
  (`fal-ai/ffmpeg-api/merge-videos` → `merge-audio-video`). **이 경로는 자막을 태우지 않는다.**

fal 합성은 `merge-videos`가 $0, `merge-audio-video`가 $0.0002/초라 비용은 사실상 없다.
그럼에도 로컬을 기본으로 두는 이유는 **자막** 하나뿐이다.

> `ffmpeg-static`은 이 저장소의 "런타임 의존성 없음" 원칙을 깨는 첫 예외다.
> 어차피 로컬 파일 저장 때문에 Vercel 배포가 이미 막혀 있어 **새로운 제약이 생기지는 않는다.**
> 배포할 때는 `SHOTFORM_COMPOSER=fal`로 바꾸고 자막을 별도 과제로 푼다.

## 6. 자막

숏폼은 소리 없이 보는 사람이 많아 자막이 사실상 필수다. **파일에 태운다**(burn-in) —
재생 화면에만 얹으면 사장님이 내려받아 틱톡에 올렸을 때 사라진다.

- 내용: `cut.sentence` 그대로. 컷 경계가 곧 자막 경계다
- 타이밍: 컷의 누적 `seconds` (③에서 실측했으므로 소리와 맞는다)
- 폰트: **Pretendard OTF**. `node_modules/pretendard/dist/public/static/Pretendard-Bold.otf`를
  `assets/subtitle-font.otf`로 복사해 쓴다 (node_modules 경로를 직접 참조하지 않는다)
- 위치: **세이프존** — 9:16에서 아래쪽 UI(틱톡·릴스의 버튼·캡션)에 가리지 않게
  하단에서 화면 높이의 18% 위. 좌우 여백 8%

## 7. 가짜 모드 — 두 단계

`SHOTFORM_FAKE_IMAGES`를 **`SHOTFORM_FAKE`로 넓힌다.**

| 값 | fal (이미지·TTS·i2v·합성) | OpenAI (브리핑·대본·컷·VLM) | 용도 |
|---|---|---|---|
| (없음) | 실제 | 실제 | 진짜로 만들 때 |
| `1` | **가짜** | 실제 | **대본 내용까지 확인** (한 바퀴 ~$0.1~0.2, 추정) |
| `all` | **가짜** | **가짜** | **완전 0원** — 배선·상태 전이만 확인 |

가짜 산출물:
- 이미지: 지금과 같은 SVG 플레이스홀더
- TTS: 무음 오디오. **`seconds`는 글자 수 ÷ 5.5로 계산해 돌려준다** — 실측 대신 추정을 쓰되
  뒤 단계가 정상 동작하도록
- i2v: 정지 영상 취급 — 이미지 URL을 그대로 `video.url`로 돌려준다
- 합성: 실제 ffmpeg를 돌리지 않는다. `project.render = { url: null, fake: true, seconds }`를 남기고,
  ⑥화면은 **"가짜 모드라 파일은 만들어지지 않았어요"**를 다운로드 버튼 자리에 보여준다.
  재생 못 하는 가짜 파일을 돌려주면 "합성이 깨졌다"로 오해하게 된다 — 없다고 말하는 편이 낫다

**하위 호환**: `SHOTFORM_FAKE_IMAGES=1`도 계속 인정한다(`=1`과 같게 취급).
`tests/vlm.test.js`가 그 이름을 쓰고 있다.

## 8. 비용 기록 — 단위를 확장한다

지금 `PRICE_TABLE`은 **초당 단가만** 다룬다. TTS는 글자당이라 구조가 안 맞는다.

```js
{ prefix: "fal-ai/elevenlabs/tts", unit: "chars", per1k: 0.05 }
{ prefix: "fal-ai/ltx-2.3/image-to-video/fast", unit: "sec", perSec: 0.04 }
{ prefix: "fal-ai/ffmpeg-api/merge-videos", unit: "sec", perSec: 0 }
{ prefix: "fal-ai/ffmpeg-api/merge-audio-video", unit: "sec", perSec: 0.0002 }
```

`estimateCost(endpoint, amount)`가 단위를 보고 계산한다. 기존 호출부는 초를 넘기므로
`unit: "sec"`이 기본이고 동작이 바뀌지 않는다.

TTS·i2v·합성 모두 `addRecord`로 기록한다. **지금은 이미지와 Quick Create 영상만 기록돼
비용 화면이 실제보다 적게 나온다** — 이번에 그 구멍 중 fal 쪽은 메운다.

> OpenAI 비용은 여전히 기록되지 않는다. 별도 과제다(§9).

## 9. 하지 않는 것

- **클립 자동 검수(VLM)** — §2 ⑤ 참조. 사람이 보고 재생성한다
- **배경음(BGM)** — 내레이션만. 음악은 저작권·믹싱 밸런스가 따로 붙는 문제다
- **라우드니스 정규화** — 내레이션 하나뿐이라 지금은 균일하다. BGM이 붙을 때 같이 한다
- **OpenAI 비용 기록** — `llm.js`·`vlm.js`에 토큰 집계를 붙이는 별도 과제
- **fal 합성 경로의 자막** — `SHOTFORM_COMPOSER=fal`은 자막 없이 동작한다
- **실제 라이브 검증** — 이번 작업의 명시적 범위 밖. 가짜 모드로만 확인한다

## 10. 검증

**자동**

- `npm test` 전량 그린. 신규 테스트:
  - `lib/tts.js` — 컷별 생성, `seconds` 실측이 `cut.seconds`를 덮어쓰는가
  - `lib/i2v.js` — 이미지 URL과 초가 제대로 전달되는가
  - `lib/compose.js` — 자막 타이밍이 컷 누적 초와 맞는가, fal 어댑터 분기
  - `lib/costs.js` — `unit: "chars"` 계산, 기존 초당 계산 불변
  - 가짜 모드 세 값(`없음`/`1`/`all`)이 각각 무엇을 막는가
- `npm run build` 성공

**눈으로** (`SHOTFORM_FAKE=all`, **비용 0**)

1. 새 프로젝트 → 자료 → 대본 → 이미지까지 (더미 텍스트로)
2. ③목소리 — 목소리 고르기, 컷별 생성 진행 표시, 컷별 다시 만들기
3. ⑤영상 — 컷별 클립 생성, 미리보기, 재생성
4. ⑥완성 — 합성 진행, 완성본 재생, 다운로드 버튼
5. 각 단계에서 **뒤로 갔을 때 앞 단계 결과가 지워지지 않는가**
6. 비용 기록에 TTS·i2v·합성 줄이 뜨는가 (가짜 모드에서는 기록하지 않으므로 **안 떠야** 정상)

**실제 호출은 이번 작업에서 하지 않는다.** 단가표 값도 fal 대시보드와 대조되지 않은 상태로 남는다.
