# 이미지 모델을 한 세대 올리고 후보를 한 장으로

**한 줄:** `nano-banana` → `nano-banana 2`로 올리고 컷당 후보를 2장에서 1장으로 줄인다.
**비용은 그대로**(컷당 $0.08)이고 모델만 한 세대 올라간다.

워크트리 `C:\Users\fixup\shotform-video`, 브랜치 `feature/video-compose`.

## 왜 지금인가

오늘 실측에서 이미지 단계의 결함을 넷 봤다 — 손이 셋인 컷, 딴 물건이 된 제품(레퍼런스 없는
컷), 무너진 라벨(`VT PDRN` → `VT PORN`), 틀린 가격표(`79,000`). 뒤 셋은 요구를 고쳐 막았고
(레퍼런스 배선·글자 금지), **첫째는 모델 급의 문제로 남아 있다.**

`docs/models-and-costs.md` §2가 `nano-banana`를 "중상급 모델"로 적고 있다. 한 세대 위가
나와 있고 **후보를 1장으로 줄이면 같은 값에 쓸 수 있다.**

레퍼런스로 컷 사이 얼굴 유지, 제품이 컷마다 같은 물건). 싸다고 갈아탔다가 그게 무너지면
07-29 작업이 통째로 날아간다.

> edit가 $0.08인 것만 확인됐다.

## A. 모델 교체 — 환경변수 한 줄

```
FAL_IMAGE_ENDPOINT=fal-ai/nano-banana-2
```

`lib/imagegen.js`가 `refs.length ? \`${base}/edit\` : base`로 조립하므로, 레퍼런스가 있는
컷은 `fal-ai/nano-banana-2/edit`으로 간다. **파라미터 이름이 지금과 같다**
(`prompt` · `image_urls` · `num_images` · `aspect_ratio`) — fal API 문서로 확인했다.

**되돌리기도 한 줄이다.** 새 모델이 기준을 못 넘으면 env만 되돌린다. 이 되돌리기 쉬움이
이번 설계를 작게 유지하는 이유다.

## B. 단가표 — 안 넣으면 조용히 절반으로 기록된다

`PRICE_TABLE`은 **prefix 매칭**이고 파일 주석이 *"더 구체적인 prefix를 위에 둘 것"*이라
적고 있다. 지금 `fal-ai/nano-banana` 줄이 **`fal-ai/nano-banana-2/edit`도 삼킨다** →
$0.08짜리가 $0.04로 기록된다.

```js
{ prefix: "fal-ai/nano-banana-2", perSec: 0.08 },   // ← 더 구체적인 것을 위에
{ prefix: "fal-ai/nano-banana",   perSec: 0.04 },
```

`ltx-2.3`/`ltx-2`가 같은 이유로 순서가 잡혀 있다.

**base 가격은 미확인이라 prefix 하나로 둘 다 $0.08로 잡는다.** base가 더 싸면 과대 기록되는데,
예산 가드(`assertBudget`)가 보수적으로 도는 쪽이라 안전하다. 실제 호출 뒤 fal 대시보드와
대조해 정정한다(`docs/models-and-costs.md` §5 "남은 대조"에 추가).

단가표에 없으면 기본값 $0.1이 적용된다 — `merge-audios`가 $1.7로 부풀려 기록됐던 사고와
같은 자리다.

## C. 후보 2장 → 1장

`lib/pipeline.js`의 `processCut`에서 `Promise.all([genImage, genImage])`를 한 번 호출로 바꾼다.

### VLM은 남기고 문구만 고친다

지금 프롬프트는 후보가 여럿인 것을 전제로 쓰여 있다:

> 후보 이미지들을 보고 JSON만 출력: `{"selectedIndex": 최선 후보 번호, "passed": 전원 불합격이면 false, ...}`

후보가 하나가 되면 **"고르기"가 사라지고 합격·불합격만 남는다.** 스키마에서 `selectedIndex`를
빼고 `selectCandidate`가 항상 `0`을 돌려준다 — **모델에게 없는 선택을 시키지 않는다.**

> ⚠️ 실측에서 **통과율이 사실상 100%이고 재시도가 0회**다. 즉 남는 그 기능이 지금 아무 일도
> 하지 않는다. 그럼에도 남기는 이유는 **나쁜 그림을 걸러낼 유일한 장치**이기 때문이고,
> 왜 다 통과시키는지는 **별건**으로 잡혀 있다.

### 함수 이름은 그대로 둔다

`selectCandidate`가 이제 "고르기"가 아니라 "검수"인데 이름이 어긋난다. 그럼에도 바꾸지 않는다 —
이번 변경은 **A/B 비교를 위해 작고 되돌리기 쉬워야** 한다. 이름 정리는 검수를 제대로 손볼 때
함께 한다. 코드에 주석으로 남긴다.

## D. 좋아졌는지 어떻게 아는가

### 판정 기준을 먼저 정한다

기준을 나중에 정하면 결과를 보고 끼워 맞추게 된다. **돌리기 전에** 못박는다.

| | 무엇을 보나 | 왜 |
|---|---|---|
| 1 | 제품이 레퍼런스와 같은 물건인가 — 청록 띠·검정 캡·라벨 배치 | 오늘 컷3에서 딴 물건이 나왔다 |
| 2 | 인물 얼굴이 아바타와 같은 사람인가 | 07-29에 어렵게 얻은 것 |
| 3 | 손·신체 오류가 있는가 | 오늘 손이 셋 나왔다 |
| 4 | `shows`에 없는 사람이 덤으로 그려졌는가 | 07-29에 고친 자리 |

**채택 규칙: 넷 중 셋 이상에서 새 모델이 낫거나 같으면 채택.** 그 미만이면 되돌린다.

**판정은 사장님이 눈으로 한다.** 넷 다 "이게 더 나은가"를 사람이 봐야 아는 것이고, VLM에게
물으면 오늘까지 여섯 번 통과시킨 그 판정을 또 믿는 셈이 된다. 스크립트는 두 URL을 나란히
출력하는 데까지만 한다.

### 비교는 측정 스크립트로 — 프로젝트를 건드리지 않는다

`scripts/measure/`에 하나 만든다(`shows-motion-leak.mjs`가 선례다).

```
프로젝트에서 컷의 prompt·refs 를 그대로 뽑는다
  → 옛 모델로 한 장
  → 새 모델로 한 장
  → 두 URL 을 나란히 출력
```

**컷별 재생성을 쓰지 않는다** — 이미지가 덮여 비교 대상이 사라진다.

대상은 **`f31c1c7f`**(오늘 만든 화장품 편). 컷 4개이고 **컷2가 사람+제품이 함께 있는** 자리다.

**비용 약 $0.48** (옛 모델 4장 $0.16 + 새 모델 4장 $0.32).

> 이미 있는 v1 이미지를 재활용하면 $0.32로 줄지만, **그것들은 후보 2장 중 VLM이 고른 것**이라
> 새 모델의 1장과 비교하면 옛 모델에 유리하다. $0.16을 더 써서 양쪽 다 1장씩으로 맞춘다.

**이 스크립트는 유료라 사장님 승인 없이 돌리지 않는다.** 코드·단가표·테스트까지는 0원으로
끝낸다.

## 하지 않는 것 (YAGNI)

- **VLM 검수를 제대로 손보기** — 통과율 100%의 원인을 캐는 것은 별건이다. 섞으면 모델 교체
  효과와 구분이 안 된다
- **Seedream·FLUX 비교** — `nano-banana 2`가 기준을 못 넘으면 그때 본다
- **모델 프로필 표**(사용자가 모델 선택) — 모델이 여전히 하나다
- **함수 이름 정리**(`selectCandidate` → 검수) — 검수를 손볼 때 함께
