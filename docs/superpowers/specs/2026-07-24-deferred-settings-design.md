# 설정 지연: 목적 폐지 · 길이 자동 · 비율은 대본 승인 시점으로

날짜: 2026-07-24 / 브랜치: `feature/deferred-settings` (base: `feature/staged-workflow-m1`)

## 배경

M1 1단계(`/create`)는 자료 입력과 함께 목적·길이·비율을 칩으로 받는다. 07-23 라이브 실험의 결론은 "짧은 입력으로는 품질이 안 나온다 = 정보량이 본질"이었고, 그 관점에서 첫 화면의 선택 3줄은 사장님이 자료를 쓰기 전에 넘어야 할 턱이면서 대본 품질에는 기여가 작다. 특히 길이는 사장님이 미리 알 수 있는 값이 아니다 — 자료를 얼마나 줬는지가 결정한다.

## 결정

- **목적 폐지.** 자료 텍스트가 목적을 이미 함축한다(D11의 연장).
- **길이는 입력이 아니라 결과.** 대본이 자료 분량에 맞춰 스스로 문단 수를 정하고, 화면에는 "약 N초"로 계산 결과만 보여준다.
- **비율은 대본 승인 시점에.** 이미지 생성이 비율을 실제로 필요로 하는 첫 순간이 컷 분할이므로, 그 직전 게이트에서 묻는다.

## 사장님이 겪는 흐름

1. `/create` — 자료 텍스트 + 사진뿐. 자료를 넣으면 [대본 만들기 · 무료].
2. 대본 게이트 — 대본 아래 "이대로 읽으면 약 28초" 한 줄. 수정 지시로 대본이 바뀌면 숫자도 따라 움직인다. 승인 버튼 위에 화면 비율 칩(9:16 기본 · 1:1 · 16:9)이 처음 등장.
3. 승인 → 선택한 비율이 저장되며 컷 분할·이미지 생성 시작. 이미지 게이트는 변화 없음.

## 변경 범위

| 대상 | 변경 |
|---|---|
| `settings` 스키마 | `{aspect_ratio}` 만. `purpose`·`duration_s` 제거 |
| `POST /api/projects` | `settings` 불요, `material`만 요구. `settings = {aspect_ratio:"9:16"}` 로 시작 |
| `POST /api/projects/[id]/cuts` | body의 `aspect_ratio`(선택)를 검증 후 `settings`에 저장하고 진행. 잘못된 값이면 400 |
| `lib/script.js` | 프롬프트에서 `[설정]` 줄 삭제. 분량 규칙 → "자료에 담긴 내용을 빠짐없이, 군살 없이. 자료가 적으면 짧게, 많으면 길게 (3~8문단)" |
| `lib/cuts.js` | `[목표 길이]` 삭제. "합이 목표의 ±20%" → "각 문장을 자연스러운 호흡으로 읽는 실제 소요 시간을 `seconds`로". `buildImagePrompt`는 그대로 |
| `lib/script.js` 신규 `estimateSeconds` | 한국어 나레이션 근사 ≈5.5자/초, 표시 전용. 파이프라인·프롬프트에 주입하지 않는다 |
| `app/create/page.js` | 칩 3줄과 관련 state 제거 |
| `app/create/[id]/page.js` | 대본 게이트에 예상 초 표시 + 비율 칩 + 승인 시 `aspect_ratio` 동봉 |

## 하지 않는 것

- 홈 빠른 생성(`/`)과 `/api/chat`은 손대지 않는다 — 챗이 길이·비율을 직접 수집하는 별개 흐름이다.
- `data/projects` 기존 파일 마이그레이션 없음. 옛 `purpose`·`duration_s`는 남아 있어도 코드가 읽지 않고, `aspect_ratio`는 그대로 유효하다.
- 길이 보정 UI(더 짧게/길게 버튼)는 만들지 않는다. 대본 수정 지시로 충분하다.

## 근거와 검증

- `estimateSeconds`는 근사치다. 정확한 초는 컷 분할이 컷별 `seconds`로 산출하며, 게이트 표시는 "약"으로 한정해 기대를 세우지 않는다.
- 비율을 `cuts` POST에 동봉하는 이유: PATCH → POST 두 번이면 비율만 저장되고 컷 분할이 실패하는 중간 상태가 생긴다. 한 번의 클릭은 한 번의 호출로.
- 테스트: `script`·`cuts`·`projects` 테스트의 제거 필드 기대값 정리, `estimateSeconds` 신규 테스트, `cuts` POST의 비율 검증 테스트. 기존 18/18 그린 유지가 하한선.
