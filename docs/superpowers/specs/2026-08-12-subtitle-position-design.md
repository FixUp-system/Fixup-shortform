# 자막 위치 3단 — 설계

> 2026-08-12 · ⑥완성 화면에서 자막을 위·중간·아래로 옮긴다

## 왜 하는가

자막 위치가 **한 값으로 박혀 있다**(`lib/subtitles.js:78`):

```js
marginV: Math.round(height * 0.18),   // 아래에서 18%
Alignment: 2                           // 하단 중앙
```

9:16(1080×1920)이면 아래에서 **약 346px**이다. 틱톡·릴스의 하단 UI를 피하려고 정한 값인데,
컷에 따라 자막이 얼굴이나 제품을 가린다. 사장님이 고를 수 있어야 한다.

## ★ 왜 ⑥완성인가 — ⑤영상이 아니라

**자막은 클립에 안 들어간다.** `lib/compose.js:197` 한 곳에서만 쓰이고, 합성 때 ffmpeg 가
태운다. 그래서:

- ⑤ 전에 두면 **사장님이 아직 아무것도 못 본 상태**에서 정해야 한다
- ⑥에 두면 실제 클립을 보고 "여기 자막이 얼굴을 가리겠다"를 판단할 수 있다
- 바꿔서 다시 만들어도 **클립을 다시 안 만든다** — 합성만 다시 하면 되고 **로컬 ffmpeg 라 0원**이다

## 무엇을 만드는가

### A. 세 자리의 실제 값

ASS 의 `Alignment` 는 숫자패드 배치다(1~3 하단, 4~6 중간, 7~9 상단).

| 고른 값 | Alignment | marginV | 왜 |
|---|---|---|---|
| `bottom`(기본) | 2 (하단 중앙) | `height * 0.18` | **지금과 똑같다** — 틱톡·릴스 하단 UI 회피 |
| `middle` | 5 (중간 중앙) | 0 | 중앙 정렬이라 세로 여백이 무의미하다 |
| `top` | 8 (상단 중앙) | `height * 0.12` | 상단 UI(시간·배터리·앱 헤더)를 피한다 |

비율로 계산하므로 9:16·1:1·16:9 세 사이즈에서 자동으로 따라 움직인다
(`subtitleStyle` 이 이미 그렇게 되어 있다).

### B. 저장 — `settings.subtitle_position`

`"bottom"` | `"middle"` | `"top"`. **기본은 `bottom`** 이라 지금 동작이 그대로다.

`PATCH /api/projects/<id>` 가 받는다. 그 라우트는 `settings` 를 화이트리스트 없이 머지하므로
**닫힌 목록 검증을 거기 더한다** — `aspect_ratio`·`target_seconds` 가 이미 그렇게 하고 있다.
모르는 값은 400 이다(조용히 기본으로 바꾸지 않는다 — 고른 것과 만들어지는 것이 달라지면
아무도 못 알아본다).

### C. ★ 각인 — 안 하면 바꿔도 아무 일이 없다

지금 `renderKey`(`lib/steps.js:107`)에 자막 설정이 **없다**:

```js
return (project?.cuts || [])
  .map((c) => `${c.audio?.url || ""}|${c.video?.url || ""}|${c.sentence || ""}`)
  .join("\n");
```

이대로 위치만 넣으면: 사장님이 자막을 올린다 → `render.of` 가 그대로 → `isRenderStale` 이
**"안 낡았다"** 고 판정 → **"다시 만들기"가 안 뜬다** → 완성본은 옛 위치인데 화면은 최신이라고
말한다. **바꿨는데 아무 일도 안 일어난다.**

그래서 `renderKey` 에 넣는다. 다만 **있을 때만 덧붙인다**:

```js
export function renderKey(project) {
  const base = (project?.cuts || [])
    .map((c) => `${c.audio?.url || ""}|${c.video?.url || ""}|${c.sentence || ""}`)
    .join("\n");
  // ⚠️ 있을 때만 덧붙인다. 형식을 무조건 바꾸면 옛 각인이 전부 불일치가 되어
  //    이미 만든 완성본이 통째로 낡는다 — clipKey 의 speed 와 같은 함정이다.
  const pos = project?.settings?.subtitle_position;
  return pos ? `${pos}\n${base}` : base;
}
```

기본값(`bottom`)일 때는 **아무것도 안 붙는다** → 기존 완성본의 각인과 글자 그대로 같다 →
낡음이 안 생긴다. 사장님이 실제로 바꿨을 때만 붙어서 그때 낡는다.

> 이 패턴은 `clipKey`(`lib/steps.js:97-104`)가 `speed` 를 다루는 방식 그대로다. 그 주석이
> "style_of 때와 같은 함정"이라 적은 사고를 되풀이하지 않으려는 것이다.

### D. 화면 — ⑥완성

합성 버튼 위에 칩 셋을 둔다. `.chips`/`.chip` 은 이미 있는 규칙이다(③목소리가 쓴다).

```
자막 위치   [위] [중간] [아래●]
            영상 아래쪽 UI에 가리지 않게 기본은 아래예요

[완성본 만들기]
```

- 이미 만든 뒤에 바꾸면 **낡음 경고가 뜬다**(위 C 가 그것을 가능하게 한다) — 다시 만들면
  값이 안 든다는 것을 문구로 말한다: "자막만 바꾸는 것은 값이 들지 않아요"
- 합성 중(`busy`)에는 잠근다

## 건드리지 않는 것

- **`buildCues`·줄바꿈·두 줄 규칙** — 위치만 바꾼다. 폭 계산(`lineWidthUnits`)도 그대로다
- **글자 크기·가로 여백** — 이번엔 위치뿐이다(사장님 결정)
- **클립·그림·목소리** — 자막은 합성에서만 쓰이므로 아무것도 안 낡는다
- **`clipKey`·`isImageStale`·`isAudioStale`** — 자막과 무관하다
- 미리보기(자막을 얹은 썸네일) — 범위 밖. 다시 만드는 값이 0원이라 감당된다

## 검증

1. `npx vitest run` — 지금 그린 위에서 는다
2. ★ **옛 프로젝트가 낡지 않는지** — `subtitle_position` 이 없는 프로젝트의 `renderKey` 가
   **바뀌기 전과 글자 그대로 같아야 한다.** 이게 이 설계의 가장 위험한 자리다
3. ★ **바꾸면 낡는지** — `bottom` → `top` 으로 바꾼 뒤 `isRenderStale` 이 참이어야 한다
4. 세 값이 실제로 다른 ASS 를 만드는지(`toAss` 출력의 `Alignment`·`MarginV`)
5. 모르는 값은 400
6. 눈으로: ⑥완성에서 칩을 고르고 다시 만들어 자막이 실제로 옮겨졌는지

⚠️ 6번은 **합성을 한 번 돌려야** 확인된다. 로컬 ffmpeg 라 0원이지만 클립이 이미 있는
프로젝트가 필요하다 — 지금 DB 에 완성본이 있는 프로젝트가 **0개**라 새로 만들거나
(유료) 로컬 유물을 살려야 한다.
