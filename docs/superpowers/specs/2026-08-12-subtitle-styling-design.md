# 자막을 사장님이 고친다 — 위치·폰트·색·크기

> 2026-08-12 · 대상: `lib/subtitles.js` · `lib/compose.js` · `lib/steps.js` ·
> `app/create/[id]/done/page.js` · `assets/`

## 무엇을 바꾸나

지금 자막은 **하단 고정 · Pretendard · 흰 글자**로만 나온다. 위치는 `bottom`/`middle`/`top`
세 칸뿐이고 화면에서 고를 수도 없다.

앞으로 사장님이 **완성본을 보면서** 자막을 드래그해 옮기고, 폰트·색·크기를 고른다.

## 왜 ⑥완성에서 고치나 (사용자 결정)

사장님은 결과를 보고 나서 "자막이 얼굴을 가리네" 라고 안다. 만들기 전에 미리 정하라고 하면
무엇을 정하는지 모르는 채로 고르게 된다.

## 구조

### 1. 완성본이 두 벌이 된다

| | 무엇 | 저장 | 언제 만드나 |
|---|---|---|---|
| **원본** | 클립 + 소리, **자막 없음** | `renders/{id}-raw.mp4` | 합성할 때 한 번 |
| **완성본** | 원본에 자막을 구운 것 | `renders/{id}.mp4` (지금과 같음) | 자막을 고칠 때마다 |

★ **원본이 있어야 미리보기가 성립한다.** 지금 완성본에는 자막이 구워져 있어, 그 위에 드래그
UI 를 얹으면 옛 자막과 새 자막이 둘 다 보인다.

★ **자막을 고쳐도 클립을 다시 사지 않는다.** 자막만 굽는 것은 원본 하나를 입력으로 받아
자막 필터만 거는 일이라, 전체 합성(클립 내려받기·이어붙이기)보다 훨씬 싸고 빠르다. 둘 다
로컬 ffmpeg 라 **0원**이다.

⚠️ 완성본 URL(`/api/renders/{id}.mp4`)을 바꾸지 않는다 — `render.of` 각인이 이 문자열로
낡음을 판정하고, 사장님이 받아 간 링크도 이 모양이다.

⚠️ **ASS 자막 픽셀은 동일하나 영상은 인코딩 2세대다** — 옛 경로는 클립을 이어 붙이며 x264 를
한 번 거쳤는데, 이제는 원본(1세대)에 자막을 굽느라 한 번 더 거친다. 자막 글자가 놓이는 자리와
모양은 같지만 **영상 화질·파일 크기·인코딩 시간은 오늘과 다르다.** 수치를 재고 정할 일이라
이번 작업 범위 밖으로 남긴다(최종 리뷰 I4, 이월).

### 2. 미리보기는 원본 위에 HTML 로 겹친다

⑥완성 화면이 **원본**을 재생하고 그 위에 브라우저가 자막을 그린다. 드래그·색·크기가 즉시
보인다. [적용]을 누르면 그 값으로 다시 굽는다.

⚠️ **브라우저와 ffmpeg 는 다른 렌더러다.** 글자 두께·줄바꿈 위치·외곽선 굵기가 미묘하게
다를 수 있다. 완전히 같게 만들 수는 없다. 줄바꿈 규칙과 글자 크기 계산을 **양쪽이 같은
함수에서 가져오게** 해서 차이를 줄인다 — 그 함수는 이미 `lib/subtitles.js` 에 있다
(`subtitleStyle`·폭 한계 계산).

### 3. 코드가 막는 것 (사용자 결정: 자유롭되 코드가 막는다)

| 무엇 | 자유 | 코드가 막는 것 |
|---|---|---|
| 위치 | 드래그로 자유 | 화면 밖·가장자리는 안전 여백 안으로 되돌린다 |
| 색 | 자유 선택 | **외곽선은 코드가 정한다** — 밝은 글자면 검정, 어두운 글자면 흰색 |
| 크기 | 범위 안에서 자유 | 하한(안 보임)·상한(세 줄을 넘어 화면을 먹음) |
| 폰트 | 세 개 중 하나 | 목록 밖 값은 기본으로 |

★ **화면 색을 분석하지 않는다.** 배경 밝기를 재려면 프레임을 뜯어야 하는데 무겁다. 지금도
외곽선(두께 3)으로 가독성을 지키고 있으므로, **글자색의 반대 명도로 외곽선을 정하는 규칙**
하나면 어떤 배경에서도 읽힌다.

### 4. 각인 — 여기가 이 설계에서 가장 조심할 자리다

지금 `renderKey` 는 자막 위치를 **첫 줄에 낱말로** 붙이고, `renderKeyBody` 가
`SUBTITLE_POSITIONS.includes(head)` 로 그 머리를 뗀다. 설정이 넷으로 늘면 **그 방식이 못
버틴다** — 첫 줄이 더는 닫힌 목록의 한 낱말이 아니다.

**바꾸는 법**: 자막 설정을 한 줄 JSON 으로 머리에 두고, 본문과 확실히 가른다.

```
subtitle:{"pos":[0.5,0.82],"font":"basic","color":"#FFFFFF","size":1.0}
<소리|클립|문장 줄들>
```

- 머리 줄이 `subtitle:` 로 시작하면 그것이 자막 설정이다 — 본문 줄은 언제나 `|` 를 품은
  `소리|클립|문장` 꼴이라 섞이지 않는다
- `isSubtitleOnlyStale`(이름을 넓힌다)이 머리를 떼고 몸통만 비교한다

⚠️ **옛 각인을 깨지 않는다.** 기본값이면 머리를 아예 안 붙인다(지금 규칙과 같다) — 붙이면
이미 만든 완성본이 전부 낡아 다시 굽게 된다. 옛 각인(`top\n…`)도 계속 읽을 수 있어야 한다.

★ **자막만 바뀌면 클립·그림은 낡지 않는다.** 이미 `isSubtitlePositionOnlyStale` 이 그 개념을
갖고 있으므로 이름과 범위만 넓힌다. 자막을 열 번 고쳐도 클립 값은 한 번만 나간다.

### 5. 값

- **자막 재굽기는 0원**(로컬 ffmpeg). 크레딧 청구도 없다 — `/render` 에는 원래 게이트가 없다
- 폰트 파일 세 개가 저장소에 들어간다(약 4MB). 무료 상업 이용 가능한 것만 고른다

## 지켜야 할 것

- ★★ **완성본 URL 을 바꾸지 않는다**(`/api/renders/{id}.mp4`)
- ★★ **옛 각인을 깨지 않는다** — 기본값이면 머리를 안 붙인다
- ★★ **자막만 바뀌었을 때 클립·그림이 낡으면 안 된다**
- ★ 줄바꿈·크기 계산을 화면과 ffmpeg 가 **같은 함수**에서 가져온다
- ★ 자막 글자 자체는 계속 **원고 그대로** 태운다(모델이 그리면 한글이 변형된다)
- 새 npm 의존성 금지 — 색 피커·드래그는 표준 입력과 포인터 이벤트로 만든다

## ★ 라이브 검증이 아직 0회다 (2026-08-12 구현 완료 시점)

**아무도 실제로 ffmpeg 를 안 돌렸다.** "기본값이면 오늘과 픽셀 동일" 도 계산·테스트로만
확인됐다. 자막 재굽기는 **로컬 ffmpeg·0원**이라 검증 비용이 사실상 없다.

프로젝트 하나로 **네 번만** 구우면 아래 대부분이 닫힌다(최종 리뷰 판정):
①기본값 그대로 ②폰트 3종 ③색 하나 ④크기 1.6

| 미검증 | 실패하면 |
|---|---|
| `\pos(540,1574)` + Alignment 2 가 libass 에서 옛 `MarginV=346` 과 같은 픽셀인가 | 이미 만든 완성본과 자막 자리가 어긋난다 |
| **`soft`(Gowun Dodum) 한글 글리프** — cmap format 12 라 스크립트로 못 봤다 | **두부(□□□) 글자**가 나온다. 알려 줄 자리가 코드에 없다 |
| `impact`·`soft` 가 `fontsdir` 에서 실제로 선택되는가 | 조용히 기본 폰트로 그려진다 |
| `burnArgs` 의 `-vf subtitles` + `-c:a copy` 가 실제로 도는가 | 자막 적용이 통째로 실패 |
| `-raw.mp4` 가 `Content-Disposition: attachment` 인 채로 `<video>` 에서 재생되는가 | 미리보기가 검은 상자 |
| 색 → ASS BGR 역순이 그 색으로 구워지는가 | 빨강이 파랑으로 |
| 크기 1.6 에서 세 줄로 안 넘치는가 | 화면의 39% 를 자막이 먹는다 |
| 미리보기 ↔ 최종의 실제 시각 차이 | 고른 것과 다른 결과 |

## 후속 과제 (최종 리뷰·재검토가 남긴 것 — 병합은 막지 않는다)

1. **이중 인코딩 수치를 재고 정한다** — 위 §1 의 ⚠️ 참고. 화질·크기·시간을 측정한 뒤
   raw 를 `-crf 18` 로 굽는 등으로 세대 손실을 낮출지 판단
2. **줄바꿈이 양쪽 다른 함수다** — 미리보기는 컷 문장을 통째로 그리고 최종은
   `splitSubtitleText`·`breakTwoLines` 로 쪼갠다. 두 함수 다 export 돼 있어 한 줄이면 맞는다
   (미리보기가 첫 컷 한 문장만 그리는 것도 같은 자리)
3. **`soft` 는 7.2MB TTF 원본을 그대로 서빙**한다 — woff2·subset 여지. `@font-face` 는 실제로
   쓰일 때만 받고 preload 도 없어(테스트로 고정) 기본만 쓰는 사장님은 안 받는다
4. **폰트가 두 곳에 바이트 복제**돼 있다(`assets/` = ffmpeg, `public/fonts/` = 브라우저).
   지금은 sha1 동일성 테스트가 어긋남을 잡지만, `/api/fonts/[id]` 로 흘려주면 중복이 사라진다
5. **저장이 두 배**다(원본+완성본, 편당 ~20MB). **삭제 경로가 아예 없어** 영구 누적이다 —
   무료 플랜 1GB 면 50편에서 찬다. **결제를 붙이기 전에 반드시 볼 자리**
6. 자막을 다시 구울 때마다 **안 바뀐 원본 8~13MB 를 브라우저가 다시 받는다**(ETag 가
   `render.ts` 하나라서). raw 에 별도 ETag 나 `immutable`
7. `SHOTFORM_COMPOSER=fal` 경로는 원본을 안 만든다 — 그 환경에서 "[다시 합치기]로 다시
   만들어 주세요" 안내가 거짓말이 된다
8. 미리보기 외곽선이 2px 고정이라 상자 크기(~400px) 기준으로 최종(Outline 3 @1080)보다
   **상대적으로 굵게** 보인다
9. 자막을 굽는 중에 [다시 합치기]를 누르면 두 경로가 같은 `render` 를 쓴다
10. 몸통이 낡은 프로젝트에서도 [적용]이 눌린다 — 낡음 판정이 살아 있어 사장님에게 나가지는
    않지만, 못 쓰는 파일이 한 번 더 덮인다
11. `composeVideo` 의 원본 best-effort `catch` 가 `readFileImpl` 실패까지 삼켜 **로그가 한 줄도
    안 남는다**

## 이번에 안 하는 것

- 컷마다 다른 자막 스타일 — 한 편에 하나다
- 자막 애니메이션(등장 효과)
- 화면 밝기 분석으로 색 자동 추천
- 자막 글자 편집(문장 고치기) — 그것은 ②대본이 하는 일이고 고치면 낭독이 낡는다
