# 시나리오를 흐름으로 · 자막을 받아쓰기로 — 설계

2026-08-19

## 한 줄

지금은 **우리가 컷을 나눠 모델에게 넘긴다.** 그래서 통짜로 굽는데도 모델이 그 경계에서 끊는다. 컷 분할을 **이미지를 만들기 위한 내부 단계**로 내리고, 모델에게는 **끊기지 않는 흐름**을 준다. 그러면 어느 초에 무슨 말을 하는지 알 수 없게 되므로 자막은 **완성본을 받아써서 실측 시각**으로 붙인다.

## 왜 (사용자 판단)

> "시나리오는 컷 분할이 아닌 전체 시나리오를 전달함으로써 **연출이 끊어짐을 방지**하기 위함이야. 묘사나 연출 기법은 영상 모델에서 처리하는 거지."

실측이 그 말을 뒷받침한다. 지금 `scenario.text` 는 이렇게 나간다:

```
Total length exactly 15 seconds.
Scene 1 (0-4s): A rustic light-wood kitchen table…
Scene 2 (4-8s): Extreme close-up orbit shot…
Scene 3 (8-12s): Eye-level medium shot…
Scene 4 (12-15s): Final hero shot…
```

**클립을 물리적으로 안 잇는 대신 모델이 내부에서 넷으로 끊는다.** 없애려던 끊김이 한 단계 안쪽으로 옮겨갔을 뿐이다.

그리고 SYSTEM 이 정반대를 목표로 삼고 있다 — *"카메라·조명·모션·음향을 반드시 말로 적는다. **빠뜨리면 모델 재량이 되어 밋밋해진다**"*. 이 전제는 **한 번도 측정된 적이 없다.**

말로 지정하는 것의 한계는 이미 값을 치르고 배웠다: 참조 사진은 라벤더 토끼인데 프롬프트가 `cream-white … pastel pink ribbon` 을 시켜 크림색 토끼가 나왔다(2026-08-19). **말은 틀릴 수 있고 그림은 안 틀린다.** 연출도 같다.

## 두 방식이 이렇게 갈린다

| | 모델에게 가는 것 |
|---|---|
| **장면 순서**(`order`) | 흐름 + **번호 붙은** 그림(컷별). 흐름 서술 **안에 그림 자리를 앵커**로 표시 |
| **참고 그림**(`refs`) | 흐름 + **번호 없는** 그림(제품·인물·장소) |

**둘 다 흐름은 같고 그림에 순서가 있느냐만 다르다.** 지금은 시나리오가 이미 장면을 번호로 쪼개 놔서 이 차이가 묻혀 있었다 — 그게 걷히면 실험이 재려던 것을 비로소 잰다.

앵커 방식(사용자 선택):

> 아침 볕이 드는 부엌에서 시작해 **(1)** 카메라가 간식 세트로 다가간다. 손이 하나를 집어 들면 **(2)** 결이 드러나고, 그대로 거실로 이어져 **(3)** 강아지가 그것을 문다.

번호만 주는 안은 기각됐다 — 모델이 그림 자리를 스스로 정해야 해서 이 방식의 뜻이 절반만 전달된다.
⚠️ **위험**: 그 앵커가 다시 "끊는 신호"로 읽힐 수 있다. **구워 봐야 안다.**

## 무엇을 남기고 무엇을 바꾸는가

조사로 확인한 사실(파일·줄은 조사 보고에):

- `shots[]` **배열 자체가 없으면** `validateScenario` 가 `null` 을 내고 "시나리오를 만들지 못했어요"로 죽는다
- `shots[].line` 은 **자막 글자의 유일한 원천**이고 `withSpokenLines` 가 대사를 프롬프트에 못 박는 근거다
- `shots[].seconds` 는 **지금 자막 시각의 유일한 근거**다. 없애면 `buildCues` 의 누적이 0 이라 **모든 자막이 0초에 겹친다**
- `shots[].shows` 는 **이미지 프롬프트 전용**이다(굽기는 안 읽는다)

→ **`shots` 는 그대로 둔다.** 바꾸는 것은 **`text` 하나**다. 컷은 내부 작업 단위로 남고 모델에게만 안 간다.

## ★ 먼저 고쳐야 할 것 — `shows` 가 한 번도 온 적이 없다

`lib/ad/llm.js` 의 `SCENARIO_SCHEMA` 에 **`shows` 가 없고 `additionalProperties: false`** 다. SYSTEM 은 요구하는데 스키마가 막는다.

**실측: 저장된 시나리오 6개 전부 `shows` 있는 장면 0.** 즉 이미지 프롬프트는 지금도 `beat`(한국어)로 폴백하고 있다. 테스트는 픽스처에 `shows` 를 손으로 넣어 전부 그린이었다.

이것부터 고치지 않으면 이 설계의 나머지가 의미가 없다 — 이미지가 계속 한국어로 만들어진다.

## 자막을 받아쓰기로

### 지금
`adSubtitleCuts(shots)` → `buildCues` 가 컷을 **순서대로 누적**해 시각을 만든다 → `toAss`

### 바꿀 것
완성본 음성을 받아써서 **절대 시각 목록**을 얻고 그것으로 자막을 굽는다.

조사로 확인한 좋은 소식: **`toAss` 는 컷 구조를 전혀 모른다.** `{ start, end, text }` 배열만 있으면 된다(초 단위 숫자). 테스트가 이미 리터럴 cue 배열을 직접 넘긴다.

막는 것은 하나뿐이다: **`burnSubtitles` 가 `cuts` 를 강제하고 내부에서 `buildCues` 를 부른다.** 여기에 **`cues` 우회 인자**를 내면 아래층은 그대로 쓴다.

### 받아쓰기를 붙이는 자리
- 이 저장소에 STT 사용처가 **0건**이다 — 새로 붙인다
- 관용구는 `lib/tts.js`(동기 `fal.run`): **가짜 판정 → `assertBudget` → 호출 → `addRecord`** 순서
- ⚠️ **`lib/costs.js` 의 `FAL_PREFIXES` 에 반드시 넣는다.** 안 넣으면 `SHOTFORM_FAKE=fal` 에서 **진짜 돈이 나간다**(주석이 그 사고를 기록하고 있다)
- 원가표(`PRICE_TABLE`)도 함께. 안 넣으면 막히지는 않고 **원장에 $0.1/초 기본값이 조용히 잘못 찍힌다**

### 모르는 것 — 구현 전에 잰다
**어느 모델을 쓸지와 값을 아직 모른다.** 짐작으로 적지 않는다. 첫 태스크가 그것을 확인하는 일이다:
- fal 이 여는 STT 엔드포인트와 단가
- **단어·문장별 시각을 주는지**(총 길이만 주면 이 설계가 성립하지 않는다 — 대안을 다시 잡아야 한다)
- 한국어 정확도(관련 실측: Seedance 한글은 *발음은 맞고 글자는 틀린다*)

## 함께 정리하는 것

이 설계에 흡수되는 앞선 발견들:

1. **`refs` 세 축 프롬프트 결함** — `person` 이 마지막 장면에 딸려 인물 없는 장면이면 무의미한 초상이 되고, `place` 는 "empty of people" 이라면서 사람 묘사를 재료로 다 넣는다. **B 방식에만 있는 결함이라 비교를 오염시킨다.** 굽기 전 그림 단계($0.24)에서 보고 고친다.
2. **굽는 중에는 시나리오 재작성이 열려 있다** — 게이트가 `video?.url` 만 보는데 굽는 동안은 아직 `null` 이다. 조건 한 줄.
3. **그림 6회 소진 + 시나리오 재작성 = 막다른 길** — 굽기도 400, 그림도 400이라 값을 치를 길이 없다.
4. **SYSTEM 을 고쳤으면 전후를 잰다** — `scripts/measure/probe-scenario.mjs` 가 정확히 이 용도로 있다(그 SYSTEM 을 대상으로 전/후를 나란히 비교). LLM 만 쓰므로 **약 $0.10**.

## 범위 밖

- **광고 경로의 시나리오도 같이 바뀐다** — `lib/ad/scenario.js` 를 두 경로가 공유하기 때문이다. 광고는 통짜 생성이라 같은 논리가 적용되지만, **광고 품질이 어떻게 변하는지는 측정 대상**이다(위 4번).
- 단계별 경로(`lib/scenario.js`)는 **안 건드린다** — 거기는 컷마다 클립을 사서 잇는 구조라 컷 분할이 필요하다.
- 1~3분 영상 — Seedance 최대 30초라는 벽은 이 설계가 못 넘는다.

## 미검증

- 흐름 서술이 **정말 덜 끊기는지** — 구워 봐야 안다($2~3)
- 앵커가 **끊는 신호로 읽히지 않는지** — 같은 확인에서 본다
- 받아쓰기가 **한국어를 제대로 받아쓰는지**
- SYSTEM 을 바꾼 뒤 **광고 시나리오 품질**이 어떻게 되는지(약 $0.10 으로 잴 수 있다)
