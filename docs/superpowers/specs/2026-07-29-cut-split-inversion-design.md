# 컷 분할 기본값 뒤집기 — 합치는 것을 예외로

**한 줄:** 조각 하나 = 컷 하나가 기본이고, 합치는 것은 예외다. 8초를 넘으면서 두 조각 이상인
컷은 **코드가 조각 경계에서 전부 푼다.**

워크트리 `C:\Users\fixup\shotform-video`, 브랜치 `feature/video-compose`.

## 왜 — 지난번 처방이 증상을 악화시켰다

07-29 오후에 "컷이 문장보다 잘아질 수 없다"고 보고 `splitUnits`(8초 넘는 문장을 쉼표·연결어미로
나눔)를 만들었다. **재보니 8초 초과가 28% → 50%로 늘었다.**

원인을 다시 쟀더니 **8초 초과 5건 중 4건이 "이미 8초 이하인 조각 둘을 LLM이 합친 것"**이었다.

> **쪼갤 능력**을 만들었는데 실제 문제는 **합치는 습관**이었다.
> [[shotform-cut-length-2026-07-29]]에서 이미 "묶기가 주범(컷 60%가 2문장 이상)"이라고 쟀는데,
> 그 설계가 그쪽을 안 건드렸다.

재시도 판정은 제대로 걸렸다 — **모델이 같은 답을 다시 냈고 코드가 받았다.** 설계가 "한 번 더
묻고 그래도 넘으면 통과"였으니 설계대로다. **판정만 하고 강제하지 않은 것의 한계다.**

## 무엇을 바꾸나 — 기본값 하나

지금은 **"LLM이 묶는 것이 기본"**이고 코드가 가끔 말린다. 앞으로는 **"안 묶는 것이 기본"**이고
묶는 것이 예외다. LLM에게 묻는 것은 그대로 두고, **받은 답을 코드가 되돌린다.**

```
지금:  callJson → 검증 → 길면 한 번 더 묻기 → (같은 답이면) 그대로 받는다
새로:  callJson 1회 → 검증 → 8초 초과·두 조각 이상이면 조각 단위로 전부 푼다
```

### 분해 규칙 — 살아남는 묶음이 없다

컷 하나가 `seconds > 8` **이고** 조각 둘 이상(`to > from`)이면, `[from], [from+1], …, [to]`
개별 컷으로 대체한다. **부분적으로 살리지 않는다.**

| 상황 | 판정 |
|---|---|
| 조각 1–2 · 6.9초 | 그대로 — 합쳤지만 8초 이하다 |
| 조각 3 · 4.4초 | 그대로 — 조각 하나다 |
| **조각 4–6 · 11.3초** | **푼다 → 컷 3개** |
| 조각 7 · 9.2초 | 그대로 — **조각 하나라 더 쪼갤 수 없다** |

마지막 줄이 중요하다. 조각 자체가 8초를 넘는 것(절 경계가 없는 긴 문장)은 통과시킨다 —
되물어도 답이 같고, 막으면 영영 실패한다. 사물 레퍼런스의 "0개일 때만 재시도"와 같은 결이다.

"8초 이하가 될 때까지만 부분적으로 푸는" 방식은 택하지 않았다. 어느 경계를 살릴지를 코드가
임의로 정하게 되고(앞부터 채우기), 그러면 **장면 의미와 무관한 묶음이 남는다.**

### 되묻기는 없앤다

코드가 강제로 푸는 이상, 되묻기는 값(시간 + OpenAI 호출)을 치르고 결과가 덮이는 자리다.
실측에서 되물었더니 **모델이 같은 답을 다시 냈다.** 분할이 빨라지고 "언제 되돌리는가"가
한 곳으로 모인다.

## 프롬프트는 건드리지 않는다

`splitSystem()`의 "한 컷이 8초를 넘지 않게 한다"는 그대로 둔다. 이번 변경은 **코드 강제
하나의 효과만** 재야 한다. 프롬프트까지 같이 바꾸면 무엇이 효과였는지 못 가린다 —
켄번즈를 미루는 것과 같은 이유다.

## 보장은 그대로

분해는 **조각 경계에서만** 자르므로 `컷을 이어붙이면 원고와 글자 그대로 같다`가 유지된다.
`validateCutRanges`는 손대지 않고, **분해 결과를 그 함수에 한 번 더 통과시킨다** — 빈틈·겹침·
전량 사용을 코드가 스스로 검사하게 한다(분해 로직의 자체 점검이기도 하다).

## 목소리 실측은 로그만

분할 시점의 8초는 **추정**(초당 5.5자)이고 진짜 낭독 길이는 ③목소리에서 나온다.
`runVoicePipeline`이 추정을 실측으로 덮는 자리에서, 실측이 8초를 넘으면 로그를 남긴다.

```
[목소리 a1b2c3d4] 추정 6.2초 → 실측 8.4초 (컷3)
```

**흐름은 막지 않는다.** 그 시점에 이미 목소리가 만들어져 있어, 컷을 쪼개면 그 소리를 버리고
다시 사야 한다(유료). 무효화 연쇄도 생긴다. 이번에는 **추정이 얼마나 맞는지를 재는 것**까지만
하고, 그 수치가 다음 판단의 재료가 된다.

## 비용 — 오르는 것을 알고 받는다

컷이 늘면 그림과 클립이 늘어 **30초당 $1.54 → $1.92**로 오른다. 짧은 컷도 i2v 눈금 바닥(6초)을
사기 때문이다.

**켄번즈(짧은 컷을 로컬 ffmpeg로 만들어 0원)를 같이 넣지 않는다.** 넣으면 컷이 짧아진 효과와
싸진 효과가 섞여 무엇이 무엇인지 못 가린다. 켄번즈는 이 측정이 끝난 뒤의 별건이다.

## 어떻게 좋아졌다고 아는가

`scripts/measure/run-pipeline.mjs`로 자료 3종 × 3회를 **컷 분할까지만** 돌린다 —
OpenAI만 쓰므로 **fal 비용 0원**(편당 약 $0.005).

| | 지금(실측) | 목표 |
|---|---|---|
| 8초 초과 컷 비율 | **50%** | 조각 자체가 8초를 넘는 것만 — 한 자릿수 |
| 30초당 컷 수 | 4~5 | 6~8 |
| 분해 건수 | — | 로그에 남는다(몇 건이 되돌려졌는지) |

**측정 없이 채택하지 않는다.** 8초 초과가 안 떨어지면 원인이 또 다른 곳에 있다는 뜻이다.

## 건드리는 곳

**수정**
- `lib/cuts.js` — `explodeLongRanges(ranges, units)` 신설. 컷 객체가 아니라 **경계 범위**를 다시 쓴다 —
  결과를 `validateCutRanges` 에 다시 통과시키면 문장·초·idx 를 그 함수가 다시 뽑아 주고,
  빈틈·겹침 검사도 한 번 더 받는다. 순수 함수라 LLM 호출 없이 테스트한다
- `lib/pipeline.js` — `defaultDeps.splitCuts`에서 되묻기 루프와 `splittableLong` 제거,
  분해 호출과 로그 추가 / `runVoicePipeline`에 추정↔실측 로그
- `tests/cuts.test.js` · `tests/pipeline.test.js`

**건드리지 않음**
- `lib/validate.js`의 `validateCutRanges` — 보장의 심장이다
- `lib/cuts.js`의 `splitUnits` · `splitSystem()` — 조각 정의와 프롬프트는 그대로
- `lib/clip-limits.js` · `lib/compose.js` · `lib/subtitles.js`

## 테스트

1. `explodeLongCuts` — 8초 초과·두 조각 이상만 푼다 / 조각 하나짜리는 8초를 넘어도 둔다 /
   8초 이하 묶음은 살아남는다
2. `explodeLongCuts` — **이어붙이면 원문과 같다**(핵심 보장)
3. `explodeLongCuts` — 분해 결과가 `validateCutRanges`를 통과한다(빈틈·겹침 없음)
4. `splitCuts` — LLM을 **한 번만** 부른다(되묻기 제거 회귀)
5. `splitCuts` — 8초 넘는 답을 주면 컷 수가 늘어난다
6. 회귀 하한선 **512 그린**

## 오류 처리

- 분할 응답을 못 받으면 지금 동작 — 조각 하나에 컷 하나로 떨어진다(이미 그 폴백이 있고,
  **이번 기본값과 같은 모양**이다)
- 분해 결과가 `validateCutRanges`를 통과하지 못하면 분해 전 컷을 쓰고 로그를 남긴다.
  분해는 개선이지 필수가 아니다 — 그것 때문에 분할이 실패하면 안 된다
- 목소리 실측 로그는 실패해도 흐름을 막지 않는다

## 하지 않는 것 (YAGNI)

- **켄번즈** — 위 참조. 이 측정이 끝난 뒤
- **장면 층(큰 덩어리)** — 사장님이 말한 "큰 덩어리 컷"은 **장면**이고 여기의 컷은 **제작
  단위**(그림 1장 + 클립 1개)다. 층이 다르므로 충돌하지 않는다. 장면 층은 시나리오 도입 뒤에
  필요가 측정되면 얹는다
- **실측 기반 재분할** — 목소리 실측으로 컷을 다시 쪼개는 것. 이미 만든 소리를 버려야 하고
  무효화 연쇄가 생긴다. 이번엔 로그만
- **프롬프트 손보기** — 효과를 가리지 않기 위해
