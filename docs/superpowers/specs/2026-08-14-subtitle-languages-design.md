# 자막 언어 — 일본어·중국어를 굽는다

> 2026-08-14 · 대상: `lib/subtitles.js` · `lib/clauses.js`(폭·줄바꿈) · 자막 폰트 자산 ·
> 번역 단계(신설) · ⑤영상/⑥완성 화면
>
> **원고와 소리는 이번 범위가 아니다** — 한국어 그대로다. 광고 경로(`lib/ad/*`)도 손대지 않는다.

## 무엇을 바꾸나

자막을 **일본어·중국어로도 구울 수 있게** 한다. 사장님이 언어를 고르면 컷 문장을 번역해
보여 주고, 고칠 수 있게 한 뒤, 그 글자로 자막을 굽는다.

**대본·낭독·클립은 한국어 그대로다.** 해외 SNS 업로드용으로 흔한 모양이고, 소리 축
(TTS 목소리 목록·Seedance 발음)을 건드리지 않아 검증되지 않은 자리를 안 늘린다.

## 근거는 실측이다 (2026-08-14)

"드롭다운 하나 추가"가 아니다. 폰트 파일의 cmap 을 직접 파싱해 확인했다:

| 자막 폰트 | 글리프 | 한글 | 가나 | 한자 | 간체 |
|---|---|---|---|---|---|
| 기본 (Pretendard) | 14,336 | O | O | **✗** | **✗** |
| 강조 (Black Han Sans) | 2,733 | O | ✗ | **✗** | **✗** |
| 부드럽게 (Gowun Dodum) | 12,494 | O | ✗ | **✗** | **✗** |

★ **세 폰트 다 한자가 없다.** 지금 상태로 일본어·중국어를 구우면 전부 **두부(□□□)** 다.
이 저장소가 08-13 에 "Seedance 한글 자막은 두부보다 나쁘다"를 겪고 **"글자는 ffmpeg,
소리는 모델"** 로 정리했는데, 그 ffmpeg 쪽이 CJK 를 못 굽는 상태였다.

그리고 폰트 말고 **구조적 제약이 둘 더** 있다:

**① 줄바꿈이 공백 기준이다** (`lib/subtitles.js` 의 `breakTwoLines`)

```js
const toks = [...s.matchAll(/\S+/g)];
if (toks.length <= 1) return s;   // ← 공백이 없으면 그대로 반환
```

중국어는 띄어쓰기가 없고 일본어도 거의 안 쓴다. **줄이 안 나뉘고 화면을 넘친다.**
같은 함정이 `splitSubtitleText` 계열(`lib/subtitles.js:181`·`:253`·`:303`)에도 있다.

**② 글자 폭 계산에 가나가 빠져 있다**

```js
const WIDE = /[ᄀ-ᇿ㄰-㆏가-힯　-〿一-鿿！-｠…]/u
```

`一-鿿`(한자)는 덮지만 `　-〿` 는 U+3000~303F(CJK 기호)까지라 **가나 U+3040~30FF 가 범위 밖**이다.
히라가나·가타카나를 반각(0.5)으로 세어 **일본어 자막이 계산보다 넓게 나와 넘친다.**

## 구조

### 1. 언어는 자막의 축이지 프로젝트의 축이 아니다

`settings.subtitle_lang`(기본 `"ko"`)에 둔다. 원고·컷·낭독·클립은 이 값을 **모른다** —
자막을 굽는 자리에서만 읽는다. 그래서 언어를 바꿔도 **다시 사는 것이 없다**(재합성은 로컬 ffmpeg 0원).

★ 이 저장소의 "값은 한 자리에" 규율대로 언어 목록은 **한 곳**에 둔다:
`lib/subtitle-langs.js`(신설, import 없는 순수 데이터 — 화면이 그대로 읽는다).

```js
export const SUBTITLE_LANGS = [
  { id: "ko", label: "한국어", line: "Korean" },
  { id: "ja", label: "일본어", line: "Japanese" },
  { id: "zh", label: "중국어(간체)", line: "Simplified Chinese" },
];
```

⚠️ 광고 경로의 `AD_LANGS`(ko·en)와 **합치지 않는다.** 그쪽은 나레이션 언어(소리)이고
이쪽은 자막 언어(글자)다 — 뜻이 달라 합치면 한쪽을 바꿀 때 다른 쪽이 끌려간다.

### 2. 번역은 컷에 붙고, 각인으로 낡는다

```js
cut.subtitles = { ja: { text: "…", of: "<번역의 근거가 된 한국어 문장>" }, zh: { … } }
```

- 번역 단위는 **컷 문장**이다. 원고 전체를 통으로 번역하면 컷 경계와 어긋난다
- `of` 는 이 저장소의 **각인 패턴**이다(`lib/steps.js` 하단). `cut.sentence !== subtitles[lang].of`
  이면 그 번역은 낡았다 — 원고를 고치면 자막이 조용히 옛 문장으로 남는 것을 막는다
- 한국어(`ko`)는 번역을 만들지 않는다. `cut.sentence` 가 곧 자막이다

★ **원고는 한 글자도 안 바뀐다.** "컷을 이어붙이면 원고와 글자 그대로 같다"는 보장은
번역이 별도 필드에 사는 한 그대로다.

### 3. 사장님이 보고 고친다

언어를 고르면 번역이 돌고, 컷별로 원문과 번역을 나란히 보여 준다. 번역문은 **눌러서 고친다** —
컷 문장을 고치는 자리가 이미 그 모양이라(②대본 화면의 `contentEditable`) 같은 방식을 쓴다.

손으로 고친 번역은 `of` 를 **그때의 원문으로 다시 찍는다**(고친 것이 낡음으로 취급되지 않게).

★ 왜 검토 자리를 두는가: 제품명·가격·고유명사를 모델이 이상하게 옮기는 일이 흔하고,
자막은 **화면에 박혀 나가는 글자**라 틀리면 그대로 사장님 책임이 된다.

### 4. 폰트는 언어가 정한다

- `assets/subtitle-ja.otf`(Noto Sans JP) · `assets/subtitle-zh.otf`(Noto Sans SC) 를 더한다
- **일본어·중국어에서는 스타일 선택(기본·강조·부드럽게)이 뜨지 않는다** — 그 언어용 폰트가
  한 벌뿐이기 때문이다. 한국어에서는 지금 그대로 셋 다
- ⚠️ ASS 의 `Fontname` 은 **폰트 파일 내부 이름**이다(`lib/subtitles.js:394` 주석).
  파일명이 아니라 내부 이름을 확인해 적는다 — 어긋나면 ffmpeg 가 **조용히 기본 폰트로** 굽는다

### 5. 줄바꿈과 폭을 공백 없는 언어에서도 맞춘다

- `WIDE` 에 **가나 범위(U+3040~30FF)** 를 더한다
- `breakTwoLines` 와 자막 분할이 **공백 토큰이 1개 이하일 때 글자 단위로** 가운데를 찾는
  폴백을 갖는다. 한국어 경로는 지금 동작 그대로여야 한다(**회귀 0**)
- ⚠️ 중국어·일본어는 아무 자리에서나 끊으면 안 되는 규칙이 있지만(금칙 처리),
  이번 범위는 **넘치지 않게 하는 것**까지다. 금칙은 나중에

## 값

- 번역은 컷당 짧은 문장이라 **편당 $0.001 미만**(gpt-4o 기준)
- 폰트는 저장소에 한 번 넣으면 끝(각 5~16MB). 함수 번들에 실리는지 확인할 것 —
  `outputFileTracingIncludes` 로 ffmpeg 를 실은 것과 같은 종류의 함정이다(08-14 실측)
- 언어를 바꿔 다시 굽는 것은 **0원**(로컬 ffmpeg). 클립·이미지는 다시 안 산다

## 지켜야 할 것

- **원고·낭독·클립을 건드리지 않는다.** 한국어 프로젝트의 동작은 **글자 그대로 지금과 같아야 한다**
- 구조적 보장(비무음 컷의 `sentence` 를 이어붙이면 원고와 같다)을 깨지 않는다
- 광고 경로(`lib/ad/*`)와 `AD_LANGS` 를 건드리지 않는다
- 언어 목록·폰트 대응을 **두 군데 두지 않는다**
- 측정 없이 품질을 주장하지 않는다 — 굽고 나서 **눈으로 본다**

## 검증

★ **이 기능은 "돌아간다"가 아니라 "글자가 제대로 보인다"가 판정이다.** 테스트가 그린인데
두부가 나오는 것이 정확히 이 자리의 실패 방식이다.

1. `tests/compose-live.test.js`(로컬 ffmpeg·**0원**)에 일본어·중국어 자막을 굽는 케이스를 넣고,
   출력 프레임에서 **글자가 두부가 아닌지** 확인한다
2. 폰트 cmap 검사를 테스트로 못 박는다 — 새 폰트가 실제로 그 언어를 덮는지
   (이번 조사에 쓴 방법 그대로. 파일이 바뀌면 빨개진다)
3. 긴 문장에서 **줄이 두 줄로 나뉘고 화면 폭을 안 넘는지**(일본어·중국어 각각)
4. 한국어 프로젝트의 자막 출력이 **바이트 단위로 이전과 같은지**

## 이번에 안 하는 것

- 나레이션·TTS·Seedance 발음의 언어(소리 축) — 별건이다
- 번체 중국어 · 영어 자막 — 목록에 더하는 것은 쉽지만 폰트·검증이 따라와야 한다
- 금칙 처리(줄 끝에 오면 안 되는 문자)
- 광고 경로의 자막 — 광고는 자막을 우리가 굽지 않는다
